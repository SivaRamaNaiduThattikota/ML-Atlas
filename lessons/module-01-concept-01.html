01 · CONCEPT FIRST

A loop, not a label

Machine learning is a system that improves its performance on a task by adjusting internal parameters based on data, rather than following rules a person wrote down explicitly. It needs four things at once: data with some signal to learn from, a model whose behavior depends on adjustable parameters, a loss that measures how wrong the model currently is, and a learning algorithm that adjusts the parameters to reduce that loss.

If any one of those four is missing — no adjustable parameters, no error measure, no adjustment procedure — it is not machine learning, whatever else it does with data.

First memory: a rule is written; a model is fit.
02 · WHY IT EXISTS

Why not just write the rule?

For some problems a person can write the exact correct rule directly — unit conversions, tax brackets, a fixed eligibility cutoff. For others, the true pattern is too complex, too full of exceptions, or too unknown to write down by hand, but there is plenty of historical data where the outcome is already recorded. Machine learning exists for exactly that second case: let the data determine the pattern that a person could not enumerate.

WRITE THE RULE

The correct logic is known, fixed, and simple enough to state directly.

LEARN THE PATTERN

The logic is unknown or too complex to state, but labeled historical examples exist.

03 · CONCRETE EXAMPLE

Routing a complaint, two ways

A rule-based router might say: “if product is Mortgage and issue contains ‘foreclosure’, route to escalations.” That works until the next exception arrives, and the next, and eventually the rule list is enormous and still wrong sometimes. A learned model instead looks at thousands of historical complaints, each with its actual eventual outcome already recorded, and adjusts its own parameters until its predictions match those real outcomes as closely as possible — without anyone writing the routing logic by hand.

RULE-BASED

A person enumerates conditions; behavior is exactly what was written.

LEARNED

Parameters are adjusted from historical outcomes; behavior is whatever minimizes error.

SHARED INPUT

Both approaches can look at the exact same complaint record.

04 · TECHNICAL MECHANISM

The four required pieces

DATA

Examples with signal

Historical records, often paired with a known outcome to learn from.

MODEL

Adjustable behavior

A function whose output depends on parameters that can be changed.

LOSS

A measure of wrongness

A number that gets smaller when predictions match reality more closely.

LEARNING ALGORITHM

The adjustment procedure

A method that changes parameters specifically to reduce the loss.

TRAINED MODEL

Fixed, deployable output

The model with its parameters now set, ready to be used on new data.

PREDICTION

Using the trained model

Applying the fixed model to a new example it has never seen labeled.

05 · ARCHITECTURE / FLOW

Training happens once; inference happens every time

TRAINING · OFFLINE

Historical data with known outcomes adjusts the model's parameters.

INFERENCE · EVERY REQUEST

The fixed, trained model produces a prediction from features alone.

Historical data → Model + loss → Learning algorithm → Trained model → New example → Prediction
Open the training/inference split
Training data (features + outcome) ↓ Parameters adjusted to reduce loss ↓ Trained model saved ↓ New data (features only) ↓ Prediction — no further learning here
06 · IMPORTANT DISTINCTIONS

Terms that get flattened into “uses data”

Approach What actually determines behavior Common confusion
Rule-based system Conditions a person wrote explicitly Assumed to be "using data" the same way ML does
Fixed lookup table A pre-computed value per category, set once Mistaken for a trained, adjustable model
Machine learning Parameters adjusted by an algorithm to reduce measured error Assumed to require deep learning specifically
Training vs. inference Parameters change vs. parameters stay fixed Assumed every prediction also updates the model

A lookup table built once from historical averages is a genuine boundary case — it uses data, but nothing adjusts it against a measured error the way a trained model's parameters are adjusted.

07 · COMMON MISTAKES

What beginners often misunderstand

“If it uses data, it's machine learning.”

A hardcoded average or a lookup table also "uses data" without ever being trained.

“Machine learning always needs huge datasets.”

Simple patterns can be learned from small datasets; complex ones typically need more.

“A trained model has no rules — it's a black box with nothing inside.”

It follows mathematical rules too — learned ones, not hand-written ones.

“A more complex model is always the better choice.”

Complexity without enough data or the right features often performs worse, not better.

“Machine learning means deep learning and neural networks.”

Linear regression, decision trees, and many other algorithms are just as much machine learning.

“You should default to a learned model when data is available.”

If a simple, correct rule already exists, it is usually the safer and cheaper choice.

04
INTUITION

A cook who tastes, not one who only reads a recipe card

A recipe card is a fixed rule: follow the steps, get the same dish every time, regardless of the ingredients' actual quality that day. A cook who tastes as they go, and adjusts seasoning based on how far off the dish is from what it should taste like, is closer to the machine learning loop: an ongoing adjustment driven by a measured gap between the current result and the goal.

Analogy boundaryA cook adjusts by intuition and taste; a learning algorithm adjusts by a precise mathematical procedure applied to a numeric loss. The analogy captures “adjust based on measured error,” not the actual mechanism.
05
PRECISION

Formal definitions

Term Definition Boundary
Model A function whose output depends on a set of adjustable parameters The function form is fixed; only its parameters change during training
Parameters The specific numeric values a learning algorithm adjusts Distinct from hyperparameters, which are set before training begins
Loss A scalar measuring how wrong a model's predictions currently are Lower is better; the exact form depends on the task
Training The process of adjusting parameters to reduce loss on given data Happens offline, before any prediction is served
06
MECHANISM

The training loop, generically

Collect examples, each with measured features and (for this course's models) a known outcome
Choose a model whose parameters can be adjusted
Define a loss that scores how far predictions are from the known outcomes
Run a learning algorithm that adjusts parameters to reduce that loss
Check performance on data the model has not been adjusted against
Save the resulting fixed parameters as the trained model

Nothing here is specific to one algorithm family — every model in this course follows this same six-step shape, differing only in what the model, the loss, and the learning algorithm actually are.

09
MATHEMATICS

Empirical risk minimization

Symbol Meaning
f_θThe model, a function of the input parameterized by θ
(x_i, y_i)The i-th training example: features x_i, known outcome y_i
L(·, ·)The loss function comparing a prediction to the true outcome
nThe number of training examples
θ* = argmin_θ (1/n) Σᵢ L(f_θ(x_i), y_i)

Training searches for the parameter values θ* that minimize the average loss across all training examples — this single expression is the mathematical core of "adjusting parameters to reduce error" stated precisely, regardless of which model family f_θ actually is.

10
WORKED EXAMPLE

Learning the simplest possible model by hand

Let the model be the simplest one possible: a single constant c that predicts the same value for every input, with squared-error loss L(c, y) = (c − y)². Training data: y = [2, 4, 4, 8].

Average loss(c) = ¼[(c−2)² + (c−4)² + (c−4)² + (c−8)²]

Minimizing this average by taking the derivative with respect to c and setting it to zero gives c* = mean(y) = (2+4+4+8)/4 = 4.5. The familiar arithmetic mean is what empirical risk minimization produces for exactly this model and loss — the simplest possible case of the same procedure every model in this course uses.

12
CODE

The simplest possible learning loop

PYTHON · FROM-SCRATCH GRADIENT DESCENT 
import numpy as np

y = np.array([2.0, 4.0, 4.0, 8.0])
c = 0.0                      # initial parameter guess
learning_rate = 0.1

for step in range(50):
    predictions = np.full_like(y, c)
    loss = np.mean((predictions - y) ** 2)
    gradient = np.mean(2 * (c - y))   # d(loss)/dc
    c = c - learning_rate * gradient  # the only line that "learns"

print(round(c, 3))  # -> 4.5, matching Section 10's hand-derived mean
13
ECOSYSTEM

Every scikit-learn model follows this exact split

Every classical ML library encodes the training/inference split from Section 05 the same way: an object exposing fit(X, y) to train on features and known outcomes, and predict(X) to run inference on new features with the model's parameters left untouched. Section 12's tiny manual loop and a full scikit-learn model differ enormously in what f_θ and the learning algorithm actually are — never in this basic training/inference shape.

16
DIAGNOSIS

Failure modes

MISFRAMING

ML where a rule would do

Adding unnecessary complexity and unpredictability to a fully-known problem.

LABEL NOISE

Wrong recorded outcomes

A model can only be as correct as the historical outcomes it trains against.

OVERFITTING PREVIEW

Memorizing, not learning

Reducing training loss without improving on genuinely new data — Module 01, Concept 04's subject.

TRAIN-SERVE SKEW

Feature mismatch

Features computed differently at training time versus prediction time.

STALE MODEL

No retraining plan

A model trained once and never revisited as the real world shifts.

MISSING BASELINE

No comparison point

Deploying a learned model without ever checking it against a simple rule.

17
CORRECTION

Misconceptions

Incorrect belief Correction
Using data automatically means machine learning A fixed lookup table also uses data without ever being trained against a loss.
Machine learning is inherently more accurate than rules A correct, fully-known rule can outperform a learned model with weak features or noisy labels.
A trained model "understands" the problem It is a fixed mathematical function whose parameters happened to minimize a measured loss.
More data always improves a model Bad labels, weak features, or the wrong model family limit performance regardless of data volume.
18
REALITY

Production implications

  • Always compare a learned model against a simple baseline before trusting the added complexity.
  • Document exactly what a training label represents and how it was recorded.
  • Decide up front whether a problem actually needs adjustable parameters, or whether a rule is safer and cheaper.
  • Plan for retraining — a trained model does not stay accurate as the real world shifts, on its own.
  • Keep training-time and serving-time feature computation identical to avoid train-serve skew.
  • Treat label quality as a first-class production concern, not an afterthought.
19
RECALL

Knowledge check

What four things does a system need to genuinely be machine learning?
Data with signal to learn from, a model with adjustable parameters, a loss measuring error, and a learning algorithm that adjusts the parameters to reduce that loss.
Why isn't a fixed lookup table a trained model?
It was computed once from data but nothing in it is adjusted against a measured error afterward — no loss, no learning algorithm.
What does empirical risk minimization search for?
The parameter values that minimize the average loss across the training examples.
What stays fixed during inference, and what changed during training?
During inference the model's parameters stay fixed; during training, those same parameters were the only thing the learning algorithm was allowed to change.

23
CAREER PRACTICE

Interview questions

How would you explain machine learning to a non-technical stakeholder in one sentence?
It is a system that adjusts its own internal parameters from historical examples until its predictions are as close as possible to the real recorded outcomes, rather than following rules someone wrote by hand.
A stakeholder says "we have lots of data, so let's use machine learning." How do you respond?
Having data is necessary but not sufficient — ask whether the underlying pattern is actually too complex for a rule, whether reliable labels exist, and whether a simple baseline has been tried first.
What is empirical risk minimization, in your own words?
Choosing the model parameters that minimize the average loss across the available training examples, as a practical stand-in for minimizing error on all possible future data.
How do you distinguish a "learned" component from a "computed" one in a system design review?
Ask whether it has adjustable parameters tuned against a measured error using a repeatable procedure — if it was computed once and left alone, it is not a trained model, regardless of how it's described.
