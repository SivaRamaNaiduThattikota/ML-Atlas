01 · CONCEPT FIRST

Three ways to give a model feedback

Supervised learning trains on examples that already carry a known outcome, and the loss compares each prediction against that outcome. Unsupervised learning trains on examples with no known outcome at all — the loss or objective is defined only on the structure of the data itself. Reinforcement learning has no fixed outcome attached to any single example either, but unlike unsupervised learning it gets a reward signal from a sequence of actions taken over time.

Same four-piece loop from Concept 01 in every case. What changes is what the "loss" is allowed to compare against.

First memory: known outcome per example → supervised. No outcome, no actions → unsupervised. No outcome, but sequential actions and a reward → reinforcement learning.
02 · WHY IT EXISTS

Not all data comes with an answer key

Most production tabular and text problems — including both of CFPB's models — have historical records where the true outcome is already known: did this complaint get relief, which product does this narrative belong to. But plenty of real problems never have that answer key. Sometimes you just have records and want to know what groups or structure exist in them. Sometimes there's no per-example answer at all, only a delayed signal after a sequence of decisions. Each of those three situations needs a genuinely different kind of loss, so it needs a name of its own.

ANSWER KEY EXISTS

Each historical example already has its true outcome recorded — supervised learning applies.

NO ANSWER KEY, NO ACTIONS

Only the data's structure is available to learn from — unsupervised learning applies.

03 · CONCRETE EXAMPLE

Three complaint-ops problems, three different feedback shapes

Predicting whether a new complaint will receive monetary relief is supervised: thousands of past complaints already show whether relief was granted, so the model's prediction can be checked against that recorded fact. Grouping ten thousand complaint narratives into natural themes with no theme labels at all is unsupervised: there is no known "correct" grouping to check against, only patterns in the text itself. Now imagine an automated routing agent that picks the next action for an open case — escalate, request more documents, close — and only learns days later, after several such decisions, whether the case resolved well. That delayed, action-dependent signal is what reinforcement learning is built for, and it is a different shape of problem than either of the first two.

SUPERVISED

Relief-risk prediction — the outcome (relief or not) is already recorded on every past complaint.

UNSUPERVISED

Narrative theme discovery — no theme label exists on any complaint to check against.

REINFORCEMENT

A routing agent's multi-step decisions, judged only by a delayed outcome — not built in this course.

04 · TECHNICAL MECHANISM

What the loss is allowed to compare against

SUPERVISED

Loss vs. a known outcome

Every training example has a recorded label or value; the loss shrinks as predictions match it.

UNSUPERVISED

Objective over structure

No label exists; the objective rewards a useful arrangement of the data itself — tight groups, low reconstruction error, and so on.

REINFORCEMENT LEARNING

Reward from sequential actions

An agent takes actions across states and receives a reward signal, often delayed, that depends on the whole sequence, not one example.

KNOWN OUTCOME

The deciding factor

Present per example → supervised. Absent, with no actions → unsupervised. Absent, but replaced by a sequential reward → reinforcement learning.

FEEDBACK TIMING

Immediate vs. delayed

Supervised feedback is immediate and per-example; reinforcement feedback can arrive long after the actions that caused it.

SCOPE OF THIS COURSE

Where each paradigm lives here

Supervised: most of the course, including both CFPB models. Unsupervised: Phase 4. Reinforcement learning: contrast only, not taught in depth.

05 · ARCHITECTURE / FLOW

One fork, two questions

QUESTION 1

Does each example carry a known outcome? If yes, the problem is supervised.

QUESTION 2

If no — are there sequential actions with a reward? If yes, reinforcement learning; if no, unsupervised.

06 · IMPORTANT DISTINCTIONS

Where beginners flatten these into one thing

ParadigmWhat the data providesCommon confusion
Supervised learningFeatures plus a known outcome per exampleAssumed to be the only kind of ML that exists
Unsupervised learningFeatures only, no known outcomeAssumed to have "no way to check" anything at all
Reinforcement learningStates, actions, and a delayed reward — no per-example labelAssumed to be needed whenever a "reward" or score is optimized
Semi/self-supervised (not covered)A mix — few or synthetic labels, mostly unlabeled dataMistaken for one of the three pure cases

Unsupervised learning still has evaluation — Phase 4 covers methods that don't need ground truth — it just has no known outcome to score accuracy against. And having a metric to optimize does not automatically mean reinforcement learning; supervised models optimize metrics too.

07 · COMMON MISTAKES

What beginners often misunderstand

"If a column looks like a number, it's the label."

A row's other numeric features aren't automatically the known outcome — the outcome is whatever you're specifically trying to predict.

"Clustering can replace classification once you don't have labels."

Clusters found by an unsupervised method don't automatically line up with your actual business categories.

"Reinforcement learning is needed whenever there's a reward to optimize."

Plenty of supervised problems optimize a metric too. RL specifically needs sequential actions and delayed, action-dependent feedback.

"Unsupervised learning can't be wrong since there's no answer key."

It has its own evaluation methods (Phase 4) — just not accuracy against a known label.

"All three paradigms show up equally often in production tabular ML."

Supervised learning dominates production tabular and text work, including both of CFPB's models.

"A dataset with a 'reward' column must need reinforcement learning."

If that column is simply a known outcome per row with no sequential actions involved, it's supervised learning wearing a different column name.

04
INTUITION

A graded test, a librarian with no catalog, and a dog earning treats

A graded practice test tells you exactly which answers were right — that's supervised learning's shape: a known correct value per question. A librarian sorting an unlabeled donation pile into sections, with no genre stickers to go by, is closer to unsupervised learning: no right answer per book, only patterns in what's actually there. A dog being trained with treats doesn't get told "sit was 73% correct" after every single attempt — it gets a reward sometime after a sequence of behaviors, and has to work out which actions actually earned it. That delayed, sequence-dependent signal is the shape reinforcement learning is built for.

Analogy boundaryNone of these creatures compute a loss function. The analogy is only meant to convey "checked immediately against a right answer" versus "no right answer, only structure" versus "a delayed reward after a sequence of actions" — not the actual mechanism of any of the three.
05
PRECISION

Formal definitions

TermDefinitionBoundary
Supervised learningLearn a function from features x to outcome y using pairs (x, y) where y is known; the loss compares predictions to yStill supervised even if y is noisy, delayed, or expensive to collect — as long as an outcome is eventually recorded per example
Unsupervised learningLearn structure from features x alone, with no known y; the objective is defined over the data's own geometry or distributionUsing an unsupervised method to build features for a later supervised model doesn't make the overall system unsupervised
Reinforcement learningLearn a policy mapping states to actions that maximizes cumulative reward from sequential interaction with an environmentA single, independent decision with immediate full feedback each time isn't meaningfully sequential — that's a supervised label, not reinforcement learning
Known outcome (label)The specific value a model is trained to reproduce for a given exampleIts presence or absence per example is exactly what separates supervised from the other two paradigms
06
MECHANISM

The two-question decision procedure, traced

Start with one training example, or one task description if no data exists yet
Question 1 — does this example carry a known, recorded outcome?
If yes: it's supervised — the loss will compare a prediction to that outcome
If no: Question 2 — does the task involve a sequence of actions with a reward?
If yes: it's reinforcement learning — the objective maximizes cumulative reward, not per-example accuracy
If no: it's unsupervised — the objective is defined only on the structure of the features themselves

Every later algorithm concept in Phases 3 and 4 is a different choice of model and loss inside one of these three branches — the branching test itself never changes.

09
MATHEMATICS

Three objectives, one shared shape

SymbolMeaning
f_θ, x_i, y_iModel, features, and known outcome — as in Concept 01
c_kThe k-th cluster's representative point, in an unsupervised objective
πA policy: a rule for choosing an action given a state
r_t, γ, G_tReward at step t, a discount factor in [0, 1], and the discounted cumulative return
Supervised: θ* = argmin_θ (1/n) Σᵢ L(f_θ(x_i), y_i)
Unsupervised (example — clustering): θ* = argmin_θ (1/n) Σᵢ d(x_i, c_assign(i))
Reinforcement learning: π* = argmax_π E[G_t], where G_t = Σ_{k=0}^∞ γᵏ r_{t+k+1}

All three are still "search for the parameters or policy that minimize wrongness or maximize reward" — Concept 01's empirical risk minimization, generalized to whatever kind of feedback is actually available. Supervised and unsupervised are covered in depth later in this course; the reinforcement learning line is shown only so its shape can be recognized, not derived.

10
WORKED EXAMPLE

The same four numbers, computed three ways

Four complaint records with a single feature x = [1, 3, 6, 8]. First, treat this as supervised with known outcomes y = [0, 0, 1, 1] and a simple rule "predict 1 if x > 4": predictions are [0, 0, 1, 1], matching y exactly — 0 errors.

Now treat the same four numbers as unsupervised, with no y at all, split into two clusters by proximity: {1, 3} and {6, 8}. Each cluster's mean is 2 and 7; the within-cluster objective is (1−2)² + (3−2)² + (6−7)² + (8−7)² = 4 — a measure of how tight the groups are, with no reference to any outcome.

Finally, treat a short reward sequence r = [1, -1, 2] as reinforcement learning's feedback, with discount γ = 0.9: G = 1 + 0.9(-1) + 0.81(2) = 1 - 0.9 + 1.62 = 1.72. Three different numbers, from three genuinely different questions being asked of the data.

12
CODE

Same features, two different objectives

PYTHON · SUPERVISED LOSS VS. UNSUPERVISED OBJECTIVE, SAME X 
import numpy as np

x = np.array([1.0, 3.0, 6.0, 8.0])
y = np.array([0, 0, 1, 1])          # known outcome — only used below

# Supervised: loss compares a prediction to the known outcome y
pred = (x > 4).astype(int)
supervised_loss = np.mean((pred - y) ** 2)

# Unsupervised: objective uses x alone, y is never touched
group_a, group_b = x[x <= 4], x[x > 4]
unsupervised_objective = (
    np.sum((group_a - group_a.mean()) ** 2) +
    np.sum((group_b - group_b.mean()) ** 2)
)

print(supervised_loss, unsupervised_objective)   # -> 0.0 4.0
13
ECOSYSTEM

The API shape gives the paradigm away

In scikit-learn, every supervised estimator exposes fit(X, y) — it needs the known outcome to train against. Every unsupervised estimator, like KMeans or PCA, exposes fit(X) with no y at all — there's nothing to hand it. Reinforcement learning doesn't fit this shape at all: libraries like Gymnasium and Stable-Baselines3 use an env.step(action) loop that returns a new state and a reward, not a fixed training set. If a library call needs a y, the problem is supervised; if it explicitly has none, it's unsupervised; if there's no fixed dataset at all, only an environment to act in, it's reinforcement learning.

CONTRAST

Choosing an approach

ParadigmWins whenOperational consequence
Supervised learningA reliable historical outcome exists per exampleLabel quality and coverage become the real bottleneck
Unsupervised learningNo outcome exists, but structure is still usefulResults need human interpretation — no accuracy metric against ground truth
Reinforcement learningActions affect future states and feedback is delayed or sequentialNeeds an environment to interact with, exploration risk, and is expensive to train safely

A spectrum between the pure supervised and pure unsupervised cases — semi-supervised and self-supervised learning, using a small labeled subset or synthetic labels — exists but isn't covered in this course.

16
DIAGNOSIS

Failure modes

MISFRAMING

Treating unlabeled data as labeled

Fabricating or assuming an outcome that was never actually recorded.

OVER-ENGINEERING

Forcing reinforcement learning

Building a full agent-and-environment loop for a task that already has a known outcome per example.

FALSE TRUST

Treating clusters as classes

Acting on unsupervised groupings without validating them against a real, separate signal.

PARTIAL LABELS

Silent semi-labeling

Only some examples have a recorded outcome; treating the whole dataset as fully supervised can bias training.

REWARD HACKING

Optimizing the wrong proxy

A reinforcement-learning agent can maximize a reward signal that doesn't actually match the real goal.

MISSING BASELINE

No supervised check

Reaching for an unsupervised or sequential approach without first checking whether a known outcome exists.

CORRECTION

Misconceptions

Incorrect beliefCorrection
Any computable number in the data is "the label"The label is specifically whatever outcome the model is meant to predict — not every column qualifies.
Unsupervised learning has no evaluation at allIt has evaluation methods that don't need ground truth (Phase 4) — just not accuracy against a known outcome.
Reinforcement learning is just supervised learning with a reward instead of a labelRL's feedback is delayed, sequential, and action-dependent; an immediate per-example outcome is a supervised label, not a reward.

18
REALITY

Production implications

  • Confirm a true historical outcome is actually recorded before assuming a problem is supervised.
  • Treat unsupervised outputs — clusters, embeddings — as needing a human validation plan before they inform decisions.
  • Never introduce a sequential-decision reinforcement-learning system into a workflow that's really a series of independent, one-shot predictions.
  • Document which paradigm produced each artifact in a pipeline, especially when paradigms are chained.
  • Label collection cost and quality are the main production constraint for supervised systems, including both CFPB models.
  • Treat "no labels available yet" as a data-strategy problem to solve, not a reason to force-fit the wrong paradigm.
19
RECALL

Knowledge check

What single question separates supervised learning from the other two?
Whether each training example carries a known, recorded outcome that the loss can compare a prediction against.
What separates unsupervised learning from reinforcement learning?
Whether there are sequential actions with a reward signal — unsupervised learning has neither an outcome nor actions, reinforcement learning has actions and a delayed reward instead of an outcome.
Why isn't "there's a metric to optimize" sufficient to call something reinforcement learning?
Supervised and unsupervised objectives are metrics too; reinforcement learning specifically requires sequential actions and reward that depends on the whole sequence, not a per-example score.
Why are both CFPB models supervised?
Company response (relief or not) and the product label are both known outcomes recorded on every historical complaint, so both models' losses compare predictions to a real recorded value.

23
CAREER PRACTICE

Interview questions

How would you explain the difference between supervised and unsupervised learning to a non-technical stakeholder?
Supervised learning checks its guesses against answers we already know from history; unsupervised learning looks for patterns in data when no such answer key exists at all.
A stakeholder wants to "use reinforcement learning" for a churn-prediction problem. How do you respond?
Ask whether the system takes a sequence of actions with a reward that arrives later, or whether it's really one prediction per independent customer with a known churn outcome — the latter is supervised learning, not RL.
Write, in words, the objective a k-means-style unsupervised method actually minimizes.
The total squared distance between each point and the mean of the group it's assigned to — no known outcome is involved anywhere in that objective.
How do you tell, from a library's method signature alone, which paradigm a piece of code implements?
If it calls something like fit(X, y), it's supervised; if it calls fit(X) with no y, it's unsupervised; if it's built around an environment's step(action) loop instead of a fixed dataset, it's reinforcement learning.
