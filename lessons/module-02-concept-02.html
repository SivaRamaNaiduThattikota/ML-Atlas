matrix.

Concept 01 proved something uncomfortable: CFPB's own 77.7%-accuracy pair — one model that helps nobody, one that serves 100 real relief cases at the cost of 100 false alarms — cannot be told apart by accuracy alone. Four cells, one honest bookkeeping system

Concept 01 named a gap without closing it: accuracy can't say which kind of error happened, or to whom. 01 · CONCEPT FIRST

Every prediction lands in exactly one of four boxes

Cross what actually happened (relief or not) with what the model predicted (relief or not), and every row falls into exactly one box: a true positive caught a real relief case, a false positive wrongly flagged a non-relief complaint, a false negative missed a real relief case, and a true negative correctly cleared a non-relief complaint. Four counts, one row each — nothing is left over and nothing is double-counted.

First memory: TP and TN are the model agreeing with reality; FP and FN are the two different ways it can disagree.
02 · WHY IT EXISTS

Accuracy collapses four counts into one — this keeps all four

Accuracy adds TP and TN together and divides by everything. That single division is exactly where Concept 01's blind spot came from: two very different splits of FP and FN can produce the identical (TP+TN)/total. The confusion matrix doesn't invent a new number — it just refuses to do that addition early, so the FP/FN split stays visible instead of disappearing into the numerator.

ACCURACY

One division, computed immediately — (TP+TN) added together before you can inspect the parts.

CONFUSION MATRIX

Four counts, kept separate — accuracy is still there, just computed one step later, after you've seen the parts.

03 · CONCRETE EXAMPLE

Model A and Model B, finally told apart

Concept 01's 1,000-row CFPB test set had 223 real relief cases and 777 non-relief complaints. Model A (majority-class) scores TP=0, FP=0, FN=223, TN=777. Model B (partial catch) scores TP=100, FP=100, FN=123, TN=677. Add TP+TN for either one and you get 777 — the identical 77.7% accuracy Concept 01 already showed. But written as four numbers instead of one, the two models are now visibly, obviously different.

MODEL A'S MATRIX

TP 0 · FP 0 · FN 223 · TN 777 — every relief case is a false negative, every non-relief complaint is a true negative.

MODEL B'S MATRIX

TP 100 · FP 100 · FN 123 · TN 677 — the same 777 correct predictions, now spread across three cells instead of hiding in one.

04 · TECHNICAL MECHANISM

Row = actual class, column = predicted class

TP · TRUE POSITIVE

Real relief case, predicted relief

The model agreed with reality on a case that mattered — a deserving complainant gets routed to review.

FP · FALSE POSITIVE

Non-relief complaint, predicted relief

A false alarm — a routine complaint gets pulled into review it didn't need.

FN · FALSE NEGATIVE

Real relief case, predicted no relief

A miss — a deserving complainant is denied the review they needed.

TN · TRUE NEGATIVE

Non-relief complaint, predicted no relief

The model agreed with reality on a case that didn't need attention.

06 · IMPORTANT DISTINCTIONS

Where beginners mix up axes, classes, and metrics

TermWhat it actually isCommon confusion
Row (actual)Ground truth — what really happened, independent of any predictionSwapped with the column, which flips every FP into an FN and back
Column (predicted)What the model output, independent of whether it was rightConfused with "what should have happened" — that's the row
"Positive" classWhichever class you name as the one of interest — here, reliefAssumed to always mean "the good outcome" — in a fraud model, positive usually means fraud, not a good thing

07 · COMMON MISTAKES

What beginners often misunderstand

"The four cells should add up to something other than the total row count."

They must always sum to exactly the test set size — every row is sorted into exactly one cell, no more and no fewer.

"Positive always means the desirable outcome."

Positive just names the class of interest for this problem. For CFPB it happens to mean relief; for a fraud model it would mean fraud.

"Building the matrix already tells me if the model is good."

The matrix is raw material, not a verdict — Model A's and Model B's matrices are both "valid," and neither is labeled good or bad until Concept 03 attaches a metric with a real cost attached.

"This is basically the same as Concept 01, just with a table."

Concept 01 could only describe the gap in words. This concept gives it four countable numbers — that's the new capability, not a restatement.

04
INTUITION

A sorting tray with exactly four bins

Picture a sorting tray with four labeled bins instead of a single "right or wrong" pile. Every complaint you drop in slides into exactly one bin, decided by two yes/no questions: was it actually a relief case, and did the model say it was. There's no fifth bin and no complaint that needs two bins — the sort is total and mutually exclusive by construction.

Analogy boundaryA physical sorting tray stops at "which bin." A production matrix continues past sorting into arithmetic on the bin counts — that arithmetic, precision and recall, is Concept 03's job, not a free byproduct of having four bins.
05
PRECISION

Formal definitions

TermDefinitionBoundary
True positive (TP)Actual = positive, predicted = positiveThe model agreed with reality on a case of interest
False positive (FP)Actual = negative, predicted = positiveA false alarm — often called a "Type I error"
False negative (FN)Actual = positive, predicted = negativeA miss — often called a "Type II error"
True negative (TN)Actual = negative, predicted = negativeThe model agreed with reality on a case that wasn't of interest

Every one of the four cells is a count over the same fixed test set, so TP+FP+FN+TN always equals the test set size n — that invariant holds regardless of which model produced the predictions.

06
MECHANISM

Sorting 1,000 rows into four bins, twice

Take CFPB's 1,000-row test set: 223 rows where actual = relief, 777 rows where actual = no relief
Model A predicts "no relief" for every row → all 223 relief rows become FN, all 777 non-relief rows become TN → TP=0, FP=0, FN=223, TN=777
Model B predicts relief for 100 of the 223 relief rows and for 100 of the 777 non-relief rows → TP=100, FN=123, FP=100, TN=677
Check both: Model A sums to 0+0+223+777=1000; Model B sums to 100+100+123+677=1000 — both pass the total-count invariant
Accuracy from the matrix: Model A = (0+777)/1000 = 77.7%; Model B = (100+677)/1000 = 77.7% — identical, exactly reproducing Concept 01

09
MATHEMATICS

Four counts, one already-familiar combination

Let y be the actual label and ŷ the predicted label for each row, with "relief" as the positive class. Then TP = |{i : y_i=1, ŷ_i=1}|, FP = |{i : y_i=0, ŷ_i=1}|, FN = |{i : y_i=1, ŷ_i=0}|, TN = |{i : y_i=0, ŷ_i=0}|, where |·| counts set size. By construction these four sets partition the full test set, so TP+FP+FN+TN=n. Accuracy, Concept 01's formula, is exactly (TP+TN)/n — nothing new is defined here, the matrix simply exposes the two numbers, TP and TN, that were always being added together.

Acc = (TP + TN) / (TP + FP + FN + TN) — the same accuracy formula, rewritten in terms of the four cells instead of a single correct/incorrect count

12
CODE

Building the matrix from raw predictions, in NumPy

PYTHON · FROM-SCRATCH CONFUSION MATRIX 
import numpy as np

def confusion_counts(y_true, y_pred, positive=1):
    tp = np.sum((y_true == positive) & (y_pred == positive))
    fp = np.sum((y_true != positive) & (y_pred == positive))
    fn = np.sum((y_true == positive) & (y_pred != positive))
    tn = np.sum((y_true != positive) & (y_pred != positive))
    return tp, fp, fn, tn

n_relief, n_no_relief = 223, 777
y_true = np.array([1] * n_relief + [0] * n_no_relief)

majority = np.zeros(1000, dtype=int)          # Model A

model_b = y_true.copy()
model_b[:123] = 0                             # miss 123 of the 223 relief cases
model_b[223:323] = 1                          # wrongly flag 100 of the 777 non-relief complaints

for name, y_pred in [("Model A", majority), ("Model B", model_b)]:
    tp, fp, fn, tn = confusion_counts(y_true, y_pred)
    accuracy = (tp + tn) / (tp + fp + fn + tn)
    print(f"{name}: TP={tp} FP={fp} FN={fn} TN={tn} accuracy={accuracy:.1%}")
# Model A: TP=0 FP=0 FN=223 TN=777 accuracy=77.7%
# Model B: TP=100 FP=100 FN=123 TN=677 accuracy=77.7%

assert tp + fp + fn + tn == 1000

The positive= argument matters: flip which class counts as "positive" and every FP becomes an FN and vice versa — the exact swap Section 06's row/column distinction warns about.

13
ECOSYSTEM

The one-line library version

sklearn.metrics.confusion_matrix(y_true, y_pred) returns exactly the four counts Section 12 computes by hand, arranged as a 2×2 array — but its default row/column order is [[TN, FP], [FN, TP]], not the actual-row-first, positive-first layout used throughout this lesson. Reading a library matrix without checking its axis order is the single most common way this concept's row/column distinction (Section 06) causes a real bug: a correct model can look inverted if the axes are misread. ConfusionMatrixDisplay renders the same array with labeled axes specifically to prevent that misreading.

16
DIAGNOSIS

Failure modes

AXIS SWAP

Reading rows as predictions and columns as truth

Silently turns every FP into an FN — Section 13's library warning is a direct consequence.

WRONG POSITIVE CLASS

Assuming "positive" is whichever class is more common

Positive is a modeling choice, not a frequency — CFPB names relief as positive even though it's the rarer class.

AGGREGATED-AWAY MATRIX

Computing one matrix across categories that behave differently

Hides a single category's FN rate inside a healthier module-wide average.

MATRIX MISTAKEN FOR A METRIC

Reporting "the matrix" with no summary number attached

Four raw counts, with no ratio or cost attached, still leave a reviewer to do the comparison by hand.

18
REALITY

Production implications

  • Log the full matrix, not just accuracy, in every model card and evaluation report — Section 15's contrast table shows exactly what a single-number report loses.
  • Fix and document which class is "positive" before comparing any two models' matrices — an unstated convention makes FP and FN silently swap between reports.
  • Compute a separate matrix per meaningful subgroup (product category, channel) rather than one aggregate matrix, to avoid the exact averaging-away failure Section 16 names.
19
RECALL

Knowledge check

Why must the four cells of a confusion matrix always sum to the test set size?
Every row is actual-positive-or-negative crossed with predicted-positive-or-negative, and those four combinations are mutually exclusive and exhaustive over any fixed test set.
What changes about a matrix if you swap which class is labeled "positive"?
Every FP cell becomes an FN cell and vice versa; TP and TN stay the same because both classes agreeing with the model is symmetric under the swap.

FEEDBACK

Solution and teach-back

Open the worked solution
TP=9 (caught relief cases), FN=12−9=3 (missed relief cases), FP=5 (false alarms), TN=38−5=33 (correctly cleared). Sum: 9+5+3+33=50, matching the sample size. Accuracy = (9+33)/50 = 42/50 = 84%.

Teach-back: explain in your own words why FN is computed as "12 minus the caught count" rather than given directly in the scenario, and why that subtraction is only valid because the row totals (12 relief, 38 non-relief) are fixed and known in advance.

PORTABLE MEMORY

Concept card

The rule

Every prediction sorts into exactly one of TP, FP, FN, TN by crossing actual class against predicted class; the four counts always sum to the test set size.

Warning signs

  • A reported matrix with no stated "positive" class convention
  • Rows and columns swapped between two reports without anyone noticing
  • One matrix aggregated across subgroups that behave very differently

One memorable example

Model A: TP 0, FP 0, FN 223, TN 777. Model B: TP 100, FP 100, FN 123, TN 677. Same 77.7% accuracy, completely different matrices.

23
CAREER PRACTICE

Interview questions

Draw and explain a confusion matrix for a binary classifier from memory.
A 2×2 grid crossing actual class (rows) against predicted class (columns): TP and TN on the diagonal where the model agrees with reality, FP and FN off-diagonal where it disagrees, in two different directions.
What's the practical risk of aggregating one confusion matrix across several distinct subgroups?
A subgroup with a much higher FN rate can be averaged away by a larger, better-performing subgroup, hiding a systematic failure that a per-subgroup matrix would expose.
How does sklearn's confusion_matrix axis order differ from the actual-row, predicted-column convention taught here, and why does it matter?
sklearn returns [[TN, FP], [FN, TP]] by default; misreading that order is a direct way to invert FP and FN when comparing to hand-computed or differently-labeled matrices.
Why doesn't building a confusion matrix alone tell you whether a model is good?
The matrix is raw counts with no attached cost or business weighting — Model A's and Model B's matrices are both internally valid, and choosing between them requires a metric, not just the matrix.
