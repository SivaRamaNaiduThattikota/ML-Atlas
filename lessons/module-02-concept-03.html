MODULE 02 · CONCEPT 03

Precision, recall
and F1.

Concept 02 built four honest counts — TP, FP, FN, TN — and combined them exactly one way: accuracy. This concept divides the same four counts two new ways. Precision asks, of everything the model flagged as relief, how much was actually relief. Recall asks, of every real relief case, how much did the model catch. Then F1 combines the two into one number — using their harmonic mean, not a plain average, for a reason this concept proves rather than asserts. Everything here is computed at one fixed threshold; sweeping that threshold is Concept 04's job.

PROGRESSIVE BEGINNER CORE

Two questions, one matrix, two different denominators

Concept 02 stopped at accuracy — one specific way of combining TP, FP, FN and TN. This concept asks two sharper questions of that same matrix: when the model says "relief," how often is it right (precision)? And of every real relief case, how many does it actually catch (recall)? Then it asks why F1, their combined score, uses a harmonic mean and not a simple average.

01 · CONCEPT FIRST

Precision and recall divide TP by two different totals

Precision = TP ÷ (TP + FP): of everything the model called "relief," what fraction actually was. Recall = TP ÷ (TP + FN): of everything that actually was relief, what fraction the model caught. Same TP on top, different denominator underneath — precision's denominator is everything predicted positive, recall's is everything actually positive.

First memory: precision looks at the model's "relief" pile and asks how clean it is; recall looks at reality's relief cases and asks how many were found.
02 · WHY IT EXISTS

Accuracy couldn't separate two costs that aren't equal

Concept 01 showed accuracy treats a missed relief case and a false alarm as the same one point lost. They aren't the same to CFPB. A false negative denies a deserving complainant the review they needed. A false positive burns reviewer time on a complaint that didn't need it. Precision and recall exist specifically to report those two costs as two separate, comparable numbers instead of one number that quietly averages them together.

RECALL'S COST

Low recall means real relief cases are being missed — the false-negative cost.

PRECISION'S COST

Low precision means non-relief complaints are being wrongly flagged — the false-positive cost.

03 · CONCRETE EXAMPLE

Model A, Model B, and a new Model C — three different trade-offs

Model A (Concept 01/02's majority-class floor): TP=0, FP=0, FN=223, TN=777 → recall = 0/223 = 0%, precision = 0/0, undefined — it never predicts relief at all, so there's no predicted-positive pile to judge. Model B (partial catch): TP=100, FP=100, FN=123, TN=677 → recall = 100/223 ≈ 44.8%, precision = 100/200 = 50%. Model C, new here — predicts relief for every single complaint: TP=223, FP=777, FN=0, TN=0 → recall = 223/223 = 100%, precision = 223/1000 = 22.3%.

MODEL A

Recall 0%, precision undefined — the "never flag anyone" extreme.

MODEL C

Recall 100%, precision 22.3% — the opposite extreme, "flag everyone."

04 · TECHNICAL MECHANISM

Same matrix, two columns of arithmetic read off it

1 · PRECISION'S DENOMINATOR

The predicted-positive column

TP + FP — every row the model called relief, correct or not.

2 · RECALL'S DENOMINATOR

The actual-positive row

TP + FN — every row that really was relief, caught or not.

3 · SHARED NUMERATOR

TP appears in both

The only cell precision and recall have in common — everything else in each ratio is a different set of rows.

4 · ONE FIXED THRESHOLD

Both ratios describe one decision point

Precision and recall are computed from one fixed set of predictions — moving the threshold that produced them is Concept 04's job, not this one's.

Where beginners collapse precision, recall, F1 and accuracy into one idea

07 · COMMON MISTAKES

What beginners often misunderstand

"F1 is just the average of precision and recall."

It's specifically the harmonic mean — Section 09 shows a plain average and F1 disagree by over 20 points on Model C, precisely because one input is much weaker than the other.

"Higher precision always means a better model."

A model that only ever flags one obviously-clear relief case can hit 100% precision while catching almost none of the real cases — high precision alone says nothing about coverage.

"Recall and precision measure the same kind of mistake."

Recall's blind spot is false negatives; precision's blind spot is false positives — they're accountable for opposite errors.

"This concept explains how to pick the best threshold."

Every number here comes from one fixed set of predictions. Comparing precision and recall across many thresholds is Concept 04's ROC and PR curves, not this concept.

04
INTUITION

A search engine's two failure modes

A search engine that returns every page on the internet for every query has perfect recall — it never misses the page you wanted — and useless precision, since almost every result is irrelevant. A search engine that returns exactly one page, and only when it's extremely confident, can have perfect precision and terrible recall, missing most queries' real answers. Neither failure is visible from a single "did it work" score; precision and recall each name one specific way the engine can fail.

Analogy boundaryA search engine's relevance judgment is often fuzzy or user-specific. CFPB's relief label is a fixed ground truth per complaint — the analogy explains the two failure directions, not the exact arithmetic, which Section 05 defines precisely.

Formal definitions

06
MECHANISM

Reading two ratios off the identical matrix

Take Model B's matrix: TP=100, FP=100, FN=123, TN=677
Precision looks only at the predicted-positive column: TP+FP = 100+100 = 200 → precision = 100/200 = 50%
Recall looks only at the actual-positive row: TP+FN = 100+123 = 223 → recall = 100/223 ≈ 44.8%
Neither computation touches TN=677 at all — precision and recall are both blind to how the model handles non-relief complaints it correctly clears
F1 = 2 × 0.500 × 0.448 / (0.500+0.448) = 0.448/0.948 ≈ 47.3% — close to the arithmetic mean of 47.4% here, because the two inputs are already close together

09
MATHEMATICS

Why a harmonic mean, proven rather than asserted

Let p be precision and r be recall, both in [0,1]. The arithmetic mean is A = (p+r)/2. The harmonic mean is H = 2pr/(p+r), which is exactly F1. A classical inequality — the arithmetic-mean/harmonic-mean inequality — states H ≤ A always, with equality only when p=r. The gap A−H grows specifically as p and r pull apart: substituting p=1, r=ε for a tiny ε shows A ≈ 0.5 while H ≈ 2ε, meaning A stays near 50% no matter how close r gets to zero, while H collapses toward zero along with the weaker input. That is the formal version of "a harmonic mean is dominated by the smaller value" — it is not a property an arithmetic mean shares.

F1 = 2pr / (p+r) ≤ (p+r)/2 = arithmetic mean — equality only when p = r, and the gap widens as p and r diverge

Business consequence: if a model can reach very high recall by flagging almost everything (as Model C does), a plain average would reward that strategy for its recall alone, half-covering for the resulting collapse in precision. F1 refuses that cover — it requires both ratios to be reasonably high before it reports a high score, which is exactly the property CFPB needs when recall and precision represent two different groups' real costs.

BOUNDARY CASE

Precision and recall both exactly equal

When p=r, the harmonic-mean/arithmetic-mean inequality becomes an equality — F1 and the plain average agree exactly, the only case where they do.

MISTAKE TO AVOID

Using F1 when one error type costs far more than the other

F1 weighs precision and recall equally; Concept 07's business-driven metric choice, later in this module, covers weighting them unevenly on purpose.

12
CODE

Precision, recall and F1, from scratch

PYTHON · FROM-SCRATCH PRECISION, RECALL, F1 
import numpy as np

def precision_recall_f1(tp, fp, fn):
    precision = tp / (tp + fp) if (tp + fp) > 0 else float("nan")
    recall = tp / (tp + fn) if (tp + fn) > 0 else float("nan")
    denom = precision + recall
    f1 = 2 * precision * recall / denom if denom > 0 else 0.0
    arithmetic = denom / 2 if not np.isnan(denom) else float("nan")
    return precision, recall, arithmetic, f1

models = {
    "Model A": (0, 0, 223),      # tp, fp, fn
    "Model B": (100, 100, 123),
    "Model C": (223, 777, 0),
}

for name, (tp, fp, fn) in models.items():
    p, r, a, f1 = precision_recall_f1(tp, fp, fn)
    print(f"{name}: precision={p:.1%} recall={r:.1%} arithmetic={a:.1%} f1={f1:.1%}")
# Model A: precision=nan recall=0.0% arithmetic=nan f1=0.0%
# Model B: precision=50.0% recall=44.8% arithmetic=47.4% f1=47.3%
# Model C: precision=22.3% recall=100.0% arithmetic=61.2% f1=36.5%

assert round(precision_recall_f1(223, 777, 0)[3], 3) < round(precision_recall_f1(223, 777, 0)[2], 3)

Model A's precision is genuinely undefined, not zero — the code returns nan rather than silently substituting a number, matching Section 05's boundary note.

13
ECOSYSTEM

The library versions, and their zero-division convention

sklearn.metrics.precision_score, recall_score, and f1_score compute exactly Section 05's three ratios given y_true and y_pred. Unlike Section 12's from-scratch code, sklearn does not return nan for Model A's undefined precision by default — it returns 0.0 and raises an UndefinedMetricWarning, a behavior controlled by the zero_division parameter. That default matters operationally: a monitoring dashboard that silently swallows the warning will log a "0% precision" that is really "no predictions were made to judge," a meaningfully different situation worth distinguishing in any alerting logic.

DIAGNOSIS

Failure modes

ARITHMETIC-MEAN SUBSTITUTION

Averaging precision and recall by hand instead of using F1

Section 10's Model C shows this can overstate a model's real score by more than 20 points.

SILENT ZERO-DIVISION

Treating a sklearn zero_division warning as noise

Collapses "no positives predicted" into the same 0% score as "predicted positives, all wrong" — two different failures.

Hides the specific cost on the audience the omitted ratio would have exposed.

18
REALITY

Production implications

  • Report precision and recall together, never F1 alone — F1 hides which of the two ratios is actually the weak one.
  • Decide and document the zero_division behavior before shipping a monitoring dashboard, so a genuine "no positives predicted" state isn't silently logged as ordinary 0% precision.
  • Recompute precision and recall per meaningful subgroup, not once module-wide, for the same aggregation reason Concept 02's matrix warning applies to every metric built from it.
19
RECALL

Knowledge check

Why is F1 always less than or equal to the arithmetic mean of precision and recall?
The arithmetic-mean/harmonic-mean inequality guarantees it for any two non-negative numbers, with equality only when the two numbers are equal — precision and recall included.
Why can a model achieve perfect recall trivially, and what does that imply about using recall alone to judge it?
Predicting the positive class for every row guarantees every real positive is caught, so recall alone can't distinguish that strategy from a genuinely selective, accurate one — precision is needed alongside it.

PORTABLE MEMORY

Concept card

The rule

Precision = TP/(TP+FP); recall = TP/(TP+FN); F1 = 2·precision·recall/(precision+recall), their harmonic mean — always ≤ the arithmetic mean, equal only when the two match.

Warning signs

  • F1 reported with no precision/recall breakdown alongside it
  • A high recall claimed as strength with no precision figure in sight
  • Zero-division warnings suppressed rather than investigated

One memorable example

Model C: 100% recall, 22.3% precision. Arithmetic mean flatters it at 61.2%; F1 correctly scores it at 36.5% — 24.7 points lower.

23
CAREER PRACTICE

Interview questions

Why does F1 use a harmonic mean instead of an arithmetic mean?
A harmonic mean is dominated by the smaller of its two inputs, so it can't be inflated the way an arithmetic mean can when one of precision or recall is much weaker than the other — proven via the AM-HM inequality.
Give a concrete model where precision and recall disagree sharply, and explain what that disagreement means operationally.
A "flag everyone" model has 100% recall (nothing is missed) and low precision (most flags are false alarms) — operationally, it trades a reviewer-time cost for a false sense of full coverage.
What does sklearn do by default when precision is mathematically undefined, and why does that default matter?
It returns 0.0 with an UndefinedMetricWarning rather than nan, which can silently conflate "no positive predictions were made" with "predictions were made and were all wrong" unless the warning is actually checked.
When would you deliberately not use F1 to compare two models?
When the real-world cost of a false positive and a false negative are meaningfully different, since F1 weighs precision and recall equally regardless of their actual business cost.
