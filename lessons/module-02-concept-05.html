MODULE 02 · CONCEPT 05

MAE, RMSE
and R².

Concepts 01-04 all scored a classification model — right class, wrong class, or a threshold swept across every possible cutoff. This concept scores a different kind of model entirely: one whose output is a number, not a class. MAE averages how far off every prediction is, in the target's own units. RMSE does the same thing but squares the errors first, so one very wrong prediction can dominate the whole score. R² asks whether the model beats the laziest possible prediction — always guessing the mean — the same baseline discipline Module 01 Concept 07 already established, applied here instead of re-derived.

A model that outputs a number, not a class

01 · CONCEPT FIRST

Three numbers, three ways of asking "how wrong?"

Model E predicts how many days a CFPB complaint will take to resolve — a number, not a class. MAE (mean absolute error) averages how far off every prediction is, in the target's own units — days, here. RMSE (root mean squared error) does the same job but squares each error before averaging, then square-roots the result back into the original units — so one very wrong prediction can pull the whole score up more than it would pull MAE. R² asks a completely different question: does this model beat the laziest possible prediction — guessing the mean every time — the same baseline test Module 01 Concept 07 already built.

First memory: MAE and RMSE both measure error size in the target's own units; R² measures whether the model beats a mean-predictor baseline at all.
02 · WHY IT EXISTS

A numeric prediction can be wrong by a specific amount

Concepts 01-04's predictions were either right or wrong — a complaint was correctly flagged as relief or it wasn't, with nothing in between. A regression prediction doesn't work that way: predicting 42 days when the true answer is 40 is a small miss; predicting 90 is a large one. There's no confusion matrix here because there's no small set of outcome cells to count into — the mechanics have to change to match a target that can be off by any amount, in either direction.

CLASSIFICATION ERROR (CONCEPTS 01-04)

"Wrong" is binary — right class or wrong class, counted into TP/FP/FN/TN cells.

NUMERIC ERROR (THIS CONCEPT)

Every prediction has a measurable distance from the true value — 2 days off is a smaller error than 40 days off, and that distance is the thing being averaged.

03 · CONCRETE EXAMPLE

Model E — 8 CFPB complaints, predicted days to resolution

Eight complaints, each with a true resolution time and Model E's predicted resolution time: (5→8), (10→12), (15→17), (20→18), (25→28), (30→33), (35→32), (40→60). Seven of the eight rows are ordinary — off by 2 or 3 days either way. The eighth row is off by 20 days: predicted 60, actual 40.

7 ORDINARY ROWS

Errors of 2-3 days each — small, everyday misses a resolution-time model would realistically make.

1 OUTLIER ROW

Row 8: predicted 60 days, actual 40 — a 20-day miss, roughly 7-10× the size of any other row's error.

04 · TECHNICAL MECHANISM

Same 8 errors, three different ways to summarize them

MAE

average(|actual − predicted|)

Every error counts in direct proportion to its size — a 20-day miss counts exactly 10× as much as a 2-day miss, no more.

RMSE

√(average((actual − predicted)²))

Every error is squared before averaging — a 20-day miss counts 100× as much as a 2-day miss before the square root brings the units back to days.

R²

1 − (model's total squared error) / (mean-predictor's total squared error)

Unitless. 0 means the model is exactly as good as always guessing the mean; 1 means every prediction is exact; negative means the model is worse than that mean guess.

SHARED UNITS

MAE and RMSE stay in days; R² does not

MAE and RMSE can be read directly against the target ("off by about 5 days"); R² only ever makes sense relative to the mean-predictor floor beneath it.

07 · COMMON MISTAKES

What beginners often misunderstand

"Lower RMSE always means a better model."

Only within the same target and the same scale — an RMSE of 5 on a days-to-resolution target and an RMSE of 5 on a dollar-amount target aren't comparable at all.

"MAE and RMSE are basically the same metric."

They agree closely when errors are roughly even in size and diverge sharply the moment one prediction is far worse than the rest — Model E's 4.75 vs. 7.48 is that divergence, not noise.

"An R² close to 1 always means a great model."

R² only says the model beats the mean-predictor baseline by a lot — it says nothing about whether a "bad" prediction here is off by 1 day or 100.

"Negative R² must be a bug."

It's a real, meaningful result: the model's predictions are, in total, worse than simply guessing the dataset's mean for every row — Section 14's lab produces one on purpose.

RMSE

Square root of average squared error — same units as MAE, but large errors count disproportionately more.

04
INTUITION

A tape measure versus a scale that squares first

Imagine measuring how far off eight arrows landed from a target's center, in inches. A tape measure records each distance directly and an average of those readings is MAE — a 20-inch miss counts as exactly ten 2-inch misses, no more. Now imagine a different instrument that squares each distance before averaging, then takes a square root at the end to bring the units back to inches — that's RMSE. The squaring step means one wildly off arrow pulls the final number up far more than nine close ones would pull it down; a tape measure never behaves that way.

Analogy boundaryA physical tape measure and scale don't actually differ in what they can record — both instruments here compute the same eight distances. The difference is entirely in how those eight numbers get combined afterward, which is the only thing MAE and RMSE actually disagree about.

09
MATHEMATICS

Why squaring changes how an error counts

MAE's building block is |e|, which grows in a straight line with the size of the error. RMSE's building block is e², which grows quadratically — doubling an error's size roughly quadruples its contribution before the final square root partially undoes that. This is also why RMSE can never be smaller than MAE for the same set of errors: squaring, averaging and then square-rooting a set of non-negative numbers (a result related to the quadratic-mean-versus-arithmetic-mean inequality) can only push the result up relative to a plain average of the same numbers, never down. Model E's 7.483 ≥ 4.75 is that inequality, not a coincidence.

RMSE ≥ MAE, for any set of errors, with equality only when every |ei| is identical

ERROR GROWTH · |e| (LINEAR) VS. e² (SCALED, QUADRATIC)

Green: |e|, rising steadily. Red: e², barely moving for small errors then overtaking |e| for large ones — the mechanism behind Model E's row 8 pulling RMSE up so much more than MAE.

Both curves are scaled to meet at the same point at the largest error shown — the shape difference, not the endpoint, is what this figure is teaching: squared error discounts small mistakes and amplifies large ones, relative to a plain average.

CONCRETE USE

Examples and counterexamples

THIS COURSE'S PROJECT

Model E's 4.75-day MAE vs. 7.48-day RMSE

Both are legitimate; they answer different questions — "typical miss" versus "how bad does the worst-case tail get."

BOUNDARY CASE

Every row predicted with zero error

MAE = 0, RMSE = 0, R² = 1 — the only point where all three metrics agree completely.

COUNTEREXAMPLE

"An RMSE of 5 is always better than an RMSE of 50"

Not if the two models are scored on different targets or different scales — an RMSE of 5 days and an RMSE of 5 dollars aren't the same kind of number at all.

MISTAKE TO AVOID

Reporting R² without stating what beat what

R² = 0.573 alone says nothing until it's paired with the mean-predictor baseline it was measured against.

12
CODE

MAE, RMSE and R², from scratch

PYTHON · FROM-SCRATCH MAE, RMSE AND R² 
import numpy as np

actual    = np.array([5, 10, 15, 20, 25, 30, 35, 40])
predicted = np.array([8, 12, 17, 18, 28, 33, 32, 60])

def mae(actual, predicted):
    return np.mean(np.abs(actual - predicted))

def rmse(actual, predicted):
    return np.sqrt(np.mean((actual - predicted) ** 2))

def r2(actual, predicted):
    ss_res = np.sum((actual - predicted) ** 2)
    ss_tot = np.sum((actual - actual.mean()) ** 2)
    return 1 - ss_res / ss_tot

print(f"MAE  = {mae(actual, predicted):.3f}")   # 4.750
print(f"RMSE = {rmse(actual, predicted):.3f}")  # 7.483
print(f"R2   = {r2(actual, predicted):.3f}")    # 0.573

assert round(mae(actual, predicted), 3) == 4.750
assert round(rmse(actual, predicted), 3) == 7.483
assert round(r2(actual, predicted), 3) == 0.573

# edge case: a mean-predictor baseline scores exactly R2 = 0 on its own training mean
baseline = np.full_like(actual, actual.mean())
assert round(r2(actual, baseline), 3) == 0.0

16
DIAGNOSIS

Failure modes

OUTLIER-DOMINATED RMSE

One bad row deciding the whole reported score

A single mislabeled or genuinely anomalous row can make RMSE look far worse than the model's typical behavior — check MAE alongside it before concluding the model is broken.

CROSS-SCALE COMPARISON

Comparing MAE or RMSE across differently-scaled targets

An MAE of 5 means something different for a days-to-resolution target than for a dollar-amount target — never rank models on raw MAE/RMSE across different targets.

R² WITHOUT ITS BASELINE

Reporting R² with no stated mean-predictor floor

The number alone answers nothing — Module 01 Concept 07's rule applies here exactly as it did for classification.

IGNORED NEGATIVE R²

Treating a negative R² as an error in the code

It's a legitimate result meaning the model loses to the mean-predictor baseline — Section 14's lab produces one on purpose at the slider's far end.

17
CORRECTION

Misconceptions

Incorrect beliefCorrection
MAE and RMSE always rank two models the same wayThey can disagree whenever the models' error distributions differ in shape, not just in average size — one model with many small errors and another with fewer but larger ones can trade places between the two metrics.
R² only ranges from 0 to 1, like a probabilityR² has no lower bound — Section 14's lab shows a prediction bad enough to push R² below −2, meaning the model is losing badly to the mean-predictor baseline.
MAE is just a cruder, less precise version of RMSENeither is an approximation of the other — they weight errors by different powers on purpose, and that difference is itself diagnostic information, not noise to average away.
18
REALITY

Production implications

  • Report MAE for any audience that needs a plain "typical miss" number, and RMSE alongside it whenever rare, large misses carry outsized real-world cost.
  • Never compare MAE or RMSE across model versions evaluated on different targets, units, or differently-scaled test splits without accounting for that difference first.
  • Log MAE, RMSE and R² together per model version in the registry (Module 18), always alongside the mean-predictor baseline's own value, so a future reader never has to guess what floor R² was measured against.
19
RECALL

Knowledge check

What is the one difference between how MAE and RMSE combine the same set of errors?
MAE averages the absolute values of the errors directly; RMSE squares each error first, averages those squares, then takes the square root of the result.
Why is R² = 0 not the same thing as "this model has zero error"?
R² = 0 means the model's total squared error exactly equals the mean-predictor baseline's — the model could still be off by a large amount on every row, it's just no better or worse than always guessing the mean.
A model's MAE is 4.75 and its RMSE is 7.48 on the same dataset. What does that gap tell you, on its own?
At least one error is much larger than the rest — a small, even spread of errors would leave MAE and RMSE much closer together.

FEEDBACK

Solution and teach-back

Open the worked solution
Errors (actual − predicted): −1, −1, +1, −3, 0. Absolute errors: 1, 1, 1, 3, 0, summing to 6 → MAE = 6/5 = 1.2. Squared errors: 1, 1, 1, 9, 0, summing to 12 → MSE = 12/5 = 2.4 → RMSE = √2.4 ≈ 1.549. Mean actual = 6, so the mean-predictor's total squared error is 4² + 2² + 0² + 2² + 4² = 40 → R² = 1 − 12/40 = 0.7. MAE and RMSE are fairly close together (1.2 vs. 1.549) because the errors here are mostly small and even, with only one row (a −3 miss) standing out moderately — nowhere near Model E's 10× outlier.

Teach-back: explain in your own words why this exercise's MAE-to-RMSE gap is much smaller than Model E's (4.75 vs. 7.48) — connect it to how evenly-sized each dataset's errors actually are.

PORTABLE MEMORY

Concept card

The three metrics

MAE: average |error|, own units. RMSE: √(average error²), own units but outlier-sensitive. R²: 1 − model's squared error / mean-predictor's squared error, unitless.

Warning signs and example

Warning sign: R² reported with no stated baseline, or a wide MAE/RMSE gap left unexplained. Memorable example: Model E's MAE 4.75 vs. RMSE 7.48 — one 20-day miss on 8 rows is the entire gap.

23
CAREER PRACTICE

Interview questions

Why would you report both MAE and RMSE rather than just one?
MAE gives a robust "typical miss" figure that one outlier can't distort; RMSE reveals whether that outlier exists at all — reporting only one hides half the story.
Explain, without calculus, why RMSE is never smaller than MAE for the same errors.
Squaring then averaging then square-rooting a set of non-negative numbers can only move the result up relative to a plain average of the same numbers, with equality only when every error has identical magnitude — a version of the quadratic-mean-versus-arithmetic-mean inequality.
Coding: how would you compute R² from raw actual and predicted arrays without a library?
Sum the squared errors for the model (SS_res) and for a constant mean-predictor (SS_tot), then compute 1 − SS_res/SS_tot — exactly Section 12's r2 function.
Debugging: a colleague reports R² = −0.4 and assumes their code has a bug. What do you tell them?
It's very likely not a bug — a negative R² is a legitimate outcome meaning the model's predictions are, in total, worse than simply predicting the dataset's mean for every row; check the model and features, not the R² formula, first.
