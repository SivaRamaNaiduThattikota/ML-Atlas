MODULE 02 · CONCEPT 09

0.4 points isn't proof.
It might just be noise.

Concept 07 chose Model 1's metric; Concept 08 warned that a chosen metric can be pushed the wrong way on purpose — gaming. This concept warns about a failure that needs nobody's help at all: on any finite test set, a metric can move by a small amount for no reason whatsoever, purely because of which complaints happened to land in the sample. Before trusting that a number went up for a real reason, ask two separate questions — is the gap statistically real, and if it is, is it large enough to matter? Neither question is about gaming; both are about noise and scale.

01 · CONCEPT FIRST

Two different questions live inside the word "improvement"

IS IT REAL? (statistical significance)

Could two candidates that perform identically, deep down, still produce this exact gap on this one test set — just from which complaints happened to land in the sample? A p-value or a confidence interval answers this.

DOES IT MATTER? (practical significance)

If the gap is real, is it large enough to justify the cost of switching models — retraining, redeploying, re-monitoring? No p-value answers this; it's a business floor, set on purpose.

First memory: a metric can move for a reason that has nothing to do with the model being better — pure sampling luck — and a real move can still be too small to care about. Both are different from Concept 08's gaming, which needs a real optimization channel to exploit.
02 · WHY IT EXISTS

Concepts 07-08 quietly assumed a clean move was a real move

Concept 07 chose which metric to tune. Concept 08 warned that the chosen metric could be pushed by gaming. Neither concept asked what happens when the metric moves for a completely clean reason — no gaming channel, nobody optimizing anything — and the move is still not real, just noise from a finite sample. Any test set has a finite number of rows; run the same model twice on two different random samples from the same underlying population, and the reported metric will almost never land on exactly the same number twice, even with nothing about the model changing at all.

WITHOUT THIS CONCEPT

A team sees candidate B's recall land 0.4 points above candidate A's and treats that as settled evidence that B is the better model.

WITH THIS CONCEPT

A team asks: could this exact 0.4-point gap show up between two models that are actually tied, just from sampling? Only after ruling that out does "does it matter" become worth asking.

CANDIDATE A

CANDIDATE B

THE GAP

0.4 recall points — exactly one additional complaint caught, out of 223.

One extra correctly-caught complaint is the entire difference between "ship candidate B" and "keep candidate A." Before that decision gets made, two separate questions need answers: is a one-row difference on a 223-row sample distinguishable from noise, and if it somehow is real, does 0.4 points actually justify retraining, redeploying, and re-monitoring a production model?

04 · TECHNICAL MECHANISM

Two questions, asked in a fixed order

Observe a gap between two candidates on one test set — b03's 0.4 points.
Ask: is it statistically real? Could two candidates with identical true performance produce this exact gap just from sampling? A p-value or confidence interval answers this.
Not statistically real — stop here. There is nothing yet to call "the effect of switching models."
Statistically real — proceed to the second question.
Ask: does it practically matter? Is the real gap large enough to be worth the cost of acting on it? This floor is a business decision, not a computed number.
Both yes — act on it. Either no — don't, not yet.

06 · IMPORTANT DISTINCTIONS

Gaming, real-but-trivial, and noise mistaken for signal — three separate failures

FailureWhat's actually happeningCommon confusion
Gaming (Concept 08)The proxy rises through a channel that doesn't touch the real goal — needs pressure and an unguarded channel to exploitAssumed to be the same thing as this concept's noise — it isn't; gaming is a real, exploitable move in the wrong direction, not an illusory move
Not statistically real (this concept)The observed gap is well within what sampling noise alone could produce on a test set this size — b03's 0.4 points, formally checked in Section 09Assumed to require something suspicious happening — it doesn't; a small, finite test set produces this on its own, with a perfectly honest evaluation

07 · COMMON MISTAKES

What beginners often misunderstand

"If B's number is higher than A's, B is the better model."

b03's 0.4-point gap is higher, full stop — but "higher" and "distinguishably better" are not the same claim; the first question in b04 exists precisely to separate them.

"A p-value under 0.05 means the difference is important."

A p-value only speaks to whether the gap is likely to be chance — it says nothing about size. Section 09's math and lab both hold this apart from the practical-floor question on purpose.

"Not statistically significant means the two models are equal."

It means the test set couldn't distinguish them — not the same claim as "they perform identically." A bigger test set, or a paired test, might still find a real gap the same data couldn't detect.

"A bigger test set always makes a result more trustworthy."

A bigger test set makes small effects easier to detect for real — including trivially small ones. Section 14's lab lets you watch this exact 0.4-point gap become "statistically significant" purely by dragging the sample size up, with the underlying gap never changing size.

09 · WHAT YOU SHOULD UNDERSTAND

Readiness check before moving on

Statistical significance

Whether an observed gap is distinguishable from what pure sampling noise could produce on a test set of this size — answered by a p-value or a confidence interval.

Practical significance

Whether a real gap is large enough to justify acting on it — a business floor, set independently of any statistical test.

The fixed order

Ask "is it real?" before "does it matter?" — a gap that isn't real yet has no size worth debating.

Neither statistically real (p≈0.92) nor, on its own, practically decided — the exact case this concept was built to catch.

04
INTUITION

A kitchen scale that jitters between two weighings of the same apple

Put the same apple on a kitchen scale twice. First reading: 152 grams. Second reading: 154 grams. Did the apple gain two grams sitting on a counter, or is that just the scale's normal jitter — the small, meaningless wobble any real measurement has? That's the "is it real?" question. Now suppose the apple genuinely did gain two grams somehow — does that matter for a recipe that just calls for "one medium apple"? Almost certainly not. That's the separate "does it matter?" question, and it only makes sense to ask once the first one is settled.

Analogy boundaryThe scale illustrates "small measurements have unavoidable noise, and a real change can still be too small to matter," not the exact arithmetic — b03's and Section 10's actual numbers come from CFPB's real 223-row test set, not from this analogy.

PRECISION

Formal definitions

TermDefinitionBoundary
Sampling noiseThe unavoidable variation in a computed metric that comes purely from which rows landed in a finite test set, with nothing about the model changingPresent in every finite-sample measurement — it is not a bug, a bias, or evidence of anything wrong
Statistical significance / p-valueThe probability of seeing a gap at least this large if the two candidates actually performed identically — a small p-value says the gap is unlikely to be pure noiseNever a probability that the model is "good" — it only speaks to whether the observed gap is distinguishable from zero
Confidence intervalA range of plausible true values for a metric, given the observed value and the sample size — b03's figure shows each candidate's recall with a roughly ±5.9-point intervalA 95% interval does not mean "95% chance the true value is in this range" in the strict frequentist sense — it means the method produces a covering range 95% of the time across repeated samples
Practical significance / effect-size floorA business-set threshold for how large a real difference has to be before it's worth acting on — CFPB's illustrative floor is 2.0 recall pointsNever derived from the data itself — it comes from weighing the cost of switching models against the benefit of the gain

09
MATHEMATICS

The two-proportion z-test, and the four-outcome matrix

Treat each candidate's recall as a proportion of successes out of n actual positive cases: p̂A = TPA/n, p̂B = TPB/n. Under the null hypothesis that both candidates truly perform identically, the pooled rate p̄ = (p̂A+p̂B)/2 gives a standard error for the difference, and the observed gap divided by that standard error gives a z-score, which converts to a two-tailed p-value.

SE = √( 2·p̄·(1−p̄) / n ) z = (p̂_B − p̂_A) / SE p = 2 · (1 − Φ(|z|)), where Φ is the standard normal CDF

This is the simplified independent-samples version, used by Section 14's lab for its "what if n were different" sweep. Section 10's worked example also runs the more correct paired version — McNemar's test, which uses the two candidates' discordant predictions on the same rows rather than treating the two samples as unrelated (Section 24's reference).

CODE

The two-proportion z-test and McNemar's test, from scratch

PYTHON · FROM-SCRATCH SIGNIFICANCE CHECK ON CFPB'S REAL 223-ROW NUMBERS 
from math import sqrt, erf

def two_proportion_ztest(a_correct, b_correct, n):
    p_a, p_b = a_correct / n, b_correct / n
    pooled = (a_correct + b_correct) / (2 * n)
    se = sqrt(2 * pooled * (1 - pooled) / n)
    z = (p_b - p_a) / se
    p = 2 * (1 - norm_cdf(abs(z)))
    return z, p

def norm_cdf(x):
    return 0.5 * (1 + erf(x / sqrt(2)))

def mcnemar(b_only_correct, a_only_correct):
    # b, c are the two discordant counts -- rows where exactly one candidate is right
    b, c = b_only_correct, a_only_correct
    chi2 = (b - c) ** 2 / (b + c)
    return chi2

# CFPB's real numbers: candidate A catches 160/223, candidate B catches 161/223
z, p = two_proportion_ztest(160, 161, 223)
assert round(z, 2) == 0.11
assert p > 0.9                      # nowhere near the conventional 0.05 cutoff

# illustrative discordant breakdown: 10 rows only-A-correct, 11 rows only-B-correct
chi2 = mcnemar(b_only_correct=11, a_only_correct=10)
assert round(chi2, 2) == 0.05        # tiny -- 21 discordant rows is not enough to separate them
assert chi2 < 3.84                   # 3.84 is the chi-square cutoff for p<0.05 at 1 degree of freedom

16
DIAGNOSIS

Failure modes

TEST-SET PEEKING

Checking significance repeatedly and stopping the moment p<0.05 appears

Re-running the same test as data trickles in, and declaring victory the instant it crosses 0.05 by chance, inflates the real false-positive rate well above 5% — a sampling-side relative of Concept 08's gaming.

IGNORING THE PAIRING

Using the independent two-sample test when the data is paired

Section 09's independent-samples formula is a simplification — CFPB's candidates share the same 223 rows, and Section 10's McNemar check is the more correct version for that exact situation.

ABSENCE OF EVIDENCE AS EVIDENCE OF ABSENCE

Treating "not significant" as "proven equal"

b03's result says the test set couldn't distinguish the two candidates — not that no real difference exists. A bigger or paired test might still find one.

ONE-METRIC TUNNEL VISION

Significance-testing the tuning metric while the guardrail moves unnoticed

Confirming candidate B's recall gap is real, without also checking Concept 07's guardrail metric for a real change, misses exactly the kind of trade-off Concept 07's framework exists to catch.

CORRECTION

Misconceptions

Incorrect beliefCorrection
A higher number on a test set always means a genuinely better modelFalse — b03's 0.4-point gap is higher, but Section 10's check puts it at p≈0.92, comfortably explainable by sampling noise alone.
Statistical significance and practical significance are the same checkFalse — one asks whether a gap is real, the other asks whether a real gap is big enough to act on; a gap can be either, both, or neither (Section 09's matrix).

18
REALITY

Production implications

  • Set the practical-significance floor before looking at the comparison's results, not after — choosing a floor to fit a result you already like is the same integrity problem as Section 11's "grow the test set until p<0.05" mistake, aimed at the floor instead of the sample size.
  • Use a paired test (McNemar, or a bootstrap over the same rows) whenever two candidates were scored on the exact same test set — Section 15's contrast explains why the independent-samples version is a conservative simplification, not the most correct choice for that case.
  • Remember that a bigger test set makes small effects easier to detect for real, including trivially small ones — a "statistically significant" result on a huge sample still needs the practical-significance question asked separately (Section 09's matrix, top-right vs. top-left cells).
19
RECALL

Knowledge check

State the two questions this concept asks, in order, and explain why the order matters.
"Is the observed gap statistically real?" then "is a real gap large enough to matter?" — the order matters because a gap that fails the first question has no size worth debating in the second (Section 06).
Why does CFPB's 0.4-point recall gap fail the first question at n=223?
The two-proportion z-test gives z≈0.11, p≈0.92 (Section 10) — a gap this small, on a sample this size, is comfortably within what pure sampling noise could produce between two identically-performing candidates.
Why is McNemar's test more correct than the independent two-proportion test for CFPB's exact situation?
Both candidates were scored on the same 223 rows — McNemar's test uses the discordant rows directly, while the independent-samples version ignores that the two samples are the same rows (Section 09, Section 15).

21
FEEDBACK

Solution and teach-back

Open one defensible answer
Pooled rate p̄ = 0.813, SE = √(2·0.813·0.187/1000) ≈ 0.0174, z = 0.006/0.0174 ≈ 0.34, p ≈ 0.73 — nowhere near significant at n=1,000. Solving SE_needed = 0.006/1.96 ≈ 0.00306 and n = 2·p̄·(1−p̄)/SE_needed² gives n ≈ 32,447 — roughly 32 times the actual test set's size would be needed for this exact 0.6-point gap to read as statistically significant.

Teach-back: explain, in your own words, why "the model was retrained on 50,000 new rows" has no bearing on whether the 0.6-point gap measured on the 1,000-row test set is statistically real — and why a bigger training set is a completely different thing from a bigger test set.

PORTABLE MEMORY

Concept card

Statistical vs. practical significance, defined

Statistical significance: is an observed gap distinguishable from sampling noise? Practical significance: if it's real, is it large enough to act on? Ask in that order, always.

Core equation and example

z = (p̂B − p̂A) / √(2p̄(1−p̄)/n). Memorable example: CFPB's candidate B beating candidate A by 0.4 recall points on n=223 gives p≈0.92 — noise, not proof.

CAREER PRACTICE

Interview questions

A stakeholder says "our new model's metric is higher, ship it." What do you check first?
Whether the gap is statistically distinguishable from sampling noise on the test set it was measured on — a higher number alone, as in b03's 0.4-point CFPB case, is not evidence of a real improvement.
Coding: given two candidates' predictions on the same test set, how would you test whether their recall difference is real?
Build the 2×2 discordant-agreement table (both-correct, A-only, B-only, both-wrong) and run McNemar's test on the two discordant counts — exactly Section 12's mcnemar function, applied to real prediction arrays instead of the illustrative breakdown.
Debugging: a "statistically significant" result appeared only after the team doubled the test set mid-experiment. What's the concern?
Test-set peeking (Section 16) — deciding to grow the sample specifically because the first result wasn't significant, then re-testing, inflates the real false-positive rate; the sample size should be fixed before looking at results.
System design: how would you build a guardrail so no one ships a model change based on a non-significant metric bump?
Require both checks — a p-value or confidence interval on the observed gap, and a pre-registered practical floor (Section 18) — as a gate in the same review process Concept 07's framework already routes deployment decisions through, before any model swap is approved.
