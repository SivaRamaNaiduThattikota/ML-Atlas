03 · CONCRETE EXAMPLE

THE TRADE

04 · TECHNICAL MECHANISM

Three checks, run in order, on both candidates

Check 1 — the guardrail (Concept 07-08): CFPB sets a 60% precision floor. Candidate A (64.0%) clears it; candidate B (57.7%) does not.
Check 2 — is B's recall edge even real (Concept 09)? No — z≈0.11, p≈0.92, comfortably explainable by sampling noise on 223 rows.
Check 3 — would it matter if it were real (Concept 09)? No — 0.4 points is well under the 2.0-point practical floor.
Verdict — candidate B fails on all three independent grounds. Candidate A wins by every check that was run.

07 · COMMON MISTAKES

What beginners often assume, and shouldn't

"Candidate B is better because its recall is higher."

b04's Check 2 already ruled this out — the 0.4-point edge is statistically indistinguishable from noise (Concept 09).

"The guardrail check alone was enough to decide."

It was enough here because B fails all three checks, but in general all three need running — a candidate could pass the guardrail and still lose on a real, large recall deficit elsewhere.

"This decision is permanent."

It's locked for now, given today's costs and today's data — Concept 08's warning still applies if this exact metric gets optimized hard later, and a new significance check applies to any future candidate.

"Model 2 gets the identical answer."

Model 2's own shape (ranking-led, calibration companion, per Concept 06/07) already differs — this concept's specific numbers apply to Model 1 only.

12
CODE

The full decision, from scratch

PYTHON · NO LIBRARIES 
def metrics(tp, fp, fn, tn):
    precision = tp / (tp + fp)
    recall = tp / (tp + fn)
    f1 = 2 * precision * recall / (precision + recall)
    return {"precision": precision, "recall": recall, "f1": f1}

A = metrics(160, 90, 63, 687)
B = metrics(161, 118, 62, 659)

PRECISION_FLOOR = 0.60
RECALL_GAP_STATISTICALLY_REAL = False   # Concept 09: p ~= 0.92
RECALL_GAP_PRACTICALLY_SIGNIFICANT = False  # Concept 09: 0.4pt < 2.0pt floor

def decide(a, b, floor, gap_real, gap_matters):
    a_ok, b_ok = a["precision"] >= floor, b["precision"] >= floor
    if a_ok and not b_ok:
        return "A"          # guardrail alone decides
    if b_ok and not a_ok:
        return "B"
    if a_ok and b_ok:
        return "B" if (gap_real and gap_matters) else "A"
    return None              # neither survives the guardrail

winner = decide(A, B, PRECISION_FLOOR, RECALL_GAP_STATISTICALLY_REAL, RECALL_GAP_PRACTICALLY_SIGNIFICANT)
assert round(A["precision"], 3) == 0.640
assert round(B["precision"], 3) == 0.577
assert winner == "A"

DIAGNOSIS

Failure modes

STOPPING AFTER ONE CHECK

Declaring a winner after only the guardrail, always

Worked here because B failed outright — a closer comparison needs Concept 09's checks to actually decide it, not just confirm a foregone conclusion.

RE-OPENING A LOCKED DECISION CASUALLY

Switching to candidate B later because "recall looked better in a demo"

Exactly Concept 08's gaming risk in a new guise — a single anecdote is not a re-run of this concept's three checks on real data.

FORGETTING THE COMPANION

Never checking calibration again once Model 1 ships

Concept 07's companion designation means "watch, not ignore" — Section 18 names when it needs promoting to a guardrail.

TREATING THIS AS PERMANENT

Assuming candidate A wins forever, regardless of future data

A new candidate, a new test set, or a real shift in costs would need this exact three-check process re-run, not an appeal to today's answer.

FEEDBACK

Solution and teach-back

Open the worked solution
Candidate C: precision = 155/(155+70) = 155/225 ≈ 68.9%, recall = 155/(155+68) = 155/223 ≈ 69.5%, F1 = 2×0.689×0.695/(0.689+0.695) ≈ 69.2%. Precision (68.9%) clears the 60% guardrail — C survives. CAREER PRACTICE

Interview questions

Walk through how you would choose between two classifier candidates for a production deployment.
Compute each candidate's relevant metrics (Concepts 01-06), run the five-question filter to name a tuning metric and guardrail (Concept 07), check the guardrail first and eliminate any candidate that fails it (Concept 08), then check whether any remaining apparent advantage is statistically real (Concept 09) and large enough to matter (Concept 09) before letting it change the decision — exactly this concept's three-check rule.
Why is a guardrail failure alone sometimes enough to decide, without needing a significance test?
A guardrail is a hard floor, not a comparative claim — a candidate below it is disqualified regardless of how its other metrics compare, so no test of "is the gap real" is needed once one candidate is already out (Section 06).
Debugging: a colleague wants to switch to candidate B because "it catches more true positives." What would you show them?
Section 10's full table — B fails the 60% precision guardrail outright, and even setting that aside, Concept 09 already showed the recall edge is statistically indistinguishable from noise and below the practical floor.
System design: how would you make this three-check decision repeatable for every future model candidate, not just Model 1?
Encode Section 12's decide() function (or its equivalent) into the model-evaluation pipeline itself, so every candidate comparison automatically runs the guardrail check, then the significance check, then the practical-floor check, in that fixed order, before a human ever sees a recommendation.
