MODULE 04 · CONCEPT 03

Never let a row grade its own exam.
The fix for the field Concept 02 refused to touch.

Concept 02 built one-hot and ordinal encoding, then deliberately stopped short of Company -- K=340, and naive one-hot there means 340 mostly-empty columns per row. Target encoding looks like the obvious fix: replace each company with the mean of the target for rows in that company. It is also the first technique in this module that reaches into the target itself, and that is exactly why it opens a leakage risk one-hot and ordinal never had. Compute a category's mean from the SAME rows you train on, and every row's encoding is partly built from that row's own label -- a direct instance of Module 01 Concept 08's general leakage warning, and a failure of Concept 01's "no leakage" gate. The fix is out-of-fold (OOF) computation: split rows into folds, and encode each fold using only what the OTHER folds know.

MODULE 04 · CONCEPT 03 ACTIVE (3/10)

PROGRESSIVE BEGINNER CORE

A mean that includes your own label isn't a statistic -- it's a mirror

Target encoding replaces a category with a statistic of the outcome. That statistic has to come from somewhere -- and if it comes from the very row being encoded, the row's own label leaks straight back into its own feature value.

01 · CONCEPT FIRST

Naive target encoding lets a row see its own label. Out-of-fold refuses to.

TARGET ENCODING (NAIVE)

Replace each category with the mean of the target across every row in that category -- including the row currently being encoded.

TARGET ENCODING, OUT-OF-FOLD

Compute that same mean, but only from rows OUTSIDE the current row's fold. The row never contributes to its own encoded value.

First memory: never let a row's encoding be built from a statistic that used that row's own label.
02 · WHY IT EXISTS

Concept 02 built two techniques and deliberately would not touch Company.

One-hot and ordinal encoding both reshape a category -- spread it into K columns, or compress it into one integer column. Neither one looks at the target. Company's K=340 (34.0% of 1,000 rows, HIGH severity per Module 03 Concept 08) makes naive one-hot impractical: 340 mostly-empty columns per row. Target encoding fixes the shape problem instantly -- one column, any K -- but it is a genuinely different kind of fix, because it computes a statistic FROM the target. That is exactly why it opens a brand-new leakage risk Concept 02's two techniques never had.

04 · TECHNICAL MECHANISM

Three steps, borrowed from cross-validation's fold idea

1 · SPLIT

Divide rows into folds

Here, 2-5 folds by round-robin row index -- a simplification for hand computation, not a claim about how real k-fold splitting works.

2 · ENCODE FROM OTHERS

Per fold, use only the OTHER fold(s)

Each category's mean is computed from rows outside the current fold, falling back to that other fold's overall mean when the category is absent there.

3 · ASSIGN BACK

Apply that mean to every row in the current fold

No row ever contributes to the statistic used to encode itself.

The fold-splitting idea is borrowed directly from cross-validation -- full k-fold mechanics, randomization, and stratification are Module 14's job ("Cross-validation & experimental design"), not taught here.

07 · COMMON MISTAKES

What beginners often assume, and shouldn't

"Target encoding is just a fancier ordinal encoding."

False -- ordinal encoding never looks at the label. Target encoding is defined entirely in terms of it.

"As long as I use the same formula on train and test, it's fine."

False -- consistency doesn't fix self-inclusion. The SAME rows still leak into the SAME rows' own encoding, no matter how consistently the formula is applied.

"Smoothing or regularization fixes the leakage."

Smoothing (blending a category's mean toward the global mean) is real and useful -- but it fixes noise in small categories, not self-inclusion. OOF fixes leakage; smoothing fixes noise; they're often combined, but they solve different problems.

04
INTUITION

An open-book exam graded with your own answer key

Naive target encoding is grading yourself using an answer key that already contains your own answer -- of course you get it right, every time, and the score means nothing. Out-of-fold encoding is grading yourself using only classmates' answers -- the other fold's rows -- which is the only version of the exercise that actually measures anything.

Analogy boundaryThe exam image captures why self-inclusion is dishonest. It doesn't capture the fold-fallback edge case for singleton categories -- what happens when there are no "classmates" in the same category at all. Sections 09 and 10 handle that exactly.

06
MECHANISM

Split, encode from the others, assign back, verify

Step 1 — split rows into folds.
Step 2 — per fold, compute each category's target mean using only the OTHER fold(s)' rows, falling back to the other fold's overall mean when the category is absent there.
Step 3 — assign that mean back onto every row in the current fold.
Step 4 — verify: confirm no row's own label contributed to its own assigned value.

09
MATHEMATICS

The singleton identity, and what the fold fallback depends on

For a singleton category c (exactly one row i with x_i = c), naive encoding is a mean over a one-element set: enc(c) = mean({y_i}) = y_i, exactly, with no exceptions. Every one of Companies A through H is a singleton in the ten-row toy table, so naive(c) = y_i for all eight -- which is precisely why the naive column reproduces the label column exactly, row for row.

c singleton ⇒ enc(c) = mean({y_i}) = y_i

The OOF fallback value depends entirely on fold composition, not on the category at all: every singleton in fold k falls back to mean(y_i : i ∉ fold k), the other fold's overall rate. In the toy example both folds' overall rate happens to be 0.6, so every singleton's OOF value is 0.6 regardless of which singleton it is -- a direct consequence of the fallback rule, not a coincidence about any one company.

11
CONCRETE USE

Four cards: a clean fit, a boundary case, a production use, and a mistake

CLEAN FIT

Company, genuinely repeating companies

A company like Company I that appears more than once benefits from real signal -- OOF preserves it instead of discarding it.

BOUNDARY CASE

A mid-cardinality field, most categories with 3-5 rows

OOF still works, just with less dramatic fallback behavior than pure singletons -- most categories have at least some cross-fold evidence to average.

PRODUCTION USE

Persisting the fold-fit encoder

At inference time there's no "own row" to leak against for a genuinely new row -- the shipped mapping uses the FULL training set's mean, computed once, after the fold structure has done its job during fitting.

MISTAKE TO AVOID

Fitting once on the whole set, never holding out folds

Silently reintroduces the naive leak -- the fold structure only protects the encoder's OWN fit; skip it and self-inclusion is back.

12
CODE

From-scratch NumPy naive and out-of-fold target encoders

PYTHON · NUMPY, NO LIBRARY ENCODER CALL 
import numpy as np

def mean(values):
    return sum(values) / len(values)

def naive_target_encode(categories, labels):
    """Leaky by construction -- each row's own label helps compute
    the very mean assigned back to that row."""
    out = []
    for i, c in enumerate(categories):
        same = [labels[j] for j in range(len(categories)) if categories[j] == c]
        out.append(mean(same))
    return out

def assign_folds(n, fold_count):
    """Round-robin: row i goes to fold i % fold_count. A deterministic
    simplification for hand-checking -- real k-fold splitting is
    typically randomized/stratified, taught in full in Module 14."""
    return [i % fold_count for i in range(n)]

def oof_target_encode(categories, labels, fold_count):
    folds = assign_folds(len(categories), fold_count)
    out = []
    for i, c in enumerate(categories):
        k = folds[i]
        other_same = [labels[j] for j in range(len(categories))
                      if folds[j] != k and categories[j] == c]
        if other_same:
            out.append(mean(other_same))
        else:
            other_fold = [labels[j] for j in range(len(categories)) if folds[j] != k]
            out.append(mean(other_fold))          # fallback: no cross-fold partner
    return out

companies = ['A','B','C','D','E','F','G','H','I','I']
labels    = [1,  0,  1,  0,  0,  1,  0,  1,  1,  1]

naive = naive_target_encode(companies, labels)
assert naive == labels                              # every singleton IS its own label

oof2 = oof_target_encode(companies, labels, fold_count=2)
assert oof2[:8] == [0.6]*8                          # every singleton falls back to 0.6
assert oof2[8] == 1.0 and oof2[9] == 1.0             # Company I keeps its real signal

Both assertions reproduce Sections 03 and 10's worked numbers exactly. assign_folds is intentionally the simplest possible split -- matching the lab's slider and the worked example's arithmetic -- not a claim about how production k-fold splitting is actually done.

DIAGNOSIS

Failure modes

NAIVE ENCODING SHIPPED SILENTLY

Perfect train-time correlation, gone on holdout

Ties directly back to Concept 01's train-vs-holdout gate -- a suspiciously perfect single-column signal is the textbook leakage tell.

FIT-ONCE, NO FOLD STRUCTURE

OOF encoder fit on the full training set with no folds

Reintroduces the naive leak silently -- the fold structure only protects the encoder's own fit, and skipping it undoes the entire fix.

UNSEEN CATEGORY AT INFERENCE

Undefined behavior with no fallback plan

A brand-new company at inference time with no fold history at all needs a defined global-mean fallback, echoing Concept 02's handle_unknown discussion.

REALITY

Production implications

  • Encoder artifacts must be versioned like Concept 02's fitted category lists -- the fold-fit mapping that ships is the single result of the encoder's OWN fit, not something recomputed per request.
  • A brand-new company at inference time needs a defined fallback (the global mean), echoing Concept 02's handle_unknown discussion for a genuinely unseen category.

19
RECALL

Knowledge check

Why does every singleton company's naive encoding exactly equal its own label?
Because naive encoding for a singleton is a mean over a one-element set -- the category's only row -- and the mean of one value is that value itself. There is no averaging effect to dilute it.
Why is the fold-invariance fact (naive's match rate never changes across fold counts) the real proof, not a coincidence?
Because naive encoding's formula never references fold membership at all -- it uses every row unconditionally. Changing something the computation never looks at cannot change the result, which is exactly why the 100% match rate is fold-invariant and exactly why that invariance itself is diagnostic of leakage.
Why doesn't smoothing alone fix this specific leak?
Smoothing blends a category's mean toward the global mean based on row count -- it reduces noise from small samples, but a singleton's self-included mean is still partly built from its own label even after blending. Only excluding the row's own fold removes the self-inclusion itself.

Open the worked solution

Rows: 1·X=1, 2·Y=0, 3·X=1, 4·Z=0, 5·W=1, 6·Y=0. Naive: X appears in rows 1 and 3, both labeled 1, so naive(X) = mean(1,1) = 1.0 for both. Folds (i mod 2, 0-based): Fold 1 = rows 1,3,5 (X,W,X... row 5 is W); Fold 2 = rows 2,4,6 (Y,Z,Y). X appears twice, in rows 1 and 3 -- both in Fold 1 -- so X has NO cross-fold partner either, and falls back to Fold 2's overall mean, mean(0,0,1) = 0.333, for both its rows. Y appears in rows 2 and 6, both in Fold 2 -- also no cross-fold partner, falls back to Fold 1's overall mean, mean(1,1,1) = 1.0. Z (row 4, Fold 2) and W (row 5, Fold 1) are singletons, falling back the same way: Z → Fold 1's mean 1.0, W → Fold 2's mean 0.333.

The teach-back point: unlike Company I in the main worked example, X and Y here repeat WITHIN the same fold rather than across folds, so even a repeating category can end up with no genuine cross-fold evidence at all -- repetition alone doesn't guarantee OOF finds real signal; the repeats have to land in different folds.

CAREER PRACTICE

Interview questions

Conceptual: why is target encoding riskier than one-hot encoding?
One-hot encoding never looks at the target column at all -- it only reshapes the category. Target encoding is defined entirely in terms of the target, so if it's computed from the same rows being encoded, each row's own label leaks straight back into its own feature value. One-hot has no equivalent risk to leak through.
Math: prove that naive target encoding equals the label exactly for a singleton category.
A singleton category c has exactly one row i with x_i = c. Naive encoding computes enc(c) = mean(y_j : x_j = c) = mean({y_i}), the mean of a one-element set, which by definition equals that single element, y_i. So enc(c) = y_i exactly, with no approximation.
Coding: spot the leak in a snippet that fits a target encoder before splitting folds.
If encoder.fit_transform(X, y) is called once on the entire training set before any fold split exists, every row's encoded value is computed using that same row's own label -- identical to the naive case in this concept, just wrapped in a class name that sounds safer. The fold split has to exist BEFORE fitting, not be checked afterward.
Debugging: an offline metric using a target-encoded feature looks great, but production is much worse. First thing to check?
Whether the target encoder was fit with proper fold exclusion or fit naively on the full training set -- a suspiciously strong offline number from a target-encoded column is the same red flag as Concept 01's train-vs-holdout gate, and it's the first place to look before touching anything else.
System design: how would you version a fold-fit target encoder across model retrains?
Persist the final fitted mapping (computed from the full training set after the fold-based fitting process completes) alongside the model artifact and its version tag, exactly like Concept 02's category lists -- and re-fit the whole fold-split process from scratch on each retrain's data rather than incrementally updating the old mapping, since fold membership itself is tied to that specific training run.
