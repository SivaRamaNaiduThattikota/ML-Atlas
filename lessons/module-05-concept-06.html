MODULE 05 · CONCEPT 06

The fix changed the model.
Not every metric noticed.

Concepts 02-05 each fixed imbalance and each pointed to a number that improved -- resample the rows, weight the loss, move the threshold, price a cost matrix. None of them asked whether the SCORING used to measure that win still means what it used to. This concept runs that audit on three metric families at once: accuracy (still misleading, and now non-monotonically so), precision/recall/F1 (still trustworthy, because they're direct confusion-matrix counts, not probability estimates), and calibration (actively distorted by a training-time fix like resampling or weighting, via a closed-form odds-rescaling shift). On a fresh 10-row CFPB-style toy set, weighting a raw model at this set's own balanced ratio r=4.0 moves the average predicted probability from 18.8% to 42.0% against an unchanged 20.0% true base rate -- a 22.01-point calibration gap opening up even as accuracy merely drops from 90% to 80% and F1 ties exactly at 66.67% on both sides. Threshold moving (Concept 04) and cost-sensitive learning (Concept 05) never retrain anything, so neither carries this calibration risk -- it's specific to Concepts 02-03's training-time fixes.

02 · WHY IT EXISTS

The question every prior fix skipped

Concepts 02-05 each celebrated a fix -- better recall, a derived threshold, a cost-matrix win -- without ever asking whether the scoring used to measure that win still means what it used to. This concept opens that question directly, and the answer turns out to be different for each metric family.

03 · CONCRETE EXAMPLE

A fresh 10-row toy set, raw versus weighted

2 relief-granted rows (R1=0.55, R2=0.35), 8 non-relief rows (N1=0.25 down to N8=0.03) -- a 20% base rate, deliberately a NEW toy set, not the 3-minority/7-majority set reused across Concepts 01/04/05. Raw, the model is reasonably calibrated: mean predicted probability 18.8% against a true 20.0% base rate. After class weighting at this set's own balanced ratio, r = 8/2 = 4.0 (this toy set's own ratio -- explicitly NOT CFPB's real 3.4843 from Concepts 01/03/05, kept separate on purpose so the numbers below stay internally consistent), the mean predicted probability jumps to 42.0% against the SAME true 20.0% base rate. Nothing about the world changed; only the loss weighting did.

04 · TECHNICAL MECHANISM

The odds-rescaling transform

Class weighting inflates every prediction's confidence by a fixed multiplier on the odds, not the probability directly: p_weighted = (r·p_raw) / (r·p_raw + (1−p_raw)), equivalently a shift of ln(r) on the logit scale. At r=4.0, ln(4)=1.3863 -- the same shape of correction discussed in Elkan (2001) for adjusting probabilities under a shifted sampling ratio, already cited in Concept 05.

07 · COMMON MISTAKES

What beginners often assume, and shouldn't

"The fix improved accuracy, so it worked."

False in general -- r=2.0 hits 100% accuracy and r=6.0 falls to 70%, on the identical fix, just at different strengths.

"A resampled or weighted model's probabilities are just as usable as before."

False -- 42% no longer means 42% once class weighting has shifted every prediction's odds by a fixed multiplier.

"If precision/recall/F1 changed after the fix, something's wrong with them."

False -- they're SUPPOSED to change; that's them working correctly, not evidence of unreliability.

09
MATHEMATICS

Deriving the odds-rescaling identity, and the F1-symmetry proof

odds_raw = p_raw / (1−p_raw)
odds_weighted = r · odds_raw ⟺ logit(p_weighted) = logit(p_raw) + ln(r)
p_weighted = (r·p_raw) / (r·p_raw + (1−p_raw))
F1(p,r) = 2pr/(p+r) = 2rp/(r+p) = F1(r,p) — symmetric in its two arguments by construction

Since p_weighted is a strictly increasing function of p_raw for any fixed r>0 (the derivative dp_weighted/dp_raw = r/(r·p_raw+1−p_raw)² is always positive), sorting by p_raw and sorting by p_weighted give the identical row order -- rank, and therefore discrimination, is exactly preserved. This is the same monotonic-transform point Module 02 Concept 06 already makes about calibration. The F1 formula's symmetry in precision and recall is why the main worked example's two operating points, (precision,recall)=(100%,50%) and (50%,100%), land on the exact same F1 -- not a numerical accident.

10
WORKED EXAMPLE

18.8% to 42.0% -- the number weighting quietly breaks

Step 1 -- the setup. A fresh 10-row CFPB-style toy validation set: 2 relief-granted rows (R1=0.55, R2=0.35), 8 non-relief rows (N1=0.25, N2=0.20, N3=0.15, N4=0.12, N5=0.10, N6=0.08, N7=0.05, N8=0.03) -- a 20% base rate, close to CFPB's real 22.3%, and deliberately NOT the 3-minority/7-majority (30%-base-rate) toy set reused across Concepts 01/04/05, to avoid muddying the calibration story. These are an unweighted/raw model's predicted probabilities -- a constructed illustration, like every toy score in this module, not a literally-fitted model's output.

Step 2 -- the raw model is reasonably calibrated. Mean(p_raw) = 1.88/10 = 0.1880 (18.8%) versus the true 20.0% base rate -- an 18.8−20.0 = −1.2-point gap, small.

Step 3 -- class weighting distorts calibration. This toy set's own balanced ratio is r = n_majority/n_minority = 8/2 = 4.0 -- deliberately NOT CFPB's real 3.4843 from Concepts 01/03/05, kept separate on purpose so this set's own numbers stay internally consistent. Class weighting's effect on a predicted probability is modeled via the odds-rescaling identity p_weighted=(r·p_raw)/(r·p_raw+(1−p_raw)) (Section 09 derives it; the same shape of correction discussed in Elkan (2001), already cited in Concept 05). Per row at r=4.0: R1 0.5500→0.830189, R2 0.3500→0.682927, N1 0.2500→0.571429, N2 0.2000→0.500000 (a genuine boundary case -- counted as flagged, matching Concept 04's own "≥0.5 predicts positive" convention), N3 0.1500→0.413793, N4 0.1200→0.352941, N5 0.1000→0.307692, N6 0.0800→0.258065, N7 0.0500→0.173913, N8 0.0300→0.110092. Mean(p_weighted) = 4.201/10 = 0.4201 (42.01%) against the SAME true 20.0% base rate -- a +22.01-point gap, roughly 18× larger than the raw model's −1.2-point gap. Nothing about the real world changed; only the loss weighting did.

Step 4 -- accuracy, at a fixed threshold of 0.5, before versus after weighting. Raw @0.5: TP=1 (R1 caught), FP=0, FN=1 (R2 missed), TN=8 → accuracy=90.0%, precision=100.0%, recall=50.0%, F1=2·1·0.5/1.5=66.67%. Weighted (r=4.0) @0.5: TP=2 (both caught), FP=2 (N1, N2 both wrongly flagged), FN=0, TN=6 → accuracy=80.0%, precision=50.0%, recall=100.0%, F1=2·0.5·1/1.5=66.67%. Accuracy DROPS 10 points (90%→80%) even though the fix did exactly what weighting is supposed to do (recall 50%→100%) -- the same accuracy blind spot Concept 01's ΔE=TP−FP mechanism and Module 02 Concept 01's own 77.7%-tie already diagnosed, now shown as one fix's own strength changes rather than two different fixed models being compared. F1 TIES EXACTLY at 66.67% in both cases -- not a coincidence: raw's (precision,recall)=(100%,50%) is exactly weighted's (recall,precision)=(100%,50%) with the two swapped, and F1(p,r)=F1(r,p) by construction (Section 09).

Step 5 -- sweeping r from 1.0 to 6.0. Accuracy moves NON-monotonically (90.0%→100.0%→90.0%→80.0%→80.0%→70.0% at r=1,2,3,4,5,6) while the calibration gap grows MONOTONICALLY and substantially (−1.2, +9.2, +16.47, +22.01, +26.46, +30.14 points), and recall is pinned at 100% for every r≥2 while precision falls off steadily (100%, 100%, 66.7%, 50%, 50%, 40%). Precision, recall, and F1 -- whatever their value -- are always exact, honest readings of the real confusion matrix at that r. The calibration gap is the number that quietly stops meaning what it claims.

Verification method: every number above was computed via an executed Node.js script using the closed-form odds-ratio formula and cross-checked with an independent logit-shift formula, matching to floating-point precision (<1e-9) on every row. An explicit confusion-matrix tally function (looping TP/FP/FN/TN by direct comparison, not a shortcut formula) ran at r=1.0 through 6.0 in 1.0 steps, alongside a rank-order check confirming discrimination is preserved.

CODE

The transform, the audit, and the calibration gap, from scratch

PYTHON · NO LIBRARIES 
def p_weighted(p_raw, r):
    return (r * p_raw) / (r * p_raw + (1 - p_raw))

def confusion_and_metrics(rows, threshold=0.5):
    tp = fp = fn = tn = 0
    for score, label in rows:
        pred = 1 if score >= threshold else 0
        if pred == 1 and label == 1: tp += 1
        elif pred == 1 and label == 0: fp += 1
        elif pred == 0 and label == 1: fn += 1
        else: tn += 1
    accuracy = (tp + tn) / (tp + fp + fn + tn)
    precision = tp / (tp + fp) if (tp + fp) > 0 else float('nan')
    recall = tp / (tp + fn) if (tp + fn) > 0 else float('nan')
    f1 = 2 * precision * recall / (precision + recall) if (precision + recall) > 0 else 0.0
    return tp, fp, fn, tn, accuracy, precision, recall, f1

def mean_calibration_gap(weighted_probs, true_base_rate):
    return sum(weighted_probs) / len(weighted_probs) - true_base_rate

RAW_ROWS = [(0.55,1),(0.35,1),(0.25,0),(0.20,0),(0.15,0),
            (0.12,0),(0.10,0),(0.08,0),(0.05,0),(0.03,0)]

# r=1.0 -- identity, reproduces the raw model exactly
w1 = [(p_weighted(p, 1.0), label) for p, label in RAW_ROWS]
assert confusion_and_metrics(w1)[:4] == (1, 0, 1, 8)

# r=4.0 -- this concept's own worked-example ratio
w4 = [(p_weighted(p, 4.0), label) for p, label in RAW_ROWS]
assert confusion_and_metrics(w4)[:4] == (2, 2, 0, 6)

gap4 = mean_calibration_gap([p for p, _ in w4], 0.20)
assert round(gap4, 4) == 0.2201

RECALL

Knowledge check

Why does calibration break under resampling or weighting but not under threshold-moving?
Resampling and weighting change training-time class balance, which shifts every prediction's confidence; threshold-moving and cost-sensitive learning only move the decision rule on already-fixed probabilities -- nothing about the probabilities themselves changes.
Why do precision, recall, and F1 stay trustworthy after any of Concepts 02-05's fixes?
They're direct counts off the real confusion matrix at a given operating point, not estimates of a probability -- whatever they read, they read honestly.
Why is the main worked example's exact 66.67% F1 tie not a coincidence?
F1(p,r)=2pr/(p+r) is symmetric in its two arguments -- raw's (precision,recall)=(100%,50%) is exactly weighted's (recall,precision) with the two swapped, so F1 lands on the same number both times by construction.

CAREER PRACTICE

Interview questions

Conceptual: why do training-time and decision-time fixes differ in calibration risk?
Training-time fixes (resampling, weighting) change what the model was trained to output, shifting every prediction's confidence; decision-time fixes (threshold-moving, cost-sensitive learning) only change which already-fixed probability gets acted on.
Mathematical: derive the odds-rescaling identity.
Assume class weighting scales the odds by r: odds_weighted = r·p_raw/(1−p_raw). Solving p_weighted/(1−p_weighted) = r·p_raw/(1−p_raw) for p_weighted gives p_weighted=(r·p_raw)/(r·p_raw+1−p_raw), equivalently a shift of ln(r) on the logit scale.
Coding: implement p_weighted and confusion_and_metrics.
Section 12 gives the full implementation, reproducing this concept's own r=1.0 and r=4.0 numbers via assert statements.
Debugging: a resampled model's accuracy hasn't moved. What do you check first?
Calibration -- a stable accuracy number can hide a large shift in the average predicted probability, exactly like the exercise's 87.5%=87.5% result.
System design: how do you decide whether Module 16 recalibration is needed after a fix?
Check which fix was logged alongside the model version -- resampling or weighting require a calibration re-check; threshold-moving or cost-sensitive learning don't, since neither retrains anything.
