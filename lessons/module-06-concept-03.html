01 · CONCEPT FIRST

Same loss, plus a leash on coefficient size

OLS (Concept 02)

Minimize SSE alone. No limit on how large a coefficient can get, no penalty for a sign that doesn't make intuitive sense.

RIDGE / LASSO (this concept)

Minimize SSE + λ×penalty. Coefficients are kept on a leash -- ridge's leash never lets go all the way to zero, lasso's sometimes does.

First memory: ridge penalizes Σb² (L2), lasso penalizes Σ|b| (L1) -- both shrink coefficients toward zero as λ grows, only lasso can land exactly on it.
02 · WHY IT EXISTS

Exact minimum and well-behaved are different claims

Concept 02 proved OLS is the exact SSE minimum, on this dataset's own six rows. That proof says nothing about what happens as more features enter, especially features that are correlated with each other. Module 01 named this territory already: Concept 04's overfitting and Concept 05's bias-variance tradeoff both describe a model chasing every last bit of training SSE at the cost of stability -- an unconstrained fit with correlated inputs is exactly the high-variance end of that tradeoff, and it shows up first and most visibly right here, in the coefficients themselves.

04 · TECHNICAL MECHANISM

Add a penalty term to the same loss

Ridge and lasso both start from OLS's own loss, SSE, and add a penalty on coefficient size:

Ridge: Loss = SSE + λ·Σb_j² (L2)
Lasso: Loss = SSE + λ·Σ|b_j| (L1)

λ=0 is plain OLS. As λ grows, both penalties push coefficients toward zero. The difference is shape: L2's penalty is a smooth bowl with no flat edges, so the pull toward zero gets weaker and weaker as a coefficient approaches zero -- it shrinks forever without landing exactly there. L1's penalty has a sharp corner right at zero, and that corner is what lets a coefficient stop dead on zero once the penalty outweighs what little that feature is still contributing.

06 · IMPORTANT DISTINCTIONS

Shrinks vs. shrinks-and-can-zero

PairingThe real difference
Ridge vs. lassoRidge (L2) shrinks every coefficient toward zero but structurally never reaches it; lasso (L1) shrinks AND can drive a coefficient to exactly zero, dropping that feature entirely

07 · COMMON MISTAKES

What beginners often assume, and shouldn't

"Penalize the intercept too."

Don't -- only the slope-type coefficients (b1, b2, ...) are penalized. The intercept just centers the fit and carries no "size" that needs restraining.

"Regularize on the raw, unstandardized scale."

An unstandardized penalty punishes large-scale features unfairly -- exactly the convention Module 04 Concept 04 already established (sample std, ddof=1) must be applied first.

"Ridge can also zero out a feature if λ is big enough."

No -- ridge's penalty has no corner at zero, so its coefficients shrink toward zero but never structurally reach it, at any λ.

04
INTUITION

A leash, and a room with corners

OLS lets coefficients run free. Ridge puts them on a leash -- however far they'd like to run, the leash pulls back proportionally, but it never quite reaches all the way to zero. Lasso puts them in a room with sharp corners, and every so often, the sharp corner is exactly where the leash actually stops -- at zero, dropping the feature outright.

Analogy boundaryThe leash-and-room picture explains WHAT each penalty does to a coefficient's size. It doesn't by itself prove WHY corners specifically cause zeros -- that's the geometry made precise in Sections 07 and 14, and the subgradient condition derived in Section 09.

06
MECHANISM

Two lanes: a closed form, and an iterative rule

RIDGE LANE -- CLOSED FORM

Differentiate SSE+λΣb_j² with respect to each b_j, set both to zero. The λ term adds λ·b_j to each derivative, which folds directly into the normal equations as (Z_jj+λ)b_j+... -- a 2x2 (or larger) linear system, solved exactly, same spirit as Concept 02's own solve.

LASSO LANE -- COORDINATE DESCENT

SSE+λΣ|b_j| isn't differentiable at b_j=0, so there's no single closed form. Instead: fix all coefficients but one, compute that coordinate's partial-residual dot product ρ_j, apply the soft-threshold operator, update, move to the next coordinate, repeat until it stops changing.

09
MATHEMATICS

Both penalty forms, in full

L_ridge = SSE + λ·Σb_j² ; closed form: b = (Z'Z + λI)⁻¹ Z'y
L_lasso = SSE + λ·Σ|b_j| ; soft threshold: b_j ← sign(ρ_j)·max(|ρ_j| − λ/2, 0) / Z_jj

Z'Z and Z'y are the standardized-feature sums (the same role Σx² and Σxy played in Concept 02's normal equations, now for two standardized features instead of one raw one). ρ_j is the partial-residual dot product for coordinate j -- what's left of feature j's correlation with the target once the OTHER coefficient's contribution is subtracted out. The 2 in the /2 comes directly from this lesson's own loss convention, SSE+λΣ|b_j| -- Section 13 flags that scikit-learn's real objective differs by a scale factor, so this exact soft-threshold constant does not carry over unchanged to sklearn's alpha.

12
CODE

The 2x2 ridge solve and the lasso coordinate-descent loop

PYTHON · NO LIBRARIES 
# Standardized-space sums, already verified in the worked example.
Z11 = 5.0
Z22 = 5.0
Z12 = 4.877541
Z1y = 26.726124
Z2y = 25.581319

def ridge_solve(lam):
    a11 = Z11 + lam
    a22 = Z22 + lam
    det = a11 * a22 - Z12 * Z12
    b1 = (Z1y * a22 - Z2y * Z12) / det
    b2 = (Z2y * a11 - Z1y * Z12) / det
    return b1, b2

def lasso_solve(lam, iters=3000):
    b1, b2 = 0.0, 0.0
    for _ in range(iters):
        rho1 = Z1y - Z12 * b2
        b1 = (1 if rho1 > 0 else -1 if rho1 < 0 else 0) * max(abs(rho1) - lam / 2, 0) / Z11
        rho2 = Z2y - Z12 * b1
        b2 = (1 if rho2 > 0 else -1 if rho2 < 0 else 0) * max(abs(rho2) - lam / 2, 0) / Z22
    return b1, b2

b1r0, b2r0 = ridge_solve(0)
assert round(b1r0, 4) == 7.3220 and round(b2r0, 4) == -2.0264

b1l1, b2l1 = lasso_solve(1)
assert round(b1l1, 4) == 5.2452 and round(b2l1, 4) == 0.0

# KKT check: b2 stays at zero under lasso, at lambda=1, iff |rho2| <= lambda/2.
rho2_at_b1l1 = Z2y - Z12 * b1l1
assert abs(rho2_at_b1l1) <= 0.5 + 1e-6

# The b2=0 sparsity threshold, located by bisection on this same rule.
lo, hi = 0.0, 2.0
for _ in range(60):
    mid = (lo + hi) / 2
    _, b2mid = lasso_solve(mid)
    if abs(b2mid) < 1e-9:
        hi = mid
    else:
        lo = mid
assert round(hi, 4) == 0.4963

ECOSYSTEM

scikit-learn's Ridge and Lasso -- and a scale-factor caveat

sklearn.linear_model.Ridge and sklearn.linear_model.Lasso confirm the same shrinkage direction this lesson derives by hand -- and Lasso's real solver is coordinate descent, matching Section 12's from-scratch loop exactly. The caveat: sklearn's actual objective is (1/(2n))·SSE+alpha·penalty, not this lesson's SSE+λ·penalty. Plugging this lesson's λ values directly into sklearn's alpha parameter will NOT reproduce identical numbers -- the two conventions differ by a scale factor tied to n, and that mismatch is flagged here rather than glossed over.

DIAGNOSIS

Where regularization itself goes wrong

λ TOO LARGE

Underfitting by penalty

Push λ far enough and every coefficient collapses toward (ridge) or onto (lasso) zero -- the model stops fitting the data at all, trading instability for a different failure.

λ TOO SMALL

Back to Concept 02's own instability

Too small a λ barely shrinks anything -- the sign flip and the inflated b1 from Step 1 of the worked example are still effectively present.

LASSO'S ARBITRARY TIE-BREAKING

Among near-equally-correlated features

This concept's own x1/x2 pair (r=0.9755) is close to equally informative about y -- lasso's coordinate descent happened to zero b2 and keep b1, but with two features this close in correlation, which one survives can be somewhat arbitrary. Ridge treats correlated features more symmetrically, shrinking both together instead of picking one.

REALITY

Production implications

  • Always standardize before penalizing -- an unstandardized penalty distorts which features get shrunk based on scale, not signal.
  • λ is chosen via cross-validation in real pipelines, not guessed -- named forward to Module 14/15.

PORTABLE MEMORY

Concept card

Both penalties, and the operators that solve them

  • Ridge: SSE+λΣb_j², closed form b=(Z'Z+λI)⁻¹Z'y -- shrinks, never exactly zero
  • Lasso: SSE+λΣ|b_j|, soft threshold b_j←sign(ρ_j)max(|ρ_j|-λ/2,0)/Z_jj -- shrinks, CAN reach exactly zero
  • The one-line distinction: L1's corner at zero is reachable by the soft-threshold update; L2's smooth bowl never lets a coefficient land exactly there

Memorable example

Adding recent_complaint_count to Concept 02's dataset flips b2 from -0.9483 (raw OLS) to exactly 0.0000 (lasso, λ≈0.4963 and beyond) -- while ridge only ever shrinks it, reaching 1.1482 at λ=12, never zero.

23
CAREER PRACTICE

Interview questions

Conceptual: why does the L1 diamond's corner cause sparsity geometrically, while the L2 circle's smooth boundary doesn't?
The constrained-form equivalent of both penalties draws a boundary of fixed "budget" size -- a diamond for L1, a circle for L2 -- and the solution sits where the SSE contours are tangent to that boundary. A diamond has corners sitting exactly on the coordinate axes, so tangency can land ON a corner, which forces the coefficient for the other axis to exactly zero. A circle has no corners anywhere, so tangency almost never lands exactly on an axis, and coefficients only ever approach zero.
Mathematical: derive the ridge closed form / the soft-threshold operator from the subgradient condition.
Ridge: differentiate SSE+λΣb_j² w.r.t. each b_j, set to zero -- the λb_j term adds directly onto the normal equations' diagonal, giving (Z'Z+λI)b=Z'y. Lasso: SSE+λΣ|b_j| is non-differentiable at b_j=0, so use the subgradient of |b_j| (any value in [-1,1] at zero); setting the subgradient of the full objective to zero and solving for b_j yields b_j=sign(ρ_j)max(|ρ_j|-λ/2,0)/Z_jj, where ρ_j is the partial-residual dot product.
Coding: implement coordinate-descent lasso from scratch.
Section 12 gives the full implementation -- alternate updating b1 and b2 via the soft-threshold rule using the other's current value, for enough iterations to converge (200 live in the lab, up to a few thousand for a tighter guarantee), with asserts reproducing this concept's own verified numbers and the λ≈0.4963 threshold.
System design: ridge vs. lasso vs. elastic net for a real feature pipeline.
Ridge when most features carry some real signal and you want to keep them all, just restrained (e.g. correlated but individually meaningful features). Lasso when you want automatic feature selection, especially with many candidate columns and a suspicion that most contribute little. Elastic net (named forward only, not built in this course) blends both when neither pure choice feels right -- a real production option, out of scope here.
Production scenario: Company's 340 one-hot columns -- which penalty helps and why?
Module 03 Concept 08 and Module 04 Concept 02 already flagged Company as one-hot-encoded into K=340 columns, many likely correlated or redundant. Lasso is the natural first choice -- its sparsity can prune the pipeline down to the columns that actually carry signal, reducing both overfitting risk and the deployed feature count. Ridge would keep all 340, just shrunk, which is safer if you're unsure which ones matter but doesn't reduce the pipeline's footprint.
