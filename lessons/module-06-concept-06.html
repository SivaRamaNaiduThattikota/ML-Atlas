MODULE 06 · CONCEPT 06

z=0 already had a shape too.
It's a line.

Concept 04 squashed z through sigma(z) to read it as a probability. Concept 05 renamed z itself as the log-odds. This concept rereads the exact same z a third way -- geometrically. sigma(z)=0.5 happens exactly at z=0 (proven in Concept 04), so the set of points where p=0.5 is exactly the set where z=0 -- and for z=w0+w1x1+w2x2, that set is a straight line. Solving -4+1.5x1-0.5x2=0 for x2 gives x2=3x1-8: the boundary separating "predict relief" from "predict no relief," using the exact same fitted weights, no refit, no new mechanism.

PROGRESSIVE BEGINNER CORE

The same z, reread as a line

Concept 05 asked "what does z already mean, on the odds scale?" This concept asks a geometric version of the same question: "where, exactly, does the model switch its prediction?" The answer is a line -- and reading a point's side of that line is the entire prediction, with no probability computed at all.

01 · CONCEPT FIRST

sigma(z)=0.5 exactly at z=0 -- and z=0 is a line

LOG-ODDS (Concept 05)

z itself already had a name before any squashing: it's the log-odds. That reading is about magnitude -- how far z is from 0, and in which direction.

GEOMETRY (this concept)

Set z=0 and it stops being a number and becomes a shape: every (x1,x2) pair that makes w0+w1x1+w2x2 equal exactly 0 traces out a straight line. Every point off that line is on one side or the other -- that side IS the prediction.

First memory: p=0.5 <=> z=0 <=> a line. Not three separate facts -- one identity, read three different ways across Concepts 04, 05 and this one.
02 · WHY IT EXISTS

A stakeholder can see a line. They can't see "p=0.5"

Concept 05 gave a CFPB analyst a sentence about odds ratios. This concept gives them something more immediate: a picture. "p=0.5" is not a shape anyone can point to, but a line on a plot of prior_contact_attempts versus satisfaction_score is instantly legible -- draw it once, and every future case's prediction is just "which side of the line is it on." That's the entire reason this concept exists: not a new model, just the geometric shape the existing model's own decision rule already had.

04 · TECHNICAL MECHANISM

Set z=0, solve for x2, get a line

Start from z=w0+w1x1+w2x2 and set it to 0: -4+1.5x1-0.5x2=0. Rearranging to isolate x2 gives 1.5x1-0.5x2=4, and dividing through by -0.5 gives the explicit line:

x2 = 3x1 - 8 (slope = -w1/w2 = 3, intercept = -w0/w2 = -8)

Every point below that line has z>0 (predict class 1); every point above it has z<0 (predict class 0). Checked against every one of Rows A-E: four match their actual label, one -- Row C -- does not.

06 · IMPORTANT DISTINCTIONS

Side-of-line versus distance-from-line

PairingThe real difference
Side of the line (categorical)Which region a point falls in -- z>=0 or z<0. This alone is the entire prediction; nothing else is needed to classify a row.
Distance from the line (continuous)A separate, secondary number, z/||w||, described in Section 09 and named forward only to SVM margins (Module 07 Concept 06). It is real and computable today, but it is not built into a "margin" concept here.
07 · COMMON MISTAKES

What beginners often assume, and shouldn't

"The boundary passes exactly between the closest points of the two classes."

False. The line's position is fixed entirely by w0, w1 and w2 -- it was fit elsewhere, on real data. Checked against these six specific rows, it is not adjusted to minimize their spacing in any way.

"Distance from the line is a confidence percentage."

False. Distance (Section 09's z/||w||) is a real number in feature units, not a probability. Turning a number into a calibrated probability is exactly what the sigmoid already does, in Concept 04 -- this concept never recomputes that step.

04
INTUITION

A property line on a map

Think of z=0 as a fence running through a field. Which side of the fence a point sits on is the entire prediction -- it doesn't matter whether the point is one foot from the fence or one hundred. Distance from the fence is a separate, secondary fact (Section 09), not the thing being predicted.

Analogy boundaryThe fence picture explains WHAT the boundary means geometrically. It doesn't explain WHY logistic regression's own fence always comes out straight -- that's Section 09's algebra, not a property of fences in general.

09
MATHEMATICS

Deriving the line, and the signed-distance formula

w0 + w1·x1 + w2·x2 = 0
w2·x2 = -w0 - w1·x1
x2 = -(w0/w2) - (w1/w2)·x1

For this model, w0=-4, w1=1.5, w2=-0.5: slope = -w1/w2 = -1.5/-0.5 = 3, intercept = -w0/w2 = -(-4)/-0.5 = -8. So x2 = 3x1 - 8. In n dimensions, the same equation w0+w1x1+...+wnxn=0 defines a hyperplane rather than a line -- the derivation doesn't change, only the number of terms.

The signed perpendicular distance from any point to this hyperplane is z/||w||, where ||w||=sqrt(w1^2+w2^2):

||w|| = sqrt(1.5^2 + (-0.5)^2) = sqrt(2.25 + 0.25) = sqrt(2.5) = 1.581139

For Row C (z=-1.0): distance = -1.0/1.581139 = -0.632456. Independently confirmed via Row C's perpendicular foot on the line, (3.6, 2.8) -- which satisfies 1.5(3.6)-0.5(2.8)-4=0 exactly -- and the plain Euclidean distance from (3,3) to that foot: sqrt((3-3.6)^2+(3-2.8)^2)=sqrt(0.36+0.04)=sqrt(0.40)=0.632456, matching z/||w|| to full float precision. Sign convention: the "below/predict-1" side is positive, "above/predict-0" is negative. This quantity is explicitly bounded from SVM's margin (Module 07 Concept 06, named forward only) -- it is a real distance, not yet a "margin" in the sense that term will later take on.

11
CONCRETE USE

A clean case, a boundary case, and a mistake

CLEAN CASE

Row A -- far below and correctly classified

z=-4.5, distance -2.846049 -- far above the line on the predict-0 side, and its actual label (0) agrees.

BOUNDARY CASE

A hypothetical point exactly on the line

Not one of the six named rows -- any (x1, 3x1-8) pair has z=0 exactly, and the classifier is indifferent: sigma(0)=0.5, neither class favored.

MISTAKE TO AVOID

"Far from the boundary" is not "more likely correct"

Row E is far from the line (distance 2.846049) and correct. But distance alone never proves correctness -- Row C's distance (-0.632456) is smaller in magnitude, yet the real test is the actual label, not how far a point sits from the line.

CODE

Side-of-line classification, and the line's own equation

PYTHON · EXTENDS CONCEPT 04'S OWN z_of() 
import math

W0, W1, W2 = -4.0, 1.5, -0.5

def z_of(x1, x2):
    return W0 + W1 * x1 + W2 * x2

def decision_boundary_side(x1, x2, w0=W0, w1=W1, w2=W2):
    """Returns 1 if (x1, x2) is on the predict-1 side of the boundary,
    else 0 -- computed from the sign of z alone, no probability involved."""
    z = w0 + w1 * x1 + w2 * x2
    return 1 if z >= 0 else 0

def boundary_slope_intercept(w0=W0, w1=W1, w2=W2):
    return -w1 / w2, -w0 / w2  # slope, intercept

rows = [
    ("A", 1, 4, 0), ("B", 2, 3, 0), ("C", 3, 3, 1),
    ("D", 4, 2, 1), ("E", 6, 1, 1),
]

correct = 0
for label, x1, x2, y in rows:
    predicted = decision_boundary_side(x1, x2)
    if predicted == y:
        correct += 1

assert correct == 4  # the 4/5 tally, A/B/D/E correct, C missed
slope, intercept = boundary_slope_intercept()
assert abs(slope - 3.0) < 1e-9 and abs(intercept - (-8.0)) < 1e-9

# Signed distance to the boundary, z/||w||.
norm_w = math.sqrt(W1 ** 2 + W2 ** 2)
dist_c = z_of(3, 3) / norm_w
assert abs(dist_c - (-0.632456)) < 1e-5

DIAGNOSIS

What a poorly-separated dataset does to the boundary

IMBALANCED OR POORLY-SEPARATED DATA

A line that can't do much

When classes overlap heavily or one is rare, a single straight boundary may separate them poorly no matter where it's drawn -- Module 05's imbalance concepts, cited, not retaught here.

THE w2=0 DEGENERATE CASE

A boundary parallel to the x2-axis

If w2 were exactly 0, the boundary equation can't be solved for x2 at all -- it becomes a vertical line, x1=-w0/w1. A real, valid edge case, deliberately excluded from this lab's w2 slider range so the equation stays single-valued in x2.

REALITY

Production implications

  • Visualizing a 2-feature model's decision boundary is a genuinely useful stakeholder-review artifact -- it turns an abstract weight vector into a picture a reviewer can sanity-check directly against known cases.
  • Beyond 2-3 features, the boundary itself can't be drawn directly -- it's still a hyperplane, but a human can no longer see it. Named only; the workaround (dimensionality reduction for visualization) is its own later module.
  • Report the boundary's known misses (like Row C here) alongside the boundary itself, not just the line -- a picture with no error cases shown overstates how clean the separation actually is.

CAREER PRACTICE

Interview questions

Conceptual: why is logistic regression's decision boundary always linear in the raw features?
Because z itself is a linear combination of the raw features (z=w0+w1x1+...+wnxn), and the boundary is defined by the single equation z=0 -- a linear equation, which always describes a hyperplane. Getting a curved boundary out of this model would require nonlinear features (e.g. x1^2) fed into the same linear z, not a change to the boundary rule itself.
Mathematical: derive the boundary line from z=0.
w0+w1x1+w2x2=0 → w2x2=-w0-w1x1 → x2=-(w0/w2)-(w1/w2)x1, an explicit line with slope -(w1/w2) and intercept -(w0/w2), valid whenever w2 != 0.
Coding: implement the side-of-line test without computing a probability.
Section 12's decision_boundary_side(x1, x2, w0, w1, w2) computes z=w0+w1*x1+w2*x2 directly and returns 1 if z>=0 else 0 -- no sigmoid call anywhere in the function.
System design: how would you visualize a 2-feature model's decision boundary for a non-technical stakeholder?
Plot the two features on x/y axes, shade the two predicted-class regions using the model's own z (as this lesson's lab does), draw the boundary line explicitly, and plot known cases -- including known misses like Row C -- on top so the review isn't just the idealized line but also its actual error cases.
