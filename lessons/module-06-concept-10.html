A straight line is enough.
Until it structurally isn't.

Concepts 01-09 spent the whole module building the linear/logistic/LDA/softmax family's own mechanics, never once asking whether that family was the right tool for the data in front of it. 03 · CONCRETE EXAMPLE

Two toy datasets, one shared line

Dataset A (near-linear): six points using the module's own feature names, x1=prior_contact_attempts and x2=case_age_days -- class 0 near (1,1), (2,1), (1,2); class 1 near (4,4), (5,4), (4,5). Fresh numbers, sharing nothing with Concepts 04-09's own weights or test points.

Dataset B (the classic XOR pattern): four points, framed as a toy illustrative label -- two binary intake flags where "escalate" is true only when exactly one flag is set: (0,0)→0, (1,1)→0, (0,1)→1, (1,0)→1. This is the standard abstract counterexample given a concrete frame -- not a claim about real CFPB data, unlike Concept 08's own company_response field, which was confirmed live against the production CFPB API.

04 · TECHNICAL MECHANISM

One straight line, tested against both datasets

The same boundary, z=w0+w1x1+w2x2, predicts class 1 when z≥0 and class 0 otherwise -- exactly the notation Concepts 04-09 already used. Run it against Dataset A with w0=-5, w1=1, w2=1 (the line x1+x2=5): every point lands on its correct side, 6/6=100%. Run the SAME line against Dataset B: only 2 of the 4 points end up correct, because the line was never built for this shape of data. No line at all reaches better than 3/4=75% on Dataset B -- a structural ceiling, not a tuning failure (Section 09-10 in the advanced lesson).

07 · COMMON MISTAKES

What beginners often assume, and shouldn't

"If training accuracy isn't 100%, the classes must be structurally non-separable."

False. Real data is usually just noisy or overlapping -- a different situation from XOR's hard, structural 75% ceiling that no amount of extra data or tuning removes.

"A more flexible model is always the safer choice."

False. It ignores the interpretability and data-efficiency cost of flexibility, covered in Section 05's citations -- a regulated decision may need an explainable coefficient more than it needs a marginally higher score.

04
INTUITION

A straight ruler vs. a flexible tape measure

A straight ruler measures a straight edge perfectly, no matter how you rotate it along that edge. Held against a curve, no rotation of the same ruler helps -- the tool itself is the wrong shape for the job, not badly used. A linear decision boundary is the same kind of tool: structurally sufficient for some datasets, structurally the wrong shape for others, regardless of how its weights are tuned.

Analogy boundaryThe ruler analogy explains the STRUCTURAL point correctly. It does not mean a linear model is "worse" in general -- Section 15's own trade-offs (interpretability, data efficiency, training speed) are real advantages a flexible model gives up, not just a fallback.

MECHANISM

Two checks, neither one a guarantee

CHECK 1 -- STRUCTURAL SEPARABILITY

Is the classification problem structurally linearly separable, or close to it? Dataset A: yes. Dataset B: no, by construction -- no line reaches above 75%.

CHECK 2 -- DATA SIZE / INTERPRETABILITY

09
MATHEMATICS

The bias-variance statement and the convex-hull criterion

The bias-variance tradeoff, quoted directly in Section 05: more tunable parameters lower bias (better training fit) but raise variance (worse generalization, especially with less data or more noise). A linear model in 2D has exactly 3 free parameters, w0, w1, w2 -- few enough that it is comparatively hard to overfit a small dataset with, which is precisely why Check 2 in Section 06 favors it when N is small.

Formal linear separability follows a convex-hull criterion: two finite point sets are linearly separable if and only if their convex hulls do not intersect. For Dataset A, the convex hulls of the two clusters (roughly the triangles spanning (1,1)-(2,1)-(1,2) and (4,4)-(5,4)-(4,5)) are far apart and do not intersect -- consistent with the 6/6 result. For Dataset B, class 0's convex hull is the line segment from (0,0) to (1,1); class 1's convex hull is the line segment from (0,1) to (1,0). Those two segments are the two diagonals of the unit square, and they cross at exactly (0.5, 0.5) -- so by the criterion, no single line can separate them. This is named as the reason, not re-derived here as a full formal proof.

Convex hull of class 0 = segment[(0,0), (1,1)]
Convex hull of class 1 = segment[(0,1), (1,0)]
The two segments intersect at (0.5, 0.5) → not linearly separable
10
WORKED EXAMPLE

6/6 on Dataset A, capped at 3/4 on Dataset B

Dataset A. class 0 = {(1,1), (2,1), (1,2)}; class 1 = {(4,4), (5,4), (4,5)}. Boundary z=-5+x1+x2 (the line x1+x2=5): class 0 gives z=(-3,-2,-2) -- all negative, correctly class 0; class 1 gives z=(3,4,4) -- all positive, correctly class 1. 6/6=100% with one straight line.

Verification, way 1 (direct sign-check). Every one of the 6 points checked directly against z=-5+x1+x2, exactly as shown above.

Verification, way 2 (independent second line). The two class centroids are (1.333, 1.333) and (4.333, 4.333). The perpendicular bisector of the segment joining them is 3x1+3x2-17=0, i.e. x1+x2=17/3≈5.667 -- a DIFFERENT line, derived a completely different way. It also scores 6/6=100%, confirming the separability is real, not an artifact of one lucky line.

Dataset B (the classic XOR pattern). (x1,x2,y) = (0,0,0), (1,1,0), (0,1,1), (1,0,1). No single straight line separates class 0 {(0,0),(1,1)} from class 1 {(0,1),(1,0)} -- the two diagonal pairs of a unit square.

Verification, way 1 (deterministic grid search). A grid over boundary weights w0, w1, w2, each ranging -3 to 3 in steps of 0.25 -- 15,625 combinations -- scoring accuracy = sign(w0+w1x1+w2x2) against each of the 4 points. Maximum accuracy found across ALL 15,625 lines: exactly 0.75 (3/4), never 1.0.

Verification, way 2 (random search). 200,000 uniformly-random lines, w0, w1, w2 each in [-4,4]. Maximum accuracy found: also exactly 0.75.

A (near-linear)6/6 = 100%Direct check + independent centroid-bisector line, both 6/6

All four checks agree with the numbers reported here -- the same "two independent methods per fact" standard this module has used since Concept 04's own worked examples.

CODE

Reproducing both ceilings directly

PYTHON · DATASET A CHECK + DATASET B GRID/RANDOM SEARCH 
import random

DATASET_A = [(1, 1, 0), (2, 1, 0), (1, 2, 0), (4, 4, 1), (5, 4, 1), (4, 5, 1)]
DATASET_B = [(0, 0, 0), (1, 1, 0), (0, 1, 1), (1, 0, 1)]

def accuracy(points, w0, w1, w2):
    correct = 0
    for x1, x2, y in points:
        z = w0 + w1 * x1 + w2 * x2
        predicted = 1 if z >= 0 else 0
        correct += (predicted == y)
    return correct / len(points)

# Dataset A: the worked example's own line, one straight check.
assert accuracy(DATASET_A, -5, 1, 1) == 1.0

# Dataset B: deterministic grid search over 15,625 combinations.
best_grid = 0.0
w = [-3 + 0.25 * i for i in range(25)]
for w0 in w:
    for w1 in w:
        for w2 in w:
            best_grid = max(best_grid, accuracy(DATASET_B, w0, w1, w2))
assert best_grid == 0.75  # never 1.0, no matter which line

# Dataset B: 200,000 random lines, independent method, same ceiling.
random.seed(0)
best_random = 0.0
for _ in range(200_000):
    w0, w1, w2 = (random.uniform(-4, 4) for _ in range(3))
    best_random = max(best_random, accuracy(DATASET_B, w0, w1, w2))
assert best_random == 0.75

DIAGNOSIS

Where "choose linear" actually fails

STRUCTURAL NON-SEPARABILITY

No amount of tuning fixes a family-level mismatch

Dataset B's 75% ceiling holds across 15,625 grid combinations and 200,000 random lines -- more data, more regularization, or more careful weight-tuning cannot raise it, because the limitation is in the FAMILY, not the fit.

MISREADING NOISE AS STRUCTURE

Confusing "not separable yet" with "cannot be separable"

Real, noisy data that fails to hit 100% training accuracy is a different situation from Dataset B's hard ceiling -- Section 17 corrects this directly.

REALITY

Production implications

  • CFPB-style regulated decisions often carry real compliance value for an explainable coefficient table, per Molnar's own interpretability citation (Section 05) -- a reason to keep a linear baseline even when a flexible model scores marginally higher.
  • Small labeled datasets in early-stage products may genuinely favor a linear model's lower variance over a flexible model's higher variance, per the bias-variance citation (Section 05) -- flexibility is not free.

RECALL

Knowledge check

Why does Dataset A reach 100% with one line while Dataset B caps at 75% with any line?
Dataset A's two classes occupy well-separated regions whose convex hulls do not intersect, so a separating line exists (confirmed two ways: the main line and an independently-derived centroid bisector, both 6/6). Dataset B's two classes are the two diagonals of a unit square; their convex hulls -- the diagonal segments themselves -- cross at (0.5, 0.5), so by the convex-hull criterion no line can separate them, and no search (15,625-combination grid, 200,000-line random) ever finds one above 75%.
Why is "not 100% training accuracy" not the same claim as "structurally non-separable"?
Ordinary noise or class overlap can keep real data below 100% without any hard ceiling -- more data or a better-tuned line could still improve things. Dataset B's 75% ceiling is a stronger, different claim: no line, however tuned, and no amount of extra data of this exact shape, can ever do better, confirmed by exhaustive-style search.
Why is this concept's question different from Concept 11's, even though both are about linear models?
This concept asks whether the whole linear/logistic/LDA/softmax family belongs in the running at all for a given dataset -- a decision made BEFORE choosing and fitting a model. Concept 11 asks whether an ALREADY-chosen linear model's own assumptions (linearity, homoscedasticity, independence) are holding up against real data -- a decision made AFTER.

Solution and teach-back

Open the worked solution
Part 1: ignoring the ambiguous point, {(1,2),(2,1)} and {(3,4),(4,3)} sit in clearly separated diagonal bands (e.g. the line x1+x2=5 again puts both class-0 points below and both class-1 points above), so this near-diagonal dataset is structurally separable in the same sense as Dataset A -- the single ambiguous point (2.5,2.5) sits exactly on that boundary, a labeling call rather than a structural break. CAREER PRACTICE

Interview questions

Conceptual: what two questions would you ask before choosing a linear model for a new classification problem?
Is the problem structurally linearly separable, or close to it? And does the situation -- small N, high noise, or a need for an explainable coefficient -- favor a simpler model's higher bias / lower variance over a flexible model's higher variance? Both favor a linear model; neither guarantees it's the right choice.
Mathematical: state the convex-hull criterion for linear separability and apply it to XOR.
Two finite point sets are linearly separable iff their convex hulls do not intersect. For XOR, class 0's hull is the segment from (0,0) to (1,1) and class 1's hull is the segment from (0,1) to (1,0) -- the two diagonals of the unit square, which cross at (0.5,0.5). Since the hulls intersect, no line separates the classes.
Coding: how would you empirically confirm a dataset's linear-separability ceiling without a formal proof?
Run an exhaustive-style search over candidate boundary weights -- a fine deterministic grid and, independently, a large random search -- and take the maximum accuracy found across both. If two independently-coded searches agree on the same ceiling well below 100%, as with XOR's 0.75, that is strong empirical evidence of a structural limit, not a search failure.
System design: a stakeholder wants the "best" model regardless of type. How do you factor in this concept's own checks?
Run both checks first: test structural separability empirically (a quick search, as above) and weigh data size/interpretability needs against the marginal accuracy a flexible model might add. If the problem is structurally linear-solvable and the situation favors interpretability or small data, a linear baseline can be the right production choice even if it isn't the mathematically highest-scoring option on paper.
