Fit already done, predict, interpret, check

CODE

The full sequence, reproduced directly

PYTHON · PREDICT, INTERPRET, CHECK -- ALL THREE FORMULAS REUSED UNCHANGED 
import math

W0, W1, W2, W3 = -2.0, 0.8, -0.02, 1.2
ROWS = [
    ("A", 1, 10, 1, 0), ("B", 2, 20, 1, 0), ("C", 3, 15, 0, 1), ("D", 1, 40, 1, 0),
    ("E", 4, 25, 0, 1), ("F", 2, 60, 0, 0), ("G", 5, 30, 1, 1), ("H", 3, 50, 0, 0),
]

def sigmoid(z):
    return 1 / (1 + math.exp(-z)) if z >= 0 else math.exp(z) / (1 + math.exp(z))

def bce(p, y):
    return -(y * math.log(p) + (1 - y) * math.log(1 - p))

total_loss = 0.0
misses = []
for name, x1, x2, x3, y in ROWS:
    z = W0 + W1 * x1 + W2 * x2 + W3 * x3
    p = sigmoid(z)
    pred = 1 if p >= 0.5 else 0
    total_loss += bce(p, y)
    if pred != y:
        misses.append(name)

assert round(total_loss / len(ROWS), 4) == 0.4529
assert misses == ["B"]

# Odds-ratio identity, verified via a paired comparison (Concept 05's own method).
def odds(x1, x2, x3):
    z = W0 + W1 * x1 + W2 * x2 + W3 * x3
    p = sigmoid(z)
    return p / (1 - p)

ratio_x1 = odds(3, 30, 0) / odds(2, 30, 0)
assert abs(ratio_x1 - math.exp(W1)) < 1e-9

# VIF check between x2 and x3 (Concept 11's own formula).
x2s = [r[2] for r in ROWS]
x3s = [r[3] for r in ROWS]
def pearson(xs, ys):
    n = len(xs)
    mx, my = sum(xs) / n, sum(ys) / n
    num = sum((x - mx) * (y - my) for x, y in zip(xs, ys))
    dx = sum((x - mx) ** 2 for x in xs)
    dy = sum((y - my) ** 2 for y in ys)
    return num / math.sqrt(dx * dy)

r = pearson(x2s, x3s)
vif = 1 / (1 - r ** 2)
assert round(vif, 2) == 1.17

Solution and teach-back

Open the worked solution
z = -2.0 + 0.8(6) - 0.02(5) + 1.2(1) = -2.0 + 4.8 - 0.1 + 1.2 = 3.9. p = sigma(3.9) ≈ 0.980199 -- predicted class 1 (relief), high confidence. Odds = p/(1-p) ≈ 49.402. CAREER PRACTICE

Interview questions

Conceptual: why run predict, interpret, and check together instead of in isolation?
A real deployment needs all three before anyone trusts a model's output -- a prediction alone doesn't explain WHY, an odds-ratio interpretation alone doesn't confirm the underlying assumptions hold, and an assumption check alone doesn't produce a usable prediction. Isolating each, as Concepts 04/05/11 did, is a teaching convenience; a real pipeline needs the full sequence.
Mathematical: derive the combined-feature odds ratio for a row differing from a baseline in two features at once.
Odds scale multiplicatively per feature: the combined ratio equals the product of each individual feature's own exp(w_j) ratio ONLY when exactly those two features change and nothing else does. Section 21's own exercise differs in three features (x1, x2, x3 all change) from P, so its 134.29x ratio is not simply exp(w1)·exp(w3) -- the x2 change (-0.02 per day over 25 fewer days) also contributes a factor of exp(-0.02·-25)=exp(0.5)≈1.6487.
Coding: extend Section 12's script to report which single feature change contributes the most to row B's own misclassification.
Recompute z with each feature individually reset to a "safe" reference value (e.g. x1=0, x2=0, x3=0 in turn) and see which single reset flips the prediction back to 0 -- for row B, resetting x3 from 1 to 0 alone (removing +1.2 from z) flips z from 0.4 to -0.8, correcting the prediction, showing the timely-response feature contributes most to this particular miss.
System design: what would need to change before this worked case became a real production baseline?
Real labeled training data with a proper train/validation/test split (Module 18, named forward), weights actually fit rather than assumed, resampling or class weighting to account for the real 22.3% CFPB base rate (Module 05, cited back), and a fuller assumption audit beyond the single VIF check run here.
