MODULE 07 · CONCEPT 01

No weights. No training.
Just look at what's nearby -- if "nearby" still means anything.

Every model in Module 06 -- logistic regression, LDA/QDA, softmax -- fit a fixed, finite object once (a weight vector, a Gaussian) and reused it unchanged for every future prediction. K-nearest neighbors does neither: it keeps the entire training set in memory and does all its work at prediction time, by majority vote among the k closest stored points. That mechanism has exactly one real failure mode, and it's a mathematical one: in high dimensions, "closest" stops meaning much, because every point ends up roughly the same distance from every other point.

02 · WHY IT EXISTS

Sometimes "look at what's similar" is the whole model

K-nearest neighbors (KNN) is a non-parametric, instance-based method: to classify a new point, measure its Euclidean distance to every stored training point, take the k closest, and let them vote by majority. For regression, average their targets instead. No training phase, no weight vector -- the training set itself IS the model.

03 · CONCRETE EXAMPLE

The same 10 rows, four different vote outcomes

Reusing Concept 06's own 10 CFPB-style rows (x1=prior_contact_attempts, x2=satisfaction_score), a query at (2.6, 3.1) gets classified differently depending on k alone: k=1 looks only at row C (relief) -- predicts relief. k=3 adds B and J -- 2 relief votes to 1 -- still relief. k=5 adds D and A -- 3 to 2 -- still relief. k=7 adds G and H -- 3 to 4 -- flips to NO relief. Nothing about the query changed; only how many neighbors got a vote.

04 · TECHNICAL MECHANISM

No formula for the boundary -- just a live lookup

Unlike Concept 06's own fixed z=0 line, KNN's decision boundary is never written down as an equation -- it's implicit, traceable only by checking neighbors point by point, and it can be arbitrarily jagged. k itself acts as a complexity dial (Concept 10's own bias-variance framing, cited unchanged): small k (e.g. k=1) leans on only the closest 1-3 points -- low bias, high variance, a jagged boundary. Large k averages over more of the dataset -- high bias, low variance, a smoother boundary.

06 · IMPORTANT DISTINCTIONS

KNN vs. its closest parametric cousin

PairingThe real difference
KNN vs. LDA/QDA (Concept 07, cited back)LDA/QDA also compares a new point to something derived from the data -- but it fits a Gaussian (mu, sigma) once per class and freezes that at prediction time. KNN never freezes anything; every prediction re-scans the live neighbor set.
07 · COMMON MISTAKES

What beginners often assume, and shouldn't

"KNN has no hyperparameters to tune."

False -- k itself is a real, consequential hyperparameter, exactly as Section 03's own vote-flip between k=5 and k=7 demonstrates.

"More features always helps KNN."

False -- this concept's own worked example shows the opposite: more dimensions make every point look roughly equidistant, weakening the exact signal KNN depends on.

04
INTUITION

Asking your nearest neighbors, until "nearest" stops meaning anything

KNN is like asking the k people standing closest to you on a street for their opinion, and going with the majority. That works well when a genuine "closest" group exists. But imagine the street stretched into a thousand dimensions -- suddenly nearly everyone is about the same distance from you, and asking "the closest k" barely differs from asking a random k.

Analogy boundaryThe street analogy explains WHY the mechanism weakens, not the specific numbers -- those come from Section 12's own hand-verified worked example, not the analogy.

09
MATHEMATICS

One distance formula, one ratio

Euclidean distance(x, x_i) = sqrt(Σ_j (x_j - x_i,j)²)
ratio(d) = max pairwise distance ÷ min pairwise distance, over a fixed n-point set in [0,1]^d

Neither equation is new; the ratio's own collapse toward 1 as d grows is exactly what Section 10's own citation and Section 12's own worked example both demonstrate.

WORKED EXAMPLE

30 points, four dimensions, one collapsing ratio

A deterministic linear-congruential generator (a=1664525, c=1013904223, m=2^32, seed=42, reseeded to 42 independently before each dimension -- no live randomness) draws 30 points in [0,1]^d for d in {2, 10, 50, 200}. Every pairwise Euclidean distance is computed per d; the ratio of the maximum to the minimum is recorded.

CONCRETE USE

CLEAN FIT

d=2 in this concept's own worked example: a 130.73x ratio between farthest and nearest -- "nearest" is a strong, meaningful signal.

BOUNDARY CASE

At that point, KNN's own "nearest k" is only weakly different from a random k -- a real, structural failure mode, not a tuning problem.

12
CODE

The worked example, reproduced directly

PYTHON · FIXED-SEED LCG, PAIRWISE DISTANCES, MAX/MIN RATIO 
def make_lcg(seed):
    state = [seed]
    a, c, m = 1664525, 1013904223, 2**32
    def next_val():
        state[0] = (a * state[0] + c) % m
        return state[0] / m
    return next_val

def gen_points(d, n=30):
    rng = make_lcg(42)
    return [[rng() for _ in range(d)] for _ in range(n)]

def dist(p, q):
    return sum((a - b) ** 2 for a, b in zip(p, q)) ** 0.5

for d in (2, 10, 50, 200):
    pts = gen_points(d)
    dists = [dist(pts[i], pts[j]) for i in range(len(pts)) for j in range(i + 1, len(pts))]
    ratio = max(dists) / min(dists)
    print(d, round(max(dists), 6), round(min(dists), 6), round(ratio, 2))
# Prints: 2 1.116635 0.008542 130.73
#         10 1.8724 0.5582 3.35
#         50 3.4755 2.1018 1.65
#         200 6.6322 4.9668 1.34

REALITY

Production implications

  • KNN's own prediction-time cost scales with the training set size -- scikit-learn's own algorithm='auto' choosing among brute-force, KDTree, and BallTree is a real, necessary engineering response to that cost.
  • Feature-count growth is a real risk for any KNN deployment -- this concept's own worked example is the concrete reason dimensionality reduction (a later module, named forward only) matters specifically for instance-based methods.
  • k should be chosen via real validation, not guessed -- Section 03's own vote-flip shows how consequential the choice is.

CAREER PRACTICE

Interview questions

Conceptual: why is KNN called "lazy learning"?
Because it defers all real computation to prediction time -- there is no training-time fitting step; the model IS the stored training set, scanned fresh on every query.
Mathematical: why does the max/min distance ratio approach 1 as dimensionality grows?
Each additional dimension contributes an independent, non-negative squared term to every pairwise distance; as more terms accumulate, the LAW of large numbers concentrates all pairwise distances around a similar typical value, shrinking the relative gap between the smallest and largest observed distance.
Coding: extend this concept's own code to report the mean pairwise distance alongside max/min.
Add mean_dist = sum(dists) / len(dists) inside the loop and print it alongside the existing max/min/ratio -- watching mean_dist grow roughly proportionally to sqrt(d) while the RELATIVE spread (max/min ratio) shrinks is the same curse of dimensionality from a second angle.
System design: when would you prefer KNN over logistic regression for a real classification task?
When the true decision boundary is highly non-linear and irregular, the feature count is small-to-moderate (avoiding the curse of dimensionality), and prediction-time latency budget can absorb a live nearest-neighbor search -- logistic regression instead when interpretability, a written decision boundary, or high-dimensional features matter more.
