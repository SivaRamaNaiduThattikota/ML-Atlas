Same product rule.
New kind of clue -- word counts.

02 · WHY IT EXISTS

A document is a bag of word counts

The bag-of-words model turns a document into a vector of word counts over a fixed vocabulary -- word order is thrown away entirely, but multiplicity (how many times each word appears) is kept (Wikipedia, Bag-of-words model). This is exactly the representation behind document classification tasks like spam filtering and topic labeling (Wikipedia, Document classification). Concept 03's features were 3 binary flags; this concept's features are word counts over a vocabulary.

03 · CONCRETE EXAMPLE

The toy training set

Six short CFPB documents, three per class, vocabulary {refund, delay, error, thanks, please}. Escalate: "refund refund delay", "error delay refund", "delay error error" -- totals refund=3, delay=3, error=3, thanks=0, please=0, N=9. Resolve: "thanks please thanks", "please thanks refund", "thanks please please" -- totals refund=1, thanks=4, please=4, delay=0, error=0, N=9. Priors: P(escalate)=P(resolve)=0.5.

04 · TECHNICAL MECHANISM

The multinomial rule

Instead of one probability per binary flag, the multinomial model estimates one P(word|class) per vocabulary word: P(word|class)=count(word,class)/total_words(class). A document's likelihood is the product of P(word|class) over every word token in it -- scikit-learn describes exactly this: "MultinomialNB implements the naive Bayes algorithm for multinomially distributed data... one of the two classic naive Bayes variants used in text classification" (scikit-learn, Naive Bayes).

Same product rule as Concept 03 -- now the factors are per-word, not per-flag.

06 · IMPORTANT DISTINCTIONS

The crash

Multiplying raw frequencies straight through: Escalate = 0.333333 × 0.333333 × 0.000000 = exactly 0. Resolve = 0.111111 × 0.000000 × 0.444444 = exactly 0. Both classes collapse to zero -- this is Concept 03's own s16 zero-frequency warning arriving on schedule, with real numbers. A word never seen for a class zeroes that class's entire product, no matter how strongly the other words point the other way. 0-vs-0 cannot be classified.

07 · TECHNICAL MECHANISM

Laplace / additive smoothing

Additive smoothing (Laplace/Lidstone smoothing) "smooths count data, eliminating issues caused by certain values having 0 occurrences" (Wikipedia, Additive smoothing). scikit-learn's MultinomialNB implements it as theta_hat=(N_yi+alpha)/(N_y+alpha·n), where alpha is its "Additive (Laplace/Lidstone) smoothing parameter," default alpha=1.0 (scikit-learn, MultinomialNB). Concretely: add 1 to every word count, add the vocabulary size (5) to every class total.

CODE

Node verification #1 -- the crash, from raw word lists

JAVASCRIPT · TALLIES VOCABULARY FROM RAW WORD LISTS -- REPRODUCES THE EXACT 0/0 CRASH 
const docs = {
  escalate: ["refund refund delay","error delay refund","delay error error"],
  resolve: ["thanks please thanks","please thanks refund","thanks please please"],
};
function tally(sentences) {
  const counts = {};
  let total = 0;
  sentences.forEach(s => s.split(" ").forEach(w => {
    counts[w] = (counts[w] || 0) + 1;
    total += 1;
  }));
  return { counts, total };
}
const eT = tally(docs.escalate);
const rT = tally(docs.resolve);
const test = ["refund","error","thanks"];
function pWord(t, w) { return (t.counts[w] || 0) / t.total; }
const unsmoothedE = test.reduce((p, w) => p * pWord(eT, w), 1);
const unsmoothedR = test.reduce((p, w) => p * pWord(rT, w), 1);
console.log(eT.counts, eT.total, rT.counts, rT.total);
console.log({ unsmoothedE, unsmoothedR });
// -> { refund: 3, delay: 3, error: 3 } 9  { thanks: 4, please: 4, refund: 1 } 9
// -> { unsmoothedE: 0, unsmoothedR: 0 }

theta_hat_yi = (N_yi + alpha) / (N_y + alpha·n)

DIAGNOSIS

The zero-frequency crash in practice

ONE WORD, WHOLE CLASS

A single unseen word zeroes the entire class score

It doesn't matter how many other words in a document support a class -- one zero conditional anywhere in the product zeroes that class's whole score, exactly as this concept's own test document demonstrated.

SCALES WORSE, NOT BETTER

Bigger vocabularies, smaller training sets make it worse

A larger vocabulary and fewer training documents per class mean more unseen words show up at test time, making the zero-frequency crash more likely, not less.

ALPHA ISN'T FREE

Smoothing amount trades bias for robustness

Alpha=1 (Laplace) is scikit-learn's default, not a universal answer -- larger alpha smooths harder and pulls estimates further from raw frequencies; alpha=0 disables smoothing entirely, reproducing the exact crash seen here.

17
CAREER PRACTICE

Interview questions

Why does Naive Bayes need smoothing for text but sometimes not for other feature types?
Text vocabularies are large relative to any single training set, so unseen words at test time are common; low-cardinality binary flags (like Concept 03's) are far less likely to hit a value never seen in training.
What does alpha=0 versus alpha=1 versus alpha>1 do to a MultinomialNB model?
alpha=0 is no smoothing (reproduces the zero-frequency crash); alpha=1 is classic Laplace smoothing; alpha>1 (Lidstone smoothing) pulls every estimate further toward uniform, trading more bias for more robustness against unseen words.
Why use log-probabilities in a real multinomial NB implementation instead of raw products?
Multiplying many small probabilities together underflows to 0 in floating point on real vocabularies; summing log-probabilities instead keeps the computation numerically stable without changing which class scores highest.

CORRECTION

Common pitfalls

PitfallCorrection
Forgetting smoothing entirelySilent 0-scores whenever any test word never occurred in a class's training documents -- exactly the crash in Section 09.
Computing products in linear space on real vocabulariesUnderflows to 0 in floating point; real implementations sum log-probabilities instead (named here, not built).
Confusing "in-vocabulary with zero count" with "out-of-vocabulary"A word absent from the training vocabulary entirely needs its own handling (usually dropped or mapped to an unknown-token bucket) -- distinct from an in-vocabulary word with a zero training count, which smoothing already fixes.
