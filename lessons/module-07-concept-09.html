MODULE 07 · CONCEPT 09

Four mechanisms, four different regimes.
This concept asks when each one still wins.

This concept builds no new model and runs no new benchmark. It takes the numbers Module 07 already published one mechanism at a time -- KNN's curse-of-dimensionality collapse, Naive Bayes' linear-in-d parameter scaling, the linear SVM's fixed cost and one-line rule, the kernel SVM's data-dependent cost -- and turns them into a decision grid: which model is still the right call, and under what conditions. Every cell in that grid traces back to a specific number this module already verified. Where a claim can't be independently re-verified here, it's flagged, not quietly assumed.

01 · CONCEPT FIRST

"Still wins" means fits the regime, not "scores highest"

No dataset gets run through all four models here to compare accuracy -- that would be a new, unverified benchmark claim, which this concept deliberately avoids. "Still wins" instead means: given this module's own already-measured properties of each mechanism -- how its cost grows, whether it needs the classes to be linearly separable, whether it produces a real probability, whether its rule fits on one line -- which model's profile actually matches the situation in front of you.

First memory: This concept sorts four already-built models into regimes using numbers Concepts 01-08 already produced -- it does not run a new competition between them.
02 · WHY IT EXISTS

Concept 08's own closing line named this concept

Concept 08 counted fitted-parameter numbers and asked whether each model's rule fit on one line. Its own last paragraph pointed here next: "when does each of these mechanisms still win." Counting was the setup; choosing is the payoff -- and Concept 10 immediately after this one applies that choice to a real CFPB narrative-tagging case.

03 · CONCRETE EXAMPLE

Where KNN still wins: small, low-dimensional, no assumed shape

Concept 01's own fixed-seed experiment measured the max/min pairwise-distance ratio collapsing from 130.73 at d=2 to just 1.34 at d=200 -- the concrete mechanism behind the curse of dimensionality, and the reason KNN's "vote among nearby points" logic stops meaning much once d grows large. Read the other direction: at low d and modest N, that ratio stays large, neighbors are still meaningfully "close" or "far," and KNN's zero-assumption, no-fitting mechanism is a perfectly reasonable choice -- it never assumes independence, linear separability, or any particular decision-boundary shape at all.

04 · IMPORTANT DISTINCTIONS

Three things this concept keeps separate

Cost regime -- how many numbers a fitted model needs, and how that count grows with N or d (Concept 08's own territory, extended here). Structural requirement -- what the mechanism assumes about the data (conditional independence for Naive Bayes, linear separability for a linear SVM). Output type -- whether the model's native answer is a probability (Naive Bayes), a signed decision value (SVM), or a raw vote (KNN). A model can win on one axis and lose on another -- "still wins" always means winning on the axis that matters for the situation at hand.

05 · ARCHITECTURE / FLOW

The same formulas, swept instead of frozen at one point

Concept 08 froze N at 4 and reported a single snapshot: 8, 7, 3, and 4-to-13. This concept unfreezes N and asks what happens as a training set grows past that one snapshot -- using the exact same formulas (N·d for KNN, d·K+(K-1) for Naive Bayes reused at 7, d+1 for linear SVM, n_sv·(d+1)+1 for kernel SVM at its own demonstrated worst case n_sv=N), not new ones.

07 · CONCRETE EXAMPLE

Where Naive Bayes still wins: high dimensionality, need a probability

Concept 03's own contrast already quantified the payoff: at d=3, Naive Bayes needs 7 fitted numbers against 19 for a full-covariance alternative; at d=20, that gap widens to 41 against 461. Naive Bayes' cost grows linearly in d; the full-covariance alternative grows quadratically -- which is exactly why Concept 04 reached for Naive Bayes when moving to text, where every distinct word becomes a feature and d gets large fast. It also produces a real posterior straight out of the mechanism -- Concept 03's own 0.8/0.2, Concept 04's 0.615385/0.384615 -- not a raw vote or a signed distance.

08 · YOUR PROJECT MAPPING

Where each SVM still wins

LINEAR SVM WINS WHEN THE CLASSES ARE ACTUALLY SEPARABLEConcept 06's own hard-margin fit only worked because A/D and B/C had a gap between them at all.

When that's true, it delivers Concept 08's most compact, most readable result of the four: d+1 numbers, one inequality.

The kernel trick fixes that, but Concept 08's own sweep showed the price: a cost that depends on the data and can exceed every other option.

09 · WHAT YOU SHOULD UNDERSTAND

The takeaway

"Still wins" is regime-matching, not a leaderboard

This concept never ran all four models on one shared dataset -- every claim here traces to a number Concepts 01-08 already published.

Cost and correctness are different questions

A model can be the cheapest to store (linear SVM, fixed cost) and still be the wrong choice if its structural requirement (linear separability) doesn't hold.

The one number that isn't re-verified here is flagged, not hidden

Concept 01's exact distance-ratio values are cited, not regenerated -- that would need its own fixed-seed generator, out of scope for this concept's own verification script.

Teach-back questions

  1. Why does a low max/min distance ratio (Concept 01) argue against using KNN, specifically -- and not against the other three models?
  2. Which of the four models is the only one whose native output is already a probability, without any extra calibration step?
  3. At what dataset size N does KNN's own storage cost first exceed Naive Bayes' fixed 7, on this module's shared d=2 convention?

01
ORIENTATION

A synthesis, not a fifth mechanism

Concepts 01-02 predicted by voting among neighbors. Concepts 03-05 predicted by scoring Bayes'-rule likelihoods. Concepts 06-07 predicted by margin-maximization, with and without a kernel. Concept 08 counted what each of those four already-built models costs to keep. This concept builds nothing new -- it takes those same four mechanisms and those same already-published numbers and asks, for each one, what has to be true of a dataset for that mechanism to still be the right call.

02
DEFINITION

"Still wins," defined precisely

In this concept, a model "still wins" in a regime when its own already-measured properties -- from Concepts 01-08 -- align with what that regime needs, on one or more of five criteria: how its cost grows with dataset size, how its cost grows with dimensionality, whether it requires linear separability, whether its native output is a probability, and whether its decision rule fits on one readable line. This is explicitly not a claim about predictive accuracy on any shared dataset -- no such comparison was run in this module, and none is fabricated here to fill the gap.

03
SCOPE

What this concept does not claim

This concept does not claim one model achieves a higher accuracy, F1, or any other performance metric than another on any real dataset -- that would require actually training and evaluating all four on the same data, which this module has not done and which this concept will not fabricate. Every quantitative claim here is one of two things: a number Concepts 01, 03, 06, 07, or 08 already published and independently verified, reused as-is; or that same number's own formula, re-evaluated at a different input (a different N) using ordinary arithmetic, itself checked by a node script (Section 09). The one exception -- Concept 01's fixed-seed distance-ratio values -- is named explicitly in Section 12 as not independently re-derived here.

04
MATHEMATICS

The four cost formulas, restated from Concept 08

KNN: N·d, no fitted parameters. Naive Bayes: fixed at 7 (Concept 03's own d=3, K=2 count). Linear SVM: fixed at d+1. Kernel SVM: n_sv·(d+1)+1, worst case n_sv=N.

Concept 08 evaluated all four of these at one frozen point, N=4: 8, 7, 3, and a sweep of 4 to 13 over n_sv=1..4. This concept evaluates the same four formulas letting N itself vary, holding n_sv=N as the worst case Concept 07's own real fit already demonstrated occurring (support_ = [0,1,2,3], all four of its own training points).

05
ARCHITECTURE

The shared convention, and where it bends

d=2 throughout, matching Concept 02's own toy set and Concept 08's own convention. Naive Bayes remains the one exception, exactly as in Concept 08: its 7-parameter count was independently verified at its own real d=3, K=2 CFPB example (Concept 03) and is reused verbatim here rather than recomputed at d=2 without a real dataset behind it. N is the only quantity this concept lets move; every other input stays fixed at the value this module already used.

06
TECHNICAL MECHANISM

The dimensionality axis, from two already-published number sets

Two of this module's concepts already measured what happens as d grows, independently of each other. Concept 01's fixed-seed 30-point experiment measured the max/min pairwise-distance ratio at d=2, 10, 50, and 200, finding it collapses from 130.73 to 1.34 -- points become almost equidistant, so "nearest neighbor" stops carrying much signal. Concept 03 measured Naive Bayes' own fitted-parameter count against a full-covariance Gaussian alternative at d=3 (7 vs. 19) and d=20 (41 vs. 461) -- linear growth in d for Naive Bayes against quadratic growth for the alternative. Put together: rising d actively hurts KNN's own mechanism, while it only linearly costs Naive Bayes more numbers -- two different, already-independently-measured relationships between the same variable (d) and two different models.

11
DIAGNOSIS

Check 3 · cross-check against Concept 03's own published counts

JAVASCRIPT · RE-DERIVING CONCEPT 03'S 7-VS-19 AND 41-VS-461 FROM FIRST PRINCIPLES 
const nbCount = (d, K) => d * K + (K - 1);
const fullCovCount = (d, K) => K * (d + d * (d + 1) / 2) + (K - 1);

console.log(nbCount(3, 2), fullCovCount(3, 2));   // 7 19
console.log(nbCount(20, 2), fullCovCount(20, 2));  // 41 461

The full-covariance count sums, per class, a d-length mean vector plus the d·(d+1)/2 unique entries of a symmetric covariance matrix, times K classes, plus (K-1) free class priors -- the standard parameter count for an unconstrained multivariate Gaussian per class. Both outputs match Concept 03's own published numbers exactly, independently confirming that contrast rather than assuming it.

12
DIAGNOSIS

Check 4 · crossover analysis, and one flagged claim

Sweeping N=1 through N=8 and comparing all four costs at each step: KNN is the cheapest of the four only at N=1 (2 numbers, versus 3/7/4). From N=2 onward, the linear SVM's fixed 3 is permanently the cheapest -- because a fixed cost eventually beats anything that grows with N, and 2N exceeds 3 for any N≥2. KNN's own cost first exceeds Naive Bayes' fixed 7 at N=4 (8>7). The kernel SVM's worst case never once beats the linear SVM's fixed 3, for any N≥1 in this sweep. Flagged: Concept 01's own curse-of-dimensionality ratios (130.73 at d=2, 1.34 at d=200) are cited from its own published ledger entry, not regenerated here -- that would require reproducing Concept 01's exact fixed-seed LCG point generator, which is out of scope for this concept's own verification script. That number is trusted as already-published, not independently re-derived in this lesson.

13
EVIDENCE + CONTROL

The separability requirement, from Concepts 06-07 directly

Concept 06's hard-margin SVM only exists because its own 4-point set (A=(1,1), D=(0,0) resolve; B=(3,3), C=(5,2) escalate) had a real gap between the two classes -- verified four independent ways, landing on w=(0.5,0.5), b=-2, margin 1.414214. Concept 07 then built a dataset (R1=(1,0), R2=(-1,0) resolve; E1=(0,4), E2=(0,-4) escalate) whose convex hulls provably cross at the origin -- confirmed by hull-intersection, a brute-force angular sweep, and a non-converging Perceptron -- meaning no straight line could ever separate it, full stop. That is the exact condition under which a linear SVM cannot be fit at all, and the kernel trick (mapping into z=x1²+x2², margin 7.500000) becomes the only way forward for that mechanism.

CAREER PRACTICE

Interview questions

Why might a hiring manager reject "just use the kernel SVM, it's the most powerful" as an answer?
Power isn't free here: this module's own sweep shows a kernel SVM's worst-case cost (n_sv=N) always exceeds the linear SVM's fixed cost, and eventually exceeds even KNN's raw storage cost -- "more powerful" mechanism, not automatically the cheaper or more interpretable one.
Why does Naive Bayes tolerate high-dimensional data (like text) better than a full-covariance Gaussian classifier?
Its parameter count grows linearly in d (d·K+(K-1)) while the full-covariance alternative grows quadratically (via the d·(d+1)/2 covariance terms) -- Concept 03's own 7-vs-19 at d=3 becomes a much wider 41-vs-461 gap at d=20.
What concrete dataset property, established in Concept 07, forces a move from a linear SVM to a kernel SVM?
Convex hulls that provably cross, as Concept 07's own R1/R2/E1/E2 dataset showed by hull-intersection, brute-force angular sweep, and a non-converging Perceptron -- no straight line can separate classes whose convex hulls overlap.
Which of these four models produces a real probability as its native output, without any extra calibration step?
Only Naive Bayes -- its mechanism is Bayes' rule itself, so a posterior probability is what comes out directly (Concept 03's 0.8/0.2). Both SVM variants output a signed decision value; KNN outputs a raw vote count.
22
CORRECTION

Common misconception

"The most sophisticated mechanism should be the default choice."This module's own numbers argue against reaching for the kernel SVM by default. Its worst-case cost, n_sv·(d+1)+1 with n_sv=N, is strictly larger than plain KNN's own N·d raw-storage cost for every N in this sweep -- more numbers kept than the "no model at all" option, plus a decision rule that (unlike the linear SVM's one inequality) cannot be read off in one line. Sophistication of mechanism and fitness for a given regime are two separate questions -- this concept's whole point is to keep asking the second one.
