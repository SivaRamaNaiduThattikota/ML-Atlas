MODULE 08 · CONCEPT 03

Fit three trees on three different samples of the same rows.
Then let them vote.

Concept 01 fit one tree to one dataset and picked one winning split. This concept keeps the same 8 rows on the table but stops fitting only one tree. It draws three separate samples of those 8 rows -- with replacement, so the same row can be picked twice and another can be missed entirely -- fits an independent stump to each sample, and lets the three of them vote. Where the data is clean, all three agree with the single full-data tree. Right at the one spot where two rows share a feature value but disagree on the label, the vote does something the single tree cannot: it changes.

PROGRESSIVE BEGINNER CORE

One tree is one opinion. Three bags is a vote.

Concept 01 asked "which cut leaves both sides cleanest" once, on all 8 rows. This concept asks the same question three times, each time on a different resample of those same 8 rows, and combines the three answers into one.

01 · CONCEPT FIRST

Bagging: resample, refit, vote

Bagging (bootstrap aggregating) fits many trees, each on its own bootstrap resample of the same training set, and aggregates their votes into one prediction. Nothing about how any single tree splits changes -- Concept 01's own Gini-based threshold scan runs unmodified inside each bag. What's new is that every bag sees a slightly different set of rows, and the final call comes from combining several independent opinions instead of trusting one.

First memory: One tree, one dataset, one answer. Bagging is several trees, several resamples of the same dataset, one vote.
02 · WHY IT EXISTS

A single fully-grown tree is unstable

A decision tree's split depends entirely on which rows happened to be in the training set. Swap out a couple of rows and a close call can flip to a different threshold entirely. That sensitivity is called high variance, and it's the specific weakness bagging targets: fit the same kind of tree on several different resamples of the same data, and average out the disagreements instead of betting everything on one draw.

03 · CONCRETE EXAMPLE

Two rows, one tie

8 CFPB-style rows, one feature (prior_contact_attempts, x1) and one label (1 = relief, 0 = no relief): A/1/0, B/2/0, C/3/0, D/4/1, E/4/0, F/5/1, G/6/1, H/7/1. Rows D and E sit at the exact same x1=4 but disagree on the label -- a genuine ambiguous zone baked right into the training data, not a hypothetical one. Root Gini impurity is 0.5 (4 zeros, 4 ones, an even split).

04 · TECHNICAL MECHANISM

Bootstrap sampling: with replacement, same size

A bootstrap sample draws N rows from an N-row training set with replacement -- every draw picks from the full original set again, so the same row can land in a bag more than once while another row is skipped completely. Each bag is then handed to Concept 01's own tree-fitting logic, unmodified, and fits its own independent stump.

05 · ARCHITECTURE / FLOW

8 rows → 3 draws → 3 stumps → 1 vote

Each bag fits its own threshold independently, using nothing but Concept 01's own scan. Averaging their three predictions by majority vote is the entire mechanism -- no new math beyond "count the votes."

06 · IMPORTANT DISTINCTIONS

Not the resampling you already met in Module 05

Module 05 Concept 02 also resamples -- but it duplicates existing minority rows on purpose, to fix a class-imbalance problem visible in the training set itself. Bagging's bootstrap draw is different: it resamples the entire training set with replacement, every row equally likely to be picked, so the class ratio stays the same in expectation. Module 05's resampling changes what the data looks like; bagging's resampling changes nothing about the data's balance and everything about how many different "looks" at it a model gets.

07 · COMMON MISTAKE

"More stable" is not "more accurate"

At x=4, the single tree says 1 (escalate risk / relief); the 3-bag vote says 0. It is tempting to call the vote's answer the correct one. It isn't -- rows D (x=4, label 1) and E (x=4, label 0) contradict each other in the training data itself, so there is no unambiguous ground truth at that exact point to be "more correct" about. What bagging actually buys here is that the vote is less sensitive to which one of two noisy, tied duplicates any single resample happened to draw -- a claim about stability, not about accuracy.

08 · YOUR PROJECT MAPPING

Where this fits the CFPB project

THE UPGRADE PATH FROM A SINGLE TREEBagging is the natural next step once one decision tree proves too sensitive to which complaints ended up in the training fold.

Concept 01 built the split-finding mechanism this concept wraps; once Concept 02's overfitting-and-pruning material lands, a single deep tree on real CFPB data would show exactly the instability bagging exists to smooth out.

WHAT DOESN'T CHANGEThe class balance in the training data.

Unlike Module 05's oversampling fix, a bootstrap draw picks every row with equal probability -- it doesn't rebalance escalate versus resolve, it just gives each tree a slightly different sample of the same balance.

09 · WHAT YOU SHOULD UNDERSTAND

The takeaway

Bootstrap sampling is with replacement, same size as the original

Some rows get picked more than once; others get skipped for that draw entirely. That's the entire mechanical trick.

A vote can disagree with the single full-data tree, and that's the point

Away from any ambiguous zone all trees agree. Right at one, the disagreement across bags is the signal that the single tree's answer there was fragile.

Stability is not accuracy

At x=4 there is no clean ground truth to be right about -- only a training-data contradiction the single tree broke one way and the vote broke another.

Teach-back questions

  1. Why can a majority vote across 3 bootstrapped stumps output a different answer than the one stump trained on all 8 rows?
  2. Why is it wrong to say the vote's answer at x=4 is "more accurate" than the single tree's answer there?
  3. What's the difference between bagging's resampling and Module 05 Concept 02's resampling, given that both sample with replacement?

01
ORIENTATION

A variance-reduction wrapper, not a new mechanism family

Module 08 opened with Concept 01's decision-tree mechanism -- Gini impurity, entropy, and an exhaustive threshold scan over candidate splits. This concept builds no new splitting rule. It takes that exact mechanism and wraps it: fit it once per bootstrap resample instead of once on the whole training set, then combine the resulting trees' predictions by majority vote. Concept 02, "Overfitting in trees -- depth and pruning," has not been published yet as a lesson file at the time this concept was written; it is cited below only as a named forward reference, never as an exact section number, so this concept does not assume content that doesn't exist yet.

04
SCOPE

What this concept covers, and what it explicitly does not

This concept covers exactly two mechanics: bootstrap resampling with replacement, and majority-vote aggregation across the resulting trees. It does not cover Random Forests' additional per-split feature subsampling, and it does not cover boosting's sequential, weighted approach -- both are named forward references only (Sections 21 and 24), not built out here. Every number below -- the root Gini, the exact tie, all three bootstrap draws and their fitted stumps, the 5-point divergence table, and the 6-seed spot-check -- was produced by running Node.js scripts on raw row lists, not typed-in arithmetic. Using B=3 bootstrap trees throughout is a hand-verifiable pedagogical minimum, not a claim about real bagging's variance-reduction magnitude -- production bagging and Random Forests average over hundreds of trees, and nothing in this worked example supports any quantitative "variance reduced by X%" statement.

CODE

Node verification 1 -- the scan and the tie-break

JAVASCRIPT · SAME SCAN AS CONCEPT 01, RUN ON THIS CONCEPT'S OWN 8 ROWS 
const POINTS = [
  { id: 'A', x1: 1, y: 0 }, { id: 'B', x1: 2, y: 0 }, { id: 'C', x1: 3, y: 0 },
  { id: 'D', x1: 4, y: 1 }, { id: 'E', x1: 4, y: 0 }, { id: 'F', x1: 5, y: 1 },
  { id: 'G', x1: 6, y: 1 }, { id: 'H', x1: 7, y: 1 },
];
function gini(labels) {
  const n = labels.length; if (!n) return 0;
  const p1 = labels.filter(y => y === 1).length / n;
  return 1 - (p1 * p1 + (1 - p1) * (1 - p1));
}
function scan(points) {
  const sorted = [...points].sort((a, b) => a.x1 - b.x1);
  const out = [];
  for (let i = 0; i < sorted.length - 1; i++) {
    if (sorted[i].x1 === sorted[i + 1].x1) continue;
    const t = (sorted[i].x1 + sorted[i + 1].x1) / 2;
    const left = points.filter(p => p.x1 <= t), right = points.filter(p => p.x1 > t);
    const giniAfter = (left.length / points.length) * gini(left.map(p => p.y))
      + (right.length / points.length) * gini(right.map(p => p.y));
    out.push({ t, giniAfter, gain: gini(points.map(p => p.y)) - giniAfter });
  }
  return out;
}
const best = scan(POINTS).reduce((a, b) => (b.gain > a.gain ? b : a));
console.log(best); // { t: 3.5, giniAfter: 0.2, gain: 0.3 } -- first-found tie-break keeps t=3.5, since t=4.5's gain (0.3) is not strictly greater
08
TECHNICAL MECHANISM

Bootstrap sampling: with replacement, same seeded convention

A bootstrap sample of size N draws N rows from the training set, sampling with replacement each time -- every draw looks at the full original 8 rows again, so a row already picked can be picked a second or third time, and a row never picked at all is simply absent from that bag. This concept draws its three bags using the same deterministic linear-congruential generator this course has used before for reproducible "random" draws (a=1664525, c=1013904223, m=2^32, seed=42), with the generator's state carried forward sequentially across all three draws rather than reset before each one. Section 16 below contrasts this against sklearn's "pasting" variant, which samples without replacement.

WORKED EXAMPLE

Unpacking the flip at x=4 and x=4.5

Row D (x1=4, y=1) and row E (x1=4, y=0) contradict each other at the exact same feature value. The single full-data tree, forced by the first-found tie-break to split at t=3.5, puts both of them on the right side and predicts 1 there. Two of the three bootstrap trees (Bags 2 and 3) split at or after 4.5, putting x=4 on the left and predicting 0. The 3-bag vote follows the majority and lands on 0. Neither answer is "the correct one" for x=4 -- the training data contains both labels at that point. What changed is not correctness but stability: the vote is less sensitive to which one of D and E's tied, contradictory copies a given resample happened to draw more of.

15
DIAGNOSIS

Why the bags disagree -- decorrelated errors, concretely

Bagging's variance-reduction argument, in general, rests on each bag's errors being at least partly independent of the others' -- so that averaging cancels some of them out instead of repeating the same mistake three times. This dataset makes that mechanism visible rather than abstract: Bag 3's bootstrap draw simply never picked row D, the one row responsible for the tie in the first place. Without D in its sample, Bag 3 had no contradictory evidence left at x=4 and split perfectly at t=5.5. Bags 1 and 2 did draw D, and their thresholds (3.5 and 4.5) landed on either side of the ambiguous zone. Three different samples, three different relationships to the one noisy row -- that's decorrelation, not a coincidence of the specific numbers.

16
CONTRAST

Bagging's resampling vs. Module 05's resampling

Both mechanisms sample with replacement, and it is easy to conflate them. Module 05 Concept 02's random oversampling duplicates existing minority-class rows on purpose, to change the training set's own class ratio before a model ever sees it -- a deliberate fix to a specific imbalance problem visible in that data. Bagging's bootstrap draw resamples the whole training set, every row (majority or minority) equally likely to be picked, so the class ratio stays the same in expectation across draws -- the goal is never to change what the data represents, only to give each tree in the ensemble a slightly different sample of it. Same mechanic, different problem, different effect on the label distribution.

17
CODE

Why "pasting" (no replacement) can't reproduce Bag 3

scikit-learn names the without-replacement variant of this same idea "pasting." At this dataset's own full sample size (8 rows drawn from 8), pasting without replacement has only one possible draw: all 8 rows, in some order, every time -- identical to the original set. A manual pasting variant on these 8 rows would therefore always refit the exact same t=3.5 stump as the single full-data tree, never Bag 3's pure t=5.5 split, because pasting at full size can never omit row D the way Bag 3's bootstrap draw happened to. Bootstrapping's willingness to duplicate some rows and omit others at the very same sample size is exactly what makes that omission possible.

18
EVIDENCE + CONTROL

The modeling decision: bagging pairs with strong, unpruned trees

Bagging's variance-reduction case is strongest when the base learner already has low bias and high variance -- a fully-grown, unpruned tree is the standard example, since it fits its own bootstrap sample almost exactly and therefore varies a lot from bag to bag. That variability is the raw material averaging works on; a heavily pruned, high-bias tree would already be stable, and bagging would have less variance left to reduce. The cost side is real too: an ensemble of B trees loses the single-tree readability Concept 01's split-by-split logic offered, and costs roughly B times the training work of fitting one tree. Nothing here quantifies the size of the variance-reduction benefit against that cost -- that tradeoff is a judgment call, made explicitly rather than left as an unexamined default.

MECHANICS

How the lab computes and renders its predictions

Each bag's own prediction is a majority vote over the labels of whichever rows its bootstrap draw picked -- ties (impossible to hit exactly with 8 rows split 3/5, but guarded anyway) fall to 0, the same majority-floor convention used earlier in this course. The grids reuse the acc-cell markup and its acc-pos/acc-neg/acc-correct/acc-wrong classes from earlier accuracy-illusion visuals, but deliberately repurposed: here, acc-correct means "drawn exactly once" and acc-wrong means "drawn two or more times," never correctness. Every cell's title and aria-label spells this out explicitly ("Row N, drawn Kx") so the reuse is legible to anyone inspecting the markup or using a screen reader, not just visually implied by color.

CONTRAST

Where a bagged-stump ensemble sits against this course's other single models

Module 06 Concept 12 closed its module with a single logistic baseline: 3 features, fixed weights, mean binary cross-entropy 0.4529 across 8 rows, one confident miss. That's a single model scored once. This concept's 3-bag ensemble is a structurally different animal -- not one fitted model but three, combined by vote -- and no accuracy comparison is made between the two here, since they were run on entirely different datasets and different tasks. The more relevant contrast is against boosting: scikit-learn's own framing distinguishes the two families by build order -- bagging's member trees are fit independently and in parallel (as this concept's three bags were), while boosting builds its members in sequence, each one weighted to correct the previous one's errors. Boosting itself is a named forward reference here, not built out in this concept.

22
CAREER PRACTICE

Interview questions

Why does bagging reduce variance but not necessarily bias?
Averaging several trees' predictions smooths out the disagreements caused by which rows each one happened to train on -- that's variance. It doesn't change what any individual tree is structurally capable of representing, so a systematic blind spot shared by every bag (bias) survives the averaging untouched.
Why must the resampling be with replacement for bagging's mechanism to work?
Without replacement, at full sample size every "resample" is just the original set again -- Section 17's pasting example shows this concretely. Replacement is what lets some rows be duplicated and others omitted, which is what makes different bags actually different.
When would you reach for bagging instead of boosting?
When the base learner already has high variance and low bias (a deep, unpruned tree) and the errors across resamples are likely to be at least partly independent -- bagging averages those out in parallel. Boosting is the better fit when the base learner is weak and biased and needs to be corrected sequentially.
23
CORRECTION

Common misconceptions

"Bagging and Random Forest are the same thing."Random Forest adds a second randomization on top of bagging -- subsampling which features are even eligible at each split -- that this concept does not build. Bagging alone, as demonstrated here, resamples rows only.
"More bootstrap trees always helps proportionally."This concept's B=3 is a hand-verifiable pedagogical minimum, not a magnitude claim. Production bagging and Random Forests average over hundreds of trees; nothing run in this concept measures how much benefit comes from going from 3 to 300.
"Bagging fixes underfitting."Bagging targets variance, not bias -- averaging several biased trees still produces a biased ensemble. If a single tree is systematically wrong in the same direction on every resample, bagging will not correct that; it will just agree with itself more confidently.

Fit three trees on three different samples of the same rows. Then let them vote.

An 8-row toy set with a genuine tie at x=4 gave the single full-data tree an arbitrary tie-break to t=3.5. Three bootstrap resamples of the same rows fit three independent stumps -- t=3.5, t=4.5, and a pure t=5.5 that happened to skip the contested row -- and their majority vote matched the single tree everywhere except the two points nearest that tie, where it was more stable, not more accurate. Bootstrap Draws → Majority Vote lets that same mechanism run live, on a separate 8-row set, redraw after redraw.
