01 · CONCEPT FIRST

A committee that focuses on whatever it's still missing

AdaBoost fits weak learners one at a time, each one told to focus on whatever the previous ones still got wrong -- instead of every learner voting on the same view of the data at once. Every round's stump is chosen to minimize error under the CURRENT weights, not the original, uniform ones.

First memory: AdaBoost doesn't fix a mistake for free -- every round's fix costs a different row, and the algorithm keeps trading which row it gets wrong.
02 · WHY IT EXISTS

The gap parallel ensembles can't close

Bagging and random forests fix instability and correlation by spreading trees across different rows or features, in parallel. Neither has a mechanism for "try harder on the cases you're still missing" -- that's the gap AdaBoost's sequential reweighting closes.

03 · CONCRETE EXAMPLE

Round 1 misses H. Round 2 fixes H, costs C.

On the 8-row CFPB relief table, round 1's single stump (x1≤2.5) misses row H exactly like Concept 04's single tree does. That miss pushes row H's weight from 0.125 up to 0.5. Round 2's stump (x1≤3.5) gets H right in exchange for missing row C instead -- one fix, one new cost.

04 · TECHNICAL MECHANISM

Fit, score, boost, renormalize

Each round fits a stump to minimize weighted error under the current sample weights. That error converts into a confidence score, alpha = 0.5 · ln((1−err)/err). Every missed row's weight is multiplied by e^alpha; every correct row's weight is multiplied by e^(−alpha); then all 8 weights renormalize to sum to 1.

05 · ARCHITECTURE / FLOW

Three rounds, three stumps, one final vote

Round 1x1≤2.5, misses H
Round 2x1≤3.5, misses C
Round 3x2≤35, misses A, B
06 · IMPORTANT DISTINCTIONS

Reweighting, not resampling -- a correction, not a footnote

This concept's own title says "weighted resampling." The real mechanism -- and scikit-learn's own AdaBoostClassifier, which passes sample_weight straight into the base estimator's fit() -- reweights the same 8 rows every round. It never draws a new bootstrap sample by weight. Some looser explanations describe AdaBoost as "resampling toward misclassified points," but the standard algorithm, and this worked example, reweight.

07 · COMMON MISTAKES

"A later round permanently fixes an earlier mistake"

"Round 2 fixing row H means H is settled for good."

Not necessarily -- round 3 changes the weights again. What's actually true is that the FINAL alpha-weighted vote gets H right; individual rounds keep trading.

"This is literally resampling, like bagging's bootstrap draws."

False -- see Section 06. The rows never change; only their weights do.

09 · WHAT YOU SHOULD UNDERSTAND

Readiness check before moving on

State the weight-update rule from memory

alpha = 0.5·ln((1−err)/err); missed rows × e^alpha; correct rows × e^(−alpha); renormalize to sum 1.

Explain why each round's fix costs a different row

Fixing the current heaviest-weighted miss changes which row the NEXT weighted-error search cares about most.

Name which row should gain weight next

Whichever row the current round's stump just got wrong -- always the heaviest-weighted miss.

Teach-back questions

  1. Why does round 2's stump get row H right but row C wrong, when round 1 got H wrong and C right?
  2. What happens to alpha as a round's weighted error approaches 0.5?
  3. Why is "weighted resampling" the wrong name for what this algorithm actually does?

RECAP

Concept 06's sequential-correction idea, recapped

Boosting trains trees in sequence, each one aware of and correcting the last, with votes weighted by how much each tree earned. Concept 06 walked this in outline on the same table; this concept re-derives every number from scratch, independently.

03
CONTRAST

AdaBoost vs. Concepts 03-04's parallel trees

Bagging and random forests (Concepts 03-04) fit trees independently, in parallel, on different resamples or feature subsets. AdaBoost fits stumps in sequence, and each one is chosen specifically to minimize error under weights the PREVIOUS round set -- there is no equivalent dependency in bagging or random forests.

06
MATHEMATICS

The weight-update rule, term by term

alpha_t = 0.5 · ln((1 − err_t) / err_t)
w_i ← w_i · exp(−alpha_t · y_i · h_t(x_i)), then renormalize so Σw_i = 1

y_i ∈ {−1, +1} (recoded from y∈{0,1}). When h_t(x_i) matches y_i (correct), the exponent is negative and the weight shrinks; when it doesn't match (wrong), the exponent is positive and the weight grows.

07
WORKED EXAMPLE

Round 1, worked

Starting weights: 0.125 each (8 rows, uniform). Weighted-error-minimizing stump: x1 ≤ 2.5, polarity −1. Weighted error 0.125000 (misses row H). alpha1 = 0.5·ln(0.875/0.125) = 0.972955.

08
DIAGNOSIS

After round 1

Row H's weight jumps 0.125 → 0.5. All seven other rows drop to 0.071429 each -- and that 0.071429 figure reappears as exactly row C's contribution to round 2's own weighted error below, an internal cross-check that the renormalization is correct.

09
WORKED EXAMPLE

Round 2, worked

With row H now dominating (weight 0.5), the weighted-error-minimizing stump shifts to x1 ≤ 3.5, polarity −1. Weighted error 0.071429 (misses row C only). alpha2 = 0.5·ln(0.928571/0.071429) = 1.282475.

10
DIAGNOSIS

The trade AdaBoost keeps making

After round 2: row C's weight jumps 0.071429 → 0.5; row H settles to 0.269231; rows A, B, D, E, F, G drop to 0.038462 each. Fixing row H cost row C -- stated as the mechanism's real behavior, not a flaw to explain away.

15
CORRECTION

Reweighting, not resampling

This concept's own title says "weighted resampling." The algorithm above -- and scikit-learn's own AdaBoostClassifier, which passes sample_weight directly into the base estimator's fit() call -- reweights the same 8 rows every round. It never draws a new bootstrap sample by weight the way bagging draws a fresh resample. If a treatment describes AdaBoost as "resampling toward misclassified points," that's a looser description of the same underlying reweighting mechanism, not a literal second sampling step.

16
EVIDENCE + CONTROL

SAMME/SAMME.R, labeled as history

Current stable scikit-learn documentation for AdaBoostClassifier exposes no algorithm parameter and contains no SAMME or SAMME.R text -- that historic parameter has been removed from the live signature, confirmed by direct inspection of the current docs. If a course or reference still teaches SAMME/SAMME.R, it should be labeled explicitly as prior-version history, not current API.

19
TECHNICAL MECHANISM

Why a stump, specifically

max_depth=1 is the library's own default weak learner -- a single split, exactly what this concept's worked example uses throughout. A deeper tree would still work mechanically, but would fit more of the current weighted data per round, changing how many rounds are needed and how aggressively each round can overfit to a few heavily-weighted rows.

22
CORRECTION

A stronger single round isn't automatically safer

"A stump with lower error is always the safer long-term choice."

Not necessarily -- more rounds on noisy or mislabeled data keeps pushing weight onto exactly those noisy points, a stated risk of the reweighting mechanism, not something demonstrated as a failure on this clean 8-row table.

23
CAREER PRACTICE

Interview questions

Mathematical: state the AdaBoost weight-update rule from memory.
alpha_t = 0.5·ln((1−err_t)/err_t); each row's weight is multiplied by exp(−alpha_t·y_i·h_t(x_i)), then all weights renormalize to sum to 1.
Conceptual: why is AdaBoost's weak learner usually a stump?
A single split is intentionally weak (better than random, not necessarily accurate) -- scikit-learn's own default base estimator is exactly a max_depth=1 DecisionTreeClassifier, matching this concept's own worked example.
Mathematical: what happens to alpha as a round's weighted error approaches 0.5?
alpha approaches 0 -- a learner barely better than a coin flip earns almost no vote-strength in the final ensemble.
Conceptual: why is "weighted resampling" not an accurate description of the mechanism?
The algorithm reweights the same fixed set of training rows every round -- it never draws a new bootstrap sample by weight, unlike bagging's actual resampling step.
