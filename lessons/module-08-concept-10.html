MODULE 08 · CONCEPT 10

Different mistakes, not more copies.
What stacking actually learns.

Bagging, random forests, AdaBoost, and gradient boosting all combine copies of ONE model family. Stacking breaks that pattern -- it trains a learned meta-model on top of several genuinely different families' predictions. This concept fits a 3-NN, a Gaussian Naive Bayes model, and a decision stump on five rows of the module's shared table, holds out the other three, and lets a meta-model decide how much to trust each vote.

PROGRESSIVE BEGINNER CORE

Combining different families instead of more copies of one

Every mechanism before this one in Module 08 repeats a single model family. This concept asks what happens when the base learners are actually different from each other, and a second model learns how to weigh their disagreements.

01 · CONCEPT FIRST

A learned combiner on top of different model families

Stacking (and its single-holdout variant, blending) trains a meta-model on the predictions of several already-different base learners, rather than averaging or reweighting copies of one weak learner the way every other concept in this module does. The base learners can be anything -- here, a KNN, a Naive Bayes model, and a decision stump -- and the meta-model's whole job is to learn how much to trust each one.

First memory: Bagging averages copies. AdaBoost reweights copies. Gradient boosting fits residuals with copies. Stacking is the first mechanism in this module where the base learners are not copies of each other at all.
02 · WHY IT EXISTS

Different families make different kinds of mistakes

A single model family shares one kind of blind spot -- trees split on thresholds, KNN struggles with local sparsity, Naive Bayes assumes independence that may not hold. Bagging and boosting only ever combine copies of one such family, so they can reduce variance or bias but never cancel a mistake that's baked into the family itself. Stacking exists for exactly that gap: if different families make genuinely different mistakes, a learned combiner can sometimes do better than any one of them, or at least learn which one to trust on which kind of row.

03 · CONCRETE EXAMPLE

Splitting the table for the first time in this module

Every prior concept in Module 08 trained on all 8 rows of the shared CFPB relief table. Stacking cannot do that safely -- if a base learner predicts on a row it was trained on, the meta-model sees an unrealistically confident vote. So this concept splits the table: train on A, B, C, D, E (fit the three base learners here), hold out F, G, H (generate the meta-features here). This is the first time in the module the full 8 rows are not all used for training.

04 · TECHNICAL MECHANISM

Each base learner votes only on rows it never trained on

Fit 3-NN, Gaussian Naive Bayes, and a decision stump on the 5 train rows. Each then predicts (or outputs a probability) on the 3 holdout rows only -- never on the rows it was fit on. Those three holdout predictions become a small new table: one row per holdout example, one column per base learner. A meta-model is then fit on THAT table, learning a combination rule from the base learners' outputs to the true label.

05 · ARCHITECTURE / FLOW

06 · IMPORTANT DISTINCTIONS

Stacking vs. blending is a naming convention, not a different class

Stacking usually means generating meta-features via out-of-fold cross-validation (every row gets a held-out prediction from some fold). Blending means using one single holdout split, the way this concept does with A-E/F-G-H. Both are the same two-layer idea with different resampling discipline -- scikit-learn's own StackingClassifier covers the cross-validated version. What actually separates stacking from bagging and boosting is that the base learners here are heterogeneous (different families), not repeated copies of one.

07 · COMMON MISTAKES

"Blending is a different algorithm" and "the blend always wins"

"Fitting the meta-model on the same rows the base learners trained on is fine."

False -- that leaks information. A base learner sees an unrealistically easy version of a row it was trained on, so the meta-model would learn from overconfident, unrepresentative votes.

"A stacked blend always beats every individual base learner."

False, and this concept's own worked example proves it: the winning meta-model here just learns to trust Naive Bayes alone, because Naive Bayes alone already gets every holdout row right. The meta-model's real skill is correctly identifying which learner to trust -- not manufacturing a stronger vote than any one of them.

01
ORIENTATION

The third ensembling idea in this module

This is the tenth concept of Module 08's core sequence (10/12). Bagging/random forests average copies of one family; AdaBoost/gradient boosting reweight or residual-fit copies of one family. Stacking is the first mechanism here that combines genuinely different families, with a learned second-layer model deciding how to weigh them.

02
RECAP

The "one family, many copies" lineage this breaks from

Bagging and random forests (Concepts 03-05) train many trees on resampled data and average their votes. AdaBoost (Concepts 06-07) reweights the same rows across rounds so later trees focus on earlier mistakes. Gradient boosting and its XGBoost/LightGBM implementations (Concepts 08-09) fit each new tree to the residual of the running prediction. All four are copies of one model family, combined by a fixed rule. Stacking replaces both the "one family" assumption and the "fixed rule" with heterogeneous learners and a learned combiner.

03
PRECISION

Formal definition: a two-layer learning problem

Layer 1 is a set of base learners f_1...f_k, each trained independently and possibly from entirely different model families. Layer 2 is a meta-model g that takes (f_1(x),...,f_k(x)) as its own input features and learns to predict y. The base learners act as feature extractors for the meta-model; the meta-model is the final estimator.

04
MECHANISM

Why leakage matters here specifically

If f_i(x) is generated on a row x that f_i was also trained on, f_i's output is not representative of how it performs on unseen data -- it can be arbitrarily overconfident or exactly memorized. The meta-model would then learn from a distorted signal, the same problem as evaluating a model on its own training set. Base-learner predictions that feed the meta-model must always come from rows unseen during that base learner's own training.

05
PRECISION

Stacking vs. blending, formally

Stacking: generate each base learner's meta-features via out-of-fold cross-validation -- every training row gets a held-out prediction from whichever fold it was excluded from. Blending: use one single held-out split, as this concept does (train A-E, holdout F-G-H). Blending is simpler and faster; stacking uses more of the data for meta-feature generation. Both are the same underlying two-layer idea with different resampling discipline -- "blending" is not a distinct scikit-learn class, just the informal name for the single-holdout variant.

11
PRECISION

The meta-model

p1 = (w1·knn_prob + w2·nb_prob + w3·stump_pred) / (w1+w2+w3)

An exhaustive integer-weight grid search, weights 0-2 for each of the three base learners, minimizing sum of squared error against the true holdout labels. This is a deliberately simple meta-model -- a weighted average -- chosen so every candidate combination is exactly checkable, not a black-box logistic regression.

12
WORKED EXAMPLE

Worked result: the winning combination

Best combination: w1=0 (KNN), w2=1 (Naive Bayes), w3=0 (stump).SSE=0, predicted labels [0,1,0] -- exactly matching the true holdout labels. 3/3 correct.
13
CORRECTION

The honest caveat

This does not show blending beats every individual base learner.On this train/holdout split, Naive Bayes ALONE already gets 3/3 on the holdout (KNN gets 2/3, missing G; the stump gets 2/3, missing H). Because the grid search minimizes error with no penalty for using only one learner, it correctly collapses to "just trust NB" rather than producing a genuinely blended nonzero-weight combination. That is a real, useful teaching point -- a learned meta-model can legitimately learn to IGNORE weak base learners rather than average them -- but this worked split demonstrates "the meta-model correctly identifies which base learner to trust," not "blend beats every individual member."
14
REALITY

Stress-testing the caveat

A brute-force check across other 3-row holdout subsets of the same 8 rows (for example, A, B, H as the holdout instead of F, G, H) finds splits where no single base learner sweeps 3/3 -- but in the subsets inspected, no integer-weight blend of these three learners beat the single best member either; weighted blends TIED the best individual learner at 2/3, never strictly beat it. This is presented as an honest limitation of this small worked example, not a general claim that stacking never helps -- on larger, more diverse datasets with more base learners, a learned combiner has more room to genuinely outperform any single member.

ECOSYSTEM

Real API — StackingClassifier and StackingRegressor

Confirmed live against scikit-learn's own documentation: sklearn.ensemble.StackingClassifier and StackingRegressor are real, current classes implementing exactly this two-layer idea, with a final_estimator parameter naming the meta-model layer.

16
ECOSYSTEM

Real API — stack_method

Confirmed live against scikit-learn's own documentation: stack_method, default 'auto', controls whether each base estimator's predict, predict_proba, or decision_function output feeds the meta-model -- 'predict_proba' is a confirmed valid literal, matching this concept's own use of probability outputs (KNN, Naive Bayes) alongside a hard prediction (the stump).

18
REALITY

Choosing base learners

The practical goal is genuine diversity -- different bias/variance trade-offs and different decision-boundary shapes -- not just a longer list of models. KNN, Naive Bayes, and a decision stump were chosen here specifically because they fail in different ways: KNN is sensitive to local density, Naive Bayes assumes feature independence, and a stump can only split on one feature at a time. Near-duplicate base learners (e.g. several depth-limited trees) give the meta-model little genuinely new information to combine.

19
REALITY

Choosing the meta-model

The meta-model is usually kept simple -- often logistic regression -- specifically to avoid overfitting the combination layer itself on top of already-fit base learners. This concept's own meta-model (an exhaustive integer-weight grid search) is deliberately simpler still, chosen so every candidate combination is hand-checkable rather than learned by an opaque second model.

22
REALITY

Practical guidance

Stacking is worth its added complexity when different model families genuinely disagree in useful ways and the extra training/inference cost of running several base learners is acceptable. When one well-tuned model (or this module's own boosting) already performs well, the added complexity of a second learned layer often buys little -- exactly the pattern this concept's own worked example shows, where the "blend" just learns to defer to the one base learner that was already right.
