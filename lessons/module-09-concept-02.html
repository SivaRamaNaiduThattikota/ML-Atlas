PROGRESSIVE BEGINNER CORE

A weighted sum, a hard cutoff, and a rule for fixing mistakes

Three earlier concepts talked around the perceptron without building it. This one builds it: what it computes, how it learns from being wrong, when that learning is guaranteed to finish, and exactly why it cannot solve XOR.

01 · CONCEPT FIRST

Logistic regression's linear combination, with a hard 0/1 rule instead of a sigmoid

A perceptron computes the exact same weighted sum every linear model in this course has computed: z = w·x + b. What it does next is different. Logistic regression squashes z through a sigmoid into a smooth 0-1 probability. A perceptron runs z through a step function: predict 1 if z≥0, else predict 0. No smoothness, no probability -- a hard cutoff.

First memory: Same linear core as every model in this course. The only new part is the activation: a step instead of a sigmoid, and a learning rule built specifically around that step's mistakes.
02 · WHY IT EXISTS

Two concepts already cited its mechanism and its limit -- neither built either

Module 06 Concept 10 stated the 1969 Minsky/Papert XOR-impossibility result as fact and explicitly reserved the mechanism for "Module 09 Concept 02." Module 07 Concept 07 ran a Perceptron for 20,000 epochs as a corroborating non-convergence check and named Novikoff's theorem without deriving it. This concept is where both debts get paid: the algorithm gets built, run, and its convergence guarantee gets stated and checked against a real computed margin.

03 · CONCRETE EXAMPLE

The same 8-row CFPB table, plus the exact XOR pattern Module 06 already used

This concept reuses the module's shared 8-row relief table (rows A-H, x1=prior_contact_attempts, x2=case_age_days, x3=timely_response, y=relief) to trace the perceptron's mechanics -- that table is linearly separable, so it can show a perceptron converging, not just running. To show the limit, it needs a table that is not separable, so it also uses the classic 4-point XOR pattern -- identical to Module 06 Concept 10's own "Dataset B" -- rather than inventing a new one.

04 · TECHNICAL MECHANISM

w ← w + η(y−ŷ)x -- update only on a mistake

For every training row, compute z=w·x+b and ŷ=step(z). If ŷ already equals y, do nothing. If it doesn't, nudge every weight by η times the error (y−ŷ) times that row's own feature value, and nudge the bias by η times the error alone. Run this over every row, repeatedly, until a full pass makes zero updates.

06 · IMPORTANT DISTINCTIONS

"Never converges" and "caps below the best possible line" are two different facts

Module 06 proved, by brute-force search over every candidate line, that no straight boundary can do better than 3 of 4 (75%) on XOR. This concept's own perceptron run never gets anywhere near that -- it cycles at exactly 2 of 4 (50%) forever. Those are not the same claim: the 75% figure is the best any line could do; the 50% figure is the best this specific update rule's own trajectory ever reaches on this table, starting from zero. The algorithm doesn't wander the whole space of lines -- it walks a path, and that path can get stuck well short of the ceiling.

07 · COMMON MISTAKES

"Non-convergence means the weights are unstable or exploding"

"It never converges, so the weights must be blowing up."

False on XOR specifically -- the weights don't grow at all; they lock into a repeating cycle (period 1 at the epoch boundary) and stay bounded forever. Non-convergence here means "stuck in a loop," not "diverging."

"A perceptron that reaches 8/8 training accuracy is 'done' the way gradient boosting was in Module 08."

False -- this concept never held out data, same caveat every prior worked case in this course has named. 8/8 on 8 rows says nothing about a row this exact table has never seen.

09 · WHAT YOU SHOULD UNDERSTAND

Readiness check before moving on

Write the perceptron's forward pass

z = w·x + b, ŷ = 1 if z≥0 else 0 -- logistic regression's own linear core, with a step instead of a sigmoid.

State the learning rule and when it stops

w ← w + η(y−ŷ)x on every mistake; by Novikoff's theorem it stops in finitely many updates if and only if the data is linearly separable.

Explain why XOR breaks it, mechanically

No weight vector and bias can put all of (0,0),(1,1) on one side of z=0 and (0,1),(1,0) on the other -- the same convex-hull crossing Module 06 already proved, now shown by an update rule that just keeps failing instead of stopping.

Teach-back questions

  1. Why does the perceptron's own update rule only touch a row when it's wrong?
  2. What would change about Novikoff's bound if this table's margin (γ) were smaller?
  3. Why is "the perceptron caps at 50% on XOR" a different, stronger statement than "the perceptron never converges on XOR"?

05
MATHEMATICS

The perceptron, formalized

z = w·x + b
ŷ = step(z) = 1 if z ≥ 0, else 0

This is exactly logistic regression's linear core (Module 06 Concepts 01-09's own z = w·x + b) with one change: instead of σ(z) = 1/(1+e−z) producing a smooth probability, a step function produces a hard binary decision with no in-between. There is no gradient to speak of at the step itself -- which is precisely why the perceptron needs its own mistake-driven learning rule rather than gradient descent on a loss.

06
MATHEMATICS

The learning rule, derived

w ← w + η(y − ŷ)x
b ← b + η(y − ŷ)

If ŷ=y, the error (y−ŷ) is 0 and nothing changes. If the row is a false negative (y=1, ŷ=0), the error is +1: every weight moves toward that row's own feature values, pulling z up for rows like it. If it's a false positive (y=0, ŷ=1), the error is −1: every weight moves away, pulling z down. η=1 throughout this concept -- the simplest, most common perceptron setting, and the one Module 07's own non-convergence checks also used.

10
THEOREM

Novikoff's convergence theorem, stated

If a dataset is linearly separable with margin γ (there exists a unit-norm weight vector ŵ* such that y·(ŵ*·x)≥γ for every point, using the bias-augmented feature vector x'=(x,1)), and R is the largest norm among the augmented feature vectors, then the perceptron algorithm, started from w=0, makes at most (R/γ)² mistakes before it converges to zero training error. This is exactly the theorem Module 07 Concept 07 cited by name ("provably converges... if and only if the data is linearly separable (Novikoff's theorem)") without deriving it.

mistakes ≤ (R / γ)²
11
WORKED EXAMPLE

Novikoff's bound, computed from this run's own margin

Using this run's own converged (w,b)=(68,−10,2,11) as the separating hyperplane, normalized to unit length, and augmenting every row with a constant 1 for the bias: R (the largest augmented-vector norm, row F) = 60.041652. The per-row margins y·(ŵ*·x'), all computed from that same normalized vector, range from 0.272852 (row A, the tightest) up to 6.505372 (row F). Taking γ as the minimum, 0.272852, gives a Novikoff bound of (60.041652/0.272852)² = 48,422.8 mistakes.

35 is nowhere close to 48,422.8. That gap is normal, not a sign the bound is wrong: Novikoff's bound is a worst-case guarantee that depends on the tightest margin found against the final converged hyperplane, which can be far more cautious than the actual path the mistake-driven updates happen to take. The theorem promises "it will stop, and here's a ceiling on how long" -- not "it will take roughly this long."

12
THE LIMIT

Introducing the non-separable case: XOR

The CFPB table converged because it is linearly separable -- Novikoff's theorem guarantees that in advance. To show the theorem's "only if" direction, this concept needs a table that isn't separable. Rather than invent one, it reuses Module 06 Concept 10's own Dataset B: the classic 4-point XOR pattern, (0,0)→0, (1,1)→0, (0,1)→1, (1,0)→1 -- already proven non-separable there by a crossing-convex-hulls argument, and capped at exactly 3 of 4 (75%) by a 15,625-combination grid search and a 200,000-line random search.

14
DIAGNOSIS

The cycle, found and checked programmatically

A direct check for a repeating (w,b) state across all 1,000 logged epochs finds one immediately: the epoch-end state first seen at epoch 1 repeats at epoch 2, a period of exactly 1. This isn't divergence -- the weights never grow unbounded, they just oscillate through the same few states inside every epoch and land on the same fixed point at every epoch boundary, forever. Checked across three variants (row order A, a reversed row order, and η=0.5 instead of 1) -- all three still cap at exactly 0.5 best-ever training accuracy, never converging.

15
CORRECTION

The 50%-vs-75% distinction, precisely stated

The perceptron's own trajectory never gets near the dataset's best possible line.Module 06 proved the best any straight line can do on this exact 4-point table is 3/4 (75%) -- for example w=(1,1), b=−0.5 gets (0,0) and both of (0,1),(1,0) right, missing only (1,1). But the mistake-driven update rule, started from zero and run with η=1 (or 0.5), never visits a fractional bias like −0.5 at all on this table -- it locks into an integer-valued cycle at w=(0,1), b=0, which predicts "escalate" for every one of the four points and is right only on the two rows where y=1. Best-ever accuracy across the entire 1,000-epoch run: exactly 0.5, confirmed as the only value in the full set of per-epoch accuracies. This is flagged plainly because it would be easy to assume "non-converging" means "close to the best available line but endlessly circling it" -- on this dataset, with this update rule, it is not close at all.
16
MECHANISM

Why XOR breaks it, connected back to the convex-hull argument

Module 06 Concept 10 already proved, via convex hulls, that no straight line can separate {(0,0),(1,1)} from {(0,1),(1,0)} -- the two classes' hulls are the unit square's two diagonals, and they cross at (0.5,0.5). The perceptron's update rule is a search procedure looking for exactly the kind of separating line that proof says cannot exist; every time it "fixes" one misclassified point, the fix breaks something else, because there is no fixed point where all four are simultaneously correct. That structural impossibility, cited as historical fact in Module 06 and used only as a diagnostic in Module 07, is the actual mechanism behind both of those concepts' XOR references.

18
NAMED FORWARD

The fix: a hidden layer, no mechanics here

A single perceptron's decision boundary is one straight line (or one hyperplane), full stop -- that's what the step activation on one weighted sum can ever produce. Stacking a hidden layer of perceptron-like units, each learning its own linear boundary, and combining their outputs in a further layer is how XOR eventually gets solved. Concept 03, "The multilayer perceptron -- architecture," is where that structure is actually built. Nothing about how, why, or with what activation function is covered here.

CAREER PRACTICE

Interview questions

Conceptual: state Novikoff's theorem and explain what its bound depends on.
If the data is linearly separable with margin γ (against some unit-norm separating hyperplane) and R is the largest feature-vector norm, the perceptron makes at most (R/γ)² mistakes before converging. A smaller margin or a larger feature-vector norm both push the bound up -- this concept's own run had bound 48,422.8 but only needed 35 updates, since the bound is a worst case, not an estimate.
Conceptual: why does a non-converging perceptron on XOR not necessarily approach the dataset's best achievable line?
The update rule only ever visits the specific sequence of weight vectors its own mistake-correction path produces, starting from zero. On this exact 4-point table with η=1 or 0.5, that path locks into an integer/rational-valued cycle capping at 50% accuracy, never reaching the fractional-bias line (e.g., w=(1,1), b=-0.5) that would achieve the table's true 75% ceiling.
Practical: what would a real CFPB relief-risk system still need beyond this worked case?
A held-out validation split (this concept trained and evaluated on the same 8 rows, same caveat as every prior worked case), a check for how sensitive the found hyperplane is to row order and initialization, and -- per Section 18 -- an acknowledgment that a single perceptron cannot fit a genuinely XOR-like feature interaction if one exists in the real data.
