PROGRESSIVE BEGINNER CORE

Layers, shapes, and a way to count what an architecture costs

Concept 02 named the fix for a single perceptron's limit without building it. This concept builds it: what a "layer" is, what shape its weights and biases take, and how many parameters a given architecture actually has -- with zero training anywhere in this lesson.

01 · HOOK

The last concept named the fix. This one builds its shape.

Concept 02 closed with a single sentence: stacking a hidden layer of perceptron-like units, each learning its own linear boundary, and combining their outputs in a further layer, is how XOR eventually gets solved. This concept builds exactly that structure -- layers, shapes, parameter counts -- and trains nothing. No weight moves in this lesson.

First memory: this concept is architecture only. Training arrives later -- forward pass in Concept 06, backprop in Concept 07.
02 · DEFINITION

A multilayer perceptron is perceptron-like units, stacked into layers

An MLP takes Concept 02's single unit and repeats it in parallel, then stacks those parallel groups on top of each other. A "layer" here means a set of units computed in parallel from the same inputs -- every unit in a layer sees the same incoming values, just with its own weights and its own bias.

03 · VOCABULARY

Input, hidden, output -- and what depth and width mean

Three layer types: the input layer holds the raw features, one or more hidden layers sit in between and are never directly observed as inputs or outputs, and the output layer produces the prediction. Depth is the number of hidden layers; width is the number of units in a given layer.

04 · CONCRETE EXAMPLE

This concept's own architecture fixes its input size at 3

The module's shared CFPB 8-row table (x1, x2, x3) sets this concept's input-layer width at 3 -- the same three features Concept 02's perceptron used. The classic 4-point XOR pattern is cited only structurally here: two inputs that need a hidden layer, not a per-row classification -- no XOR row gets run through anything in this concept.

05 · TECHNICAL MECHANISM

Weights are a matrix per layer, not a scalar per unit

Each layer's weights form a matrix shaped (units_out × units_in), and its biases form a vector of length units_out. For this concept's own 3→4→1 architecture: W1 is 4×3, b1 has length 4, W2 is 1×4, b2 has length 1 -- 21 parameters total, node-verified (Section 11).

06 · RESULT

Depth and width cost parameters differently

Widening the hidden layer from 4 to 10 units brings the same 3→H→1 shape to 51 parameters. Adding a second 4-unit hidden layer instead, keeping H=4, brings it to 41 parameters. Two architectures that both look like "one step bigger" differ by a real 10 parameters (Section 14).

07 · COMMON MISTAKES

"More layers or units is automatically more powerful"

"A bigger architecture is a better one."

Not automatically true. Parameter count is a cost measure -- more numbers to store, compute, and eventually train -- not a capability proxy. Section 06's own comparison shows two "one step bigger" changes costing very different amounts.

08 · COMMON MISTAKES

"Adding a hidden layer, by itself, solves XOR"

"A [2,2,1] shape has more parameters than [2,1], so it must be more capable."

False -- node-verified in Section 16: two purely linear (no-nonlinearity) layers collapse into one linear layer. The minimal XOR-shaped architecture, [2,2,1], still needs a nonlinear activation (Concept 04) to actually gain any power over a single perceptron, [2,1].

09 · WHAT YOU SHOULD UNDERSTAND

Readiness check before moving on

State layer vocabulary and shapes

Input, hidden, output; a layer's weights are a matrix shaped (units_out × units_in), its biases a vector of length units_out.

Compute a parameter count

The general formula, plus this concept's own numbers: [3,1]=4, [3,4,1]=21, [3,10,1]=51, [3,4,4,1]=41, [2,1]=3, [2,2,1]=9.

State universal approximation's exact claim

Existence only (Cybenko 1989; Hornik, Stinchcombe & White 1989): a wide-enough single hidden layer with a suitable nonlinear activation can approximate any continuous function on a compact domain. It says nothing about unit count, trainability, or depth.

Teach-back questions

  1. Why is a layer's weight set a matrix rather than a per-unit list of scalars?
  2. Why does [3,10,1] have more parameters than [3,4,4,1], even though both look like "one step bigger" than [3,4,1]?
  3. Why doesn't a two-layer network with no nonlinearity gain any power over a single perceptron?

04
ARCHITECTURE

Input, hidden, output

An MLP has an input layer (the raw features, not computed by anything), one or more hidden layers in between, and an output layer producing the prediction. A "layer" means a set of units computed in parallel from the same incoming values -- every unit in a layer reads the exact same inputs, each with its own weights and its own bias. Depth is the number of hidden layers; width is the number of units in any one layer.

05
MATHEMATICS

Weight and bias shapes, per layer

layer(x) = Wx + b, where W is (n_out × n_in) and b is (n_out)

A layer's weights are not one scalar per unit -- they're a matrix, shaped (units_out × units_in), and its biases are a vector of length units_out. This matches PyTorch's documented convention for nn.Linear(in_features, out_features), whose weight tensor is shaped (out_features, in_features) -- cited here from the resolved torch 2.13 docs (the "stable" URL client-side redirects there; the 2.13 target is cited directly rather than treating "stable" as a fixed link). It also matches scikit-learn's hidden_layer_sizes tuple convention for MLPClassifier/MLPRegressor, where each entry in the tuple is one hidden layer's width.

06
MATHEMATICS

The parameter-count formula, stated before any numbers

For layer sizes [n0, n1, …, nL]: total params = ∑ (ni−1·ni + ni), for i = 1..L

Each consecutive pair of layer sizes contributes a weight matrix of ni−1·ni entries plus a bias vector of ni entries. Summing that contribution across every layer transition gives the architecture's total parameter count -- the formula this concept applies to every specific example below, rather than counting each one from scratch by hand.

07
MECHANISM

The resolving move: from one hyperplane to stacked layers

Concept 02's limit was structural: one weighted sum, one step activation, one straight-line boundary -- no arrangement of that single unit's own weights can ever produce more than one hyperplane. The resolving move is to stop asking one unit to do everything, and instead compute several units in parallel (a hidden layer), each free to learn its own boundary, then combine their outputs in a further layer. No arithmetic yet -- just the structural move this concept exists to name.

13
THE CHOICE

Depth and width are two independent knobs, not one dial

Section 12's sweep only ever changed one number: the width of a single hidden layer. But an architecture has a second, independent knob -- depth, the number of hidden layers -- and growing that knob instead produces a different parameter cost for what looks, informally, like the same amount of "growth."

16
CORRECTION

The linear collapse: more parameters is not automatically more power

Two purely linear (no-nonlinearity) layers collapse into one linear layer. Node-verified: running an input through two stacked affine layers with no nonlinearity in between produces the exact same output as running it through one single equivalent affine layer -- y=[22] from the two-layer computation, identical to y_eq=[22] from the collapsed single-layer equivalent. [2,2,1]'s extra parameters over [2,1] (9 vs. 3) do not, by themselves, grant any extra capability -- a stack of purely linear layers is mathematically still just one linear layer. Actually gaining power over a single perceptron requires a nonlinear activation function between the layers, which is explicitly Concept 04's call, not made here.
17
THEOREM

Universal approximation, stated as an existence result only

The universal approximation theorem (Cybenko, 1989; Hornik, Stinchcombe & White, 1989) states that a single hidden layer, made wide enough, with a suitable nonlinear activation function, can approximate any continuous function on a compact domain to arbitrary accuracy. It is an existence result: it does not say how many hidden units are needed, it does not say those weights are findable by training, and it says nothing about whether depth (more hidden layers) helps at all. Cybenko's original paper is paywalled and was not independently curl-verified this pass; the live-verified grounding source used here is the scikit-learn user guide on multi-layer perceptrons (HTTP 200 confirmed), which states the result inline.

18
NAMED FORWARD

What's deferred: activation, initialization, forward pass, backprop

Nothing about how a layer's output is actually squashed, how weights start out, how a real input flows through this architecture, or how errors flow back through it to update anything is covered here. Named forward only: activation functions (Concept 04) -- the missing piece Section 16 flagged directly; weight initialization (Concept 05); forward-pass arithmetic (Concept 06); backpropagation (Concept 07).

CAREER PRACTICE

Interview questions

Conceptual: state the parameter-count formula for an arbitrary MLP.
For layer sizes [n0, n1, ..., nL], total parameters = the sum, over each consecutive pair, of n_{i-1}*n_i (the weight matrix) plus n_i (the bias vector). Applied to [3,4,1]: (3*4+4) + (4*1+1) = 16+5 = 21.
Conceptual: why does [2,2,1] need a nonlinearity to beat [2,1]?
Section 16's own node-verified finding: stacking purely linear (affine) layers with no nonlinearity between them collapses into one equivalent linear layer, no matter how many extra parameters the stack has. [2,2,1] only gains real capability over a single perceptron [2,1] once a nonlinear activation function sits between its layers -- Concept 04's call, not made in this concept.
Conceptual: state universal approximation's exact existence claim and its caveats.
A single hidden layer, made wide enough, with a suitable nonlinear activation, can approximate any continuous function on a compact domain to arbitrary accuracy (Cybenko 1989; Hornik, Stinchcombe & White 1989). It is an existence result only: it doesn't say how many units are needed, it doesn't say training will find them, and it says nothing about whether depth helps.
