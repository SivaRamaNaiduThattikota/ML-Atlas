01 · CONCEPT FIRST

Two numbers multiplied at every single node: how much arrived, and how sensitive this node is

Backpropagation computes, for every weight in a network, exactly how much a small change in that weight would change the final loss -- without touching the weight and re-running the network to check. At every node it visits, it multiplies exactly two numbers: the upstream gradient (how much error already arrived from everything downstream) and the local gradient (how sensitive this one node's own output is to its own input, at the value it happened to take). Concept 06's own hidden unit 1, on Row C, receives an upstream gradient of 20.651321 and has a local ReLU slope of 1 -- product: 20.651321. Unit 3 receives an upstream gradient of 7.993886 and has a local slope of exactly 0 -- product: exactly 0, no matter how large that upstream number is.

First memory: upstream × local, at every node, all the way back. That is the entire mechanism -- nothing else is added for a deeper network, just more nodes to visit.
02 · DEFINITION

The chain rule, restated as a weight's own responsibility for the loss

For any composed function L(a2(z2(a1(z1(W1))))), calculus's chain rule says dL/dW1 = (dL/da2)·(da2/dz2)·(dz2/da1)·(da1/dz1)·(dz1/dW1) -- one factor per step the computation actually took to get from W1 to L. Backpropagation is just this product, computed right-to-left and reused: dL/dz2 (called delta2) is computed once and multiplied by W2 to get dL/da1; dL/da1 is multiplied by da1/dz1 (the local ReLU slope) to get dL/dz1 (delta1); delta1 is multiplied by the input x to get dL/dW1. Every delta computed once is reused for every weight that flows through that node -- nothing is recomputed per weight.

04 · WHY IT EXISTS

The alternative -- nudge each weight and re-run the network -- costs 21 times more

A gradient could, in principle, be estimated without any chain rule at all: nudge one weight up slightly, re-run the whole forward pass, nudge it down slightly, re-run again, and see how the loss moved. That is numerical differentiation, and it needs two full forward passes per parameter -- 42 forward passes for this network's 21 parameters, on Row C alone. Backpropagation gets every one of those 21 gradients from exactly one forward pass and one backward pass, total, regardless of how many parameters the network has -- 21 here, or 21 million in a real network. This concept checked both approaches against each other on two parameters and they agree to within about 1×10&supminus;&sup8; -- the chain rule isn't an approximation of numerical differentiation, it's an exact shortcut to the identical number.

08 · IMPORTANT DISTINCTIONS

"This unit's own local slope" (Concept 04) is not "this unit's own gradient" (this concept)

Concept 04 computed each activation's own derivative at a fixed z -- a property of the function alone, with nothing about the rest of the network in it. This concept's delta is that same local derivative multiplied by an upstream gradient that depends on everything downstream: the loss, the output weights, all of it. A live local derivative with zero upstream gradient still produces zero net gradient, and a dead local derivative with an enormous upstream gradient (unit 3's own 7.993886 here) still produces exactly zero. Both factors matter; neither one alone is "the gradient."

09 · COMMON MISTAKES

"Backpropagation updates the weights"

"Running backprop changes W1, b1, W2 or b2."

False -- nothing in this concept's own numbers touches a weight's value. Backprop only produces the 21 gradients (dL/dW1, dL/db1, dL/dW2, dL/db2); actually subtracting a step in that direction is gradient descent, Concept 08's job, not attempted here.

"A dead forward-pass unit always gets exactly zero gradient."

True in this specific case (unit 3's local ReLU slope is exactly 0), but for the reason that matters: it's the LOCAL factor that's zero, not the upstream one. Unit 3's own upstream gradient (7.993886) is real and nonzero -- it just gets multiplied by 0 and vanishes at that one node.

05
MATHEMATICS

The chain rule, defined generally

If L depends on w only through a chain of intermediate values, L(u(v(w))), then dL/dw = (dL/du)·(du/dv)·(dv/dw).

Every factor on the right is a derivative of one step with respect to the step just before it -- "how much does this step's output change if its own input changes a little." Multiplying all of them together answers the question the chain was built to answer: how much does the far end (L) change if the far-back input (w) changes a little, even though nothing computes that relationship directly.

06
MATHEMATICS

The chain rule, specialized to this exact [3,4,1] network

delta2 = dL/dz2 = (dL/da2)·(da2/dz2)
dL/dW2 = delta2·a1    dL/db2 = delta2
dL/da1 = W2·delta2  (broadcast across all 4 hidden units)
delta1 = dL/da1 · (da1/dz1)  (elementwise, using each unit's own local derivative)
dL/dW1 = delta1·xᵀ    dL/db1 = delta1

Every "delta" (delta2, delta1) is computed exactly once and reused for every weight downstream of it -- delta1's four numbers are reused across all 12 entries of dL/dW1 (4 units × 3 features each) plus all 4 entries of dL/db1. That reuse is the entire reason backpropagation is efficient: nothing here is recomputed per weight.

07
DISCLOSURE

The loss function used here, and why it's a stand-in

L = 0.5·(a2 − y)²    dL/da2 = (a2 − y)

Squared error is the simplest possible differentiable scalar loss, and its own derivative (a2−y) is clean enough to keep the worked example legible. It is not the loss a real classifier trained on CFPB's binary relief label would actually use -- Concept 09 is where that gets decided properly (almost certainly a cross-entropy variant, since y∈{0,1}). Using it here changes nothing about how the chain rule itself works; only dL/da2's exact formula would change under a different loss, and every downstream step (delta2 onward) would follow the identical pattern with a different starting number.

15
DIAGNOSIS

Why "upstream × local," and why it doesn't get more complicated at more layers

Every node in a computation graph has exactly one job during the backward pass: take whatever gradient arrived from downstream, multiply it by its own local derivative, and hand the result upstream to whatever fed it. A 2-layer network like this one does that twice (output unit, then each hidden unit); a 200-layer network does it 200 times, in the same pattern, at the same per-node cost. Nothing about the chain rule's structure changes with depth -- only the number of multiplications, which grows linearly with layers, not exponentially, and never requires re-running the forward pass more than once.

CORRECTION

The exact cost gap between the two methods

This network has 21 parameters (4×3 in W1, 4 in b1, 4 in W2, 1 in b2 -- Concept 03's own count). A central-difference numerical gradient needs 2 forward passes per parameter to get all 21 gradients for Row C alone: 42 forward passes, total. Backpropagation needs exactly 1 forward pass (already done, in Concept 06) plus 1 backward pass (this concept), regardless of parameter count. At 21 parameters the ratio is 42:2; the ratio only gets more lopsided as a network grows -- a real network with 21 million parameters would need 42 million forward passes for numerical differentiation, and still only 1 forward + 1 backward pass for backpropagation.

Interview questions

Conceptual: derive delta1 for one hidden unit, in general terms.
delta1_j = (dL/da1_j)·(da1_j/dz1_j). The first factor is the upstream gradient reaching unit j -- for a single output unit connected by weight W2_j, that's delta2·W2_j. The second factor is unit j's own local derivative of its activation function, evaluated at its own z1_j. Multiply the two and delta1_j is exactly what's needed for dL/dW1_j (times the input) and dL/db1_j (directly).
Conceptual: why is backpropagation "one forward pass plus one backward pass," regardless of network size?
Because each node's backward computation only needs two things: the gradient handed to it by whatever came after it (already computed, once, by the node right after it), and its own local derivative (a property of that one node, computed from values the forward pass already produced). No node needs to be revisited once its delta is computed, and no separate pass is needed per parameter -- unlike numerical differentiation, which needs two full forward passes for every single parameter.
Practical: a hidden unit's gradient comes back as exactly 0.000000 during real training. What would you check?
First, whether the local derivative is the culprit -- for ReLU, that means the unit's own pre-activation is at or below zero for every example in the batch (this concept's own Section 14 finding). Then whether that's a weights problem (the unit's own row, as here) or a data problem (unstandardized features letting one input dominate, Concept 06's Section 16). Then whether it's actually stuck, which needs to be observed across real training steps (Concept 08) rather than assumed from one static snapshot.
