01 · CONCEPT FIRST

Four recipes, one gradient

You now have a gradient -- an arrow, for every one of the network's 21 parameters, pointing which way to nudge it. This lesson is entirely about the recipe that turns "here's the direction" into "here's the actual new number." Concept 07's own Row C gradient, delta2=19.269262, and its own 8-row sequence for b2 are reused exactly as computed -- nothing here recomputes a single gradient.

First memory: Four recipes, one gradient. theta -= lr·g is the simplest one; the other three add memory of past gradients.
02 · DEFINITION

An optimizer is a deterministic update rule

Formally, an optimizer is theta_t = theta_(t−1) − f(g_t, history) -- a rule that turns the current gradient g_t, plus whatever it remembers from earlier steps, into a new parameter value. The four rules this concept builds: SGD, theta −= lr·g; Momentum, v=μv_(t−1)+g_t, theta −= lr·v; RMSprop, s=αs_(t−1)+(1−α)g_t², theta −= lr·g/(√s+ε); Adam, bias-corrected first and second moments m̂ and v̂, theta −= lr·m̂/(√v̂+ε).

03 · PREREQUISITE CHECK

Two things, both already built: Concept 07's own dL/db2 sequence for rows A through H, and its Row C gradient delta2=19.269262; and Concept 03's [3,4,1] shapes, so "which parameter is theta" stays concrete. Quick check: can you state Concept 07's own delta2 for Row C from memory (19.269262)? If not, its Sections 09–13 are worth a re-read before continuing.

04 · WHY IT EXISTS

A single shared step size ignores a 100x scale gap between parameters

Plain gradient descent with one fixed step either crawls or overshoots, and a single shared learning rate ignores that different parameters see wildly different gradient magnitudes on the exact same steps: b2's own gradients range 14.5 to 83.3 across the 8 rows, while W2[unit2]'s range 295 to 8,911 -- a more than 100x scale gap, on the same 8 steps, same network. Momentum, RMSprop and Adam each fix a specific, nameable failure mode of vanilla gradient descent rather than being arbitrary alternatives.

05 · CONCRETE EXAMPLE

b2, from −0.905926, through the same 8 gradients, four ways

Starting value b2=−0.905926. The 8-row dL/db2 sequence, rows A→H: 14.518902, 28.370300, 19.269262, 56.450749, 33.120659, 83.292917, 40.969927, 69.189750. After all 8 steps: SGD −1.251108, Momentum −1.944742, RMSprop −1.434742, Adam −0.913558. Same gradients, same start, four different endings.

06 · TECHNICAL MECHANISM

One real step (row A, g=14.518902), through all four formulas

SGD: −0.905926 − 0.001×14.518902 = −0.920445. Momentum: v=0.9×0+14.518902=14.518902, theta=−0.905926−0.001×14.518902=−0.920445 (identical to SGD at step 1, diverges after). RMSprop: s=0.01×14.518902²=2.107985, theta=−0.905926−0.01×14.518902/√2.107985=−1.005926. Adam, with bias correction making m̂_1 exactly equal g_1 (Section 09 in the advanced layer): theta=−0.906926 -- the smallest single-step move of the four, on purpose.

08 · IMPORTANT DISTINCTIONS

Batch, mini-batch, and one-row-at-a-time are not the same feed

The 8-row, one-row-per-step feed used throughout this concept is stochastic gradient descent's own definition. A single averaged step over all 8 rows (batch GD) moves b2 from −0.905926 to only −0.949073 -- a displacement of −0.043148, versus SGD's own net displacement of −0.345182 across its 8 separate steps. PyTorch's real momentum convention, v=μv+g, is also explicitly not the (1−β)-weighted exponential moving average some courses teach -- the two are different formulas, and only PyTorch's own convention is used for this concept's headline numbers.

09 · COMMON MISTAKES

"Bigger accumulated velocity always converges faster"

"More momentum always gets you there faster."

Not necessarily -- momentum moved furthest of all four rules here (−1.944742), which is not obviously "best"; it can just as easily mean overshoot.

"RMSprop's per-parameter scaling makes the learning rate irrelevant."

False -- it still needs one. The same α at two different learning rates gives −0.958807 (lr=0.001) versus −1.434742 (lr=0.01, RMSprop's own documented default).

"An optimizer can revive a dead gradient."

False -- hidden unit 3's exactly-zero gradient (Concept 07's finding) leaves its weight at exactly −0.247334 under every one of the four rules, node-verified.

11 · WHAT YOU SHOULD UNDERSTAND

Readiness check before moving on

State what state each rule keeps between steps

SGD keeps nothing; Momentum keeps a velocity v; RMSprop keeps a running squared-gradient average s; Adam keeps both a first moment m and a second moment v, each bias-corrected.

Say why the dead unit's weight never moves under any of the four rules

Its gradient is exactly zero on every one of the 8 rows -- every rule multiplies or accumulates a real gradient, none of them can manufacture one from nothing.

Explain why Adam's first step is the smallest of the four here

Bias correction at t=1 makes Adam's corrected first moment exactly equal the raw gradient, but its own denominator (the corrected second moment) still moderates the step -- producing the smallest single-step move of the four rules on this particular gradient.

Teach-back questions

  1. Why does Momentum end up furthest from the start, and is that necessarily good?
  2. What would change if the loss function changed but the gradients stayed the same shape?
  3. Which of today's four numbers would look different at 100 steps instead of 8, and why is that outside this concept's own hedge?

05
MATHEMATICS

Batch gradient descent versus stochastic gradient descent, defined

Batch GD: theta -= lr · mean(g_1...g_n)
SGD: theta -= lr · g_i, one row i at a time

Batch gradient descent averages every row's gradient into one step; stochastic gradient descent takes one row's own gradient as a step, immediately, before seeing the next row. The 8-row, one-row-per-step feed used throughout the rest of this concept is SGD's own definition, not an approximation of it.

06
MATHEMATICS

Momentum, RMSprop and Adam, defined

Momentum: v_t = μ·v_(t−1) + g_t    theta -= lr·v_t
RMSprop: s_t = α·s_(t−1) + (1−α)·g_t²    theta -= lr·g_t/(√s_t+ε)
Adam: m_t=β1·m_(t−1)+(1−β1)g_t, v_t=β2·v_(t−1)+(1−β2)g_t²
m̂_t=m_t/(1−β1^t), v̂_t=v_t/(1−β2^t)    theta -= lr·m̂_t/(√v̂_t+ε)

Momentum accumulates a running velocity from every past gradient. RMSprop accumulates a running average of squared gradients, dividing the step by its square root so large-gradient parameters get smaller effective steps. Adam does both -- a first moment (like momentum) and a second moment (like RMSprop) -- with a bias correction that matters most in the earliest steps, when the running averages have seen very little data.

07
DISCLOSURE

Hyperparameters and the momentum-convention choice

The momentum formula used throughout is PyTorch's own convention, not the only one taught. v_t=μv_(t−1)+g_t (PyTorch's own torch.optim.SGD(momentum=...) formula) is used for every headline number in this concept. Some courses instead teach a (1−β)-weighted exponential moving average of the gradient itself -- a different formula, shown once in Section 16 as a labeled contrast, never used for the numbers reported elsewhere. Hyperparameters: lr=0.001 held constant for SGD/Momentum/Adam; RMSprop shown at both lr=0.001 (for direct comparison) and its own documented default lr=0.01 (the headline number); μ=0.9; RMSprop α=0.99, ε=1e-8; Adam β1=0.9, β2=0.999, ε=1e-8 -- all PyTorch's own documented defaults, not tuned for this table.

09
WORKED EXAMPLE

Batch GD versus SGD -- the displacement gap

Batch GD (1 averaged step, lr=0.001): −0.905926 → −0.949073 (displacement −0.043148)
SGD (8 separate steps, same lr): net displacement −0.345182

Averaging all 8 rows into one step moves b2 by less than an eighth of what taking each row's own gradient as a separate step does -- averaging cancels out some of the per-row variation that SGD's own row-by-row steps each fully apply.

10
WORKED EXAMPLE

Momentum, full 8-step trace

Step 1 (row A, g=14.518902): v=0.9×0+14.518902=14.518902, theta=−0.905926−0.001×14.518902=−0.920445. Step 2 (row B, g=28.370300): v=0.9×14.518902+28.370300=41.437312, theta=−0.920445−0.001×41.437312=−0.961882. The velocity keeps accumulating across all 8 steps, ending at b2=−1.944742 -- the largest net move of the four rules, because momentum keeps adding each new gradient on top of a share of everything that came before it.

11
WORKED EXAMPLE

RMSprop, full 8-step trace

Step 1 (row A, g=14.518902): s=0.01×14.518902²=2.107985, theta=−0.905926−0.01×14.518902/√2.107985=−1.005926. The running average s grows with every squared gradient, so later steps' effective step size shrinks relative to the raw gradient's own size. At lr=0.01 (RMSprop's own documented default), 8 steps land at b2=−1.434742; at lr=0.001 (matching the other three rules for direct comparison), the same 8 steps land at only −0.958807 -- RMSprop's own scaling still needs a real learning rate, it doesn't remove the need for one.

12
WORKED EXAMPLE

Adam, full 8-step trace and bias correction checked exactly

t=1: m_1=(1−0.9)×14.518902=1.451890   m̂_1=m_1/(1−0.9^1)=14.518902

m̂_1 comes out to exactly g_1 -- the raw first moment is 10x smaller than the true gradient at t=1, and bias correction exactly cancels that shrinkage on this very first step. Without it, Adam's earliest steps would badly understate the real gradient. After all 8 steps, b2 lands at −0.913558 -- the smallest net move of the four rules, since Adam's second moment continues to moderate the effective step size even after the first-moment correction.

13
WORKED EXAMPLE

The same four rules, on a second parameter with a much larger gradient scale

W2[unit2]'s own gradients run 295 to 8,911 across the same 8 rows -- more than 100x larger than b2's own 14.5-to-83.3 range, on the identical 8 steps. Confirmed via the same four update rules ported directly from verify/m09c08_worked_case.js: RMSprop and Adam's per-parameter scaling means this much larger gradient does not simply produce a proportionally larger step the way plain SGD's would -- the adaptive rules compress the effective step size for parameters whose own gradients run large, exactly the behavior Section 04 in this module's own Concept 04 first motivated.

14
FINDING

Dead-unit invariance, confirmed across all four rules

Hidden unit 3's weight never moves, under any of the four rules. W1[unit3][feat1] starts at −0.247334, and its own gradient is exactly zero on all 8 rows (Concept 07's finding). Every one of SGD, Momentum, RMSprop and Adam ends exactly where it started, node-verified. An optimizer reweights or accumulates a real gradient; it does not manufacture one from a value that is exactly zero.
15
DIAGNOSIS

Why RMSprop matters more on the second parameter than on b2

RMSprop's own benefit is largest exactly where a parameter's own gradient scale is largest and most variable -- W2[unit2]'s 100x-larger range gives its running average s much more to compress than b2's own comparatively tame range ever does. On a parameter whose gradients are already small and stable, adaptive scaling has less work to do, and the four rules' own final numbers stay closer together than they do here.

16
CORRECTION

The real momentum convention, versus the EMA one some courses teach

v=μv+g is not the only "momentum" formula taught elsewhere -- it is the one this concept, and PyTorch, actually use. A (1−β)-weighted exponential moving average of the gradient itself, v=βv_(t−1)+(1−β)g_t, is a real, different formula some courses present as "momentum." It is shown here only as a labeled contrast -- never as the number behind any of this concept's own headline results.
17
CORRECTION

The batch-vs-SGD displacement gap, exact numbers

Batch GD's single averaged step moves b2 by −0.043148; SGD's 8 separate steps move it by a net −0.345182 -- roughly 8x further, not because SGD is "faster" in general, but because averaging specifically cancels the row-to-row variation that SGD's own per-row steps each apply in full. Neither number says anything about which approach reaches a better final answer -- only about how far the same 8 gradients move the parameter under each feeding strategy.

23
CAREER PRACTICE

Interview questions

Conceptual: derive Adam's bias correction and say why it matters most at small t.
Adam's raw first moment m_t is initialized at 0 and updated as an exponential moving average, so at small t it is systematically biased toward 0 -- at t=1, m_1=(1−β1)g_1 is only a small fraction of the true gradient. Dividing by (1−β1^t) exactly corrects for that shrinkage; as t grows, (1−β1^t) approaches 1 and the correction's effect shrinks toward negligible.
Conceptual: why would you not use plain SGD with a huge learning rate to "save time"?
A large shared learning rate applied to every parameter uniformly ignores exactly the gradient-scale gap Section 04 and Section 13 both show -- a step size tuned for a small-gradient parameter like b2 would badly overshoot a large-gradient parameter like W2[unit2], and vice versa; that's the specific problem adaptive rules like RMSprop and Adam exist to address.
Practical: a parameter's gradient comes back as exactly 0.000000 during real training. Would switching from SGD to Adam fix it?
No -- Section 14's own finding: every one of the four rules leaves a zero-gradient parameter completely unchanged, because all four multiply or accumulate the actual gradient value. The fix has to happen upstream (the mechanism producing the zero gradient, e.g. a dead ReLU unit per Concept 07), not in which optimizer consumes it.
